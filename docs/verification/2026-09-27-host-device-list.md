# Add host's device list and Connect to Tailscale in the built app

Test citations use the current split files. Recorded counts and outcomes are from the original runs.

September 27, 2026, on the Windows 11 development machine, branch `feat/host-device-list`, for #430. The design is round 3 of `prototype/host-setup-checklist` (commit 14fd23a6), rewritten in the app's React and CSS; see [ADR-0034](../adr/0034-add-host-lists-this-computers-tailnet.md).

## The running app

`tests/e2e/hosts.spec.ts` launches the built app on an end-to-end profile with reduced motion on. Tailscale there is the end-to-end stand-in: it answers `tailscale status --json` from `e2e-tailscale-status.json` in the profile, which starts as the recorded tailnet (`tests/fixtures/tailscaleStatus.ts`) with its backend stopped, and `tailscale up` sets it running. The machine's own Tailscale is never run and no browser opens. The SSH setup is a stand-in `~/.ssh` in the profile: `forge` with `HostName forge.tail5728ca.ts.net`, `pihole` with `HostName 100.64.0.5`, `spark`, which is already a saved host, and a known host `buildbox.example.net` on port 2200.

```powershell
npm run build
npx playwright test tests/e2e/hosts.spec.ts
```

## Against this machine's real Tailscale, read-only

`HostTailscale.devices()` was run once against this laptop's real `tailscale status --json` (Tailscale 1.102.2, running) and its real `~/.ssh`, and printed names only. It read 5 devices on the tailnet and listed: forge (Linux, online, Tailscale SSH) merged with its SSH configuration alias; pihole (online, no Tailscale SSH), which also carries a known-hosts tag; spark from the SSH configuration; the other known hosts; omarchy and DESKTOP-8NPFSBM offline; and the iPhone as iphone-15-pro, a phone, although it reports its own name as `localhost`. That matches the prototype's device list for the same tailnet.

## What could not be checked here

- **Connect to Tailscale against the real CLI.** It was not pressed on this machine, because Tailscale here is running and signed in to the owner's tailnet, and `tailscale up` would act on it. The unit tests script `tailscale up`'s sign-in output, including a URL printed in two pieces, a sign-in on another control server, success, failure and the CLI missing. The ten-minute wait, and whether a sign-in finishes after the page opens, were not tried live.
- **Adding forge end to end.** Picking forge saves `forge` as the target and connects through the SSH alias, but a live connection to forge needs the owner's browser approval in Tailscale SSH's check mode (#429), so it was not run.
- **macOS.** The CLI's place inside `Tailscale.app` is the one phone access already uses and is covered by `tailscaleCandidates`' unit test; it was not run on the Mac.
