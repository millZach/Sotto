# An interactive visual's three protective settings

October 7, 2026. Issue #819, on `feat/interactive-visuals`. Changes remain in the working tree.

The app turns DNS prefetching off before readiness, keeping existing Blink settings. The visual guest keeps its
sandbox and isolated world, with Node integration off. Its preload also runs in subframes. The preload removes
both WebRTC peer constructors from the page's main world and makes page-started copy and cut commands return false.
Its copy and cut listeners leave the reader's default action available and stop page listeners from changing it.
Only the main frame reports height.

Electron 43.1 skips preloads in `about:blank` subframes. The first built-app check caught this: the guest preferences
were set, but both constructors remained functions in the empty frame. The guest preload now watches for added
frames and applies the same protections through Electron's frame API. This is after frame creation, rather than
a preload in the empty frame. Frame loads remain refused by the page's policy. The setting check now passes.

`tests/e2e/visual-sandbox.spec.ts` adds an ordinary page with text and an empty frame. It reads the app's Blink
setting, reads both constructors as undefined in the page and frame, reads `require` and `process` as undefined
in the frame, and reads the page's own copy and cut commands as false. The text has a visible height and the page's
script runs. This page tries no outbound request. The existing visual checks still cover drawing, themes,
walkthrough steps, Escape, source, Expand and the three window sizes. The tests check settings and ordinary pages;
they do not prove every possible way the containment could fail.

The preload unit test checks that the installed copy and cut listeners preserve the trusted default action and
prevent an untrusted event. It does not write to the operating system's clipboard or check its contents.

`artifacts/interactive-visual/page-protected-1280x800-dark.png` is the final build's composited Electron window
capture of the chart at 1280x800 in dark mode. It was opened and visually checked. The page still draws inside
its card, with its walkthrough and composer visible. The existing spec also passed at 1600x1000 and 820x560,
in light and dark and with reduced motion. Existing captures regenerated by the spec were restored;
only this new capture is retained. No design baseline was changed.

No packaged build or macOS run was checked. The running checks used the built Windows app with a fresh test profile.
