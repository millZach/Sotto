# Omarchy setup with one press

Zach chose variant A and every recommendation on October 12, 2026: “So I like the one press to do everything” and “Your recommendations look good”. The approved prototype is `docs/prototypes/omarchy-setup-prototype.html`, originally d07469e0 on `prototype/omarchy-setup`, carried by this build at the brief’s request.

The Linux-only step follows Welcome. Settings → Dictation has the same three rows, a button naming unfinished pieces, Remove per owned piece and Remove all. The Shortcut step says Hold F9 to try it once the keys are ready. Windows and macOS keep their nine steps and native shortcut field.

The press authorizes the keys, owl and theme. Main detects each before writing, keeps a backup of bindings.lua, checks Lua and new compositor errors, and records only its own installations. Hand-installed pieces count as done and remain untouched. A non-Voxtype conflict asks Give F9 to Sotto or Leave my keys alone, with the first selected; no key picker. A stopped shell means nothing is copied for the owl. Theme setup renders under Omarchy’s lock, then selects both Omarchy halves and Match Linux. Removal restores the preceding choices while keeping later user choices.

A package update refreshes unchanged owned keys and theme quietly at startup, with a note in Settings. Updating the owl waits for a press because it restarts the bar. Without sotto on PATH, the guarded snippet leaves Voxtype’s defaults in place and the owl hides. Users press Remove all before pacman -R because pacman cannot clean their home. All pieces ship as Linux resources and in sotto-bin. There is no sotto setup CLI in this change. It goes straight to stable, as approved; Linux has no Owl build.

Acceptance includes the offer, working, done, partly done, failed, conflict, undo, update and hand-installed states; keyboard navigation and Escape; 1600×1000, 1280×800 and 820×560 in both modes with reduced motion. Unit and process integration checks cover decisions and rollback, and the real journeys run in a private HOME and nested Omarchy shell. The Linux tarball and makepkg build must carry all pieces. Local gates, independent Standards and Spec reviews, required PR checks and Linux result must pass. The PR is not merged by this run.
