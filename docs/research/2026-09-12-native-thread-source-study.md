# Native threads: lessons from T3's source

2026-09-12. Research for #24/#18. Official source inspected at **[d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3](https://github.com/pingdotgg/t3code/commit/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3)**, shallow-cloned into `.claude/tmp/t3-reference-24`. This is research provenance, not a requirement to keep T3 installed or retain its production host/settings documentation.

**Recommendation:** retain Sotto's native adapters, thread registry, durable outbox and authority guards. Borrow T3's separation of command acceptance, provider execution, targeted state, and presentation. Do not import its Effect/RPC/event-sourcing framework to solve a desktop send delay.

## Evidence and limits

This study inspected implementation and the test bodies linked below; it did **not** execute T3's tests or benchmark either app. Numeric batching/buffer limits below are verified source constants, not measured performance results. Sotto's existing [latency investigation](../verification/thread-send-latency-investigation.md) measured one manual send at 10,829 ms total / 158 ms delegation; the remaining 10,671 ms was not attributed to individual stages. Source suggests broad reads and serialization as avoidable dependencies, but does not establish how many milliseconds each change will save.

## Submission to presentation

1. **Immediate local presentation.** T3 inserts an optimistic user message with the outgoing `messageId`, then clears the composer, before asynchronous metadata/settings/upload/turn submission finishes. Display merges server messages and only local IDs absent from the server. On failure it restores the original draft only if the composer remains empty, avoiding overwriting new edits. This code does not establish a separate visible "confirmed by provider" badge. Sotto should adapt the identity/merge/restore pattern and explicitly distinguish pending, confirmed, failed, and uncertain delivery. [Insertion](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/web/src/components/ChatView.tsx#L7281-L7311), [merge](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/web/src/components/ChatView.tsx#L3240-L3249), [failure restoration](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/web/src/components/ChatView.tsx#L7534-L7590).
2. **Durable command acceptance.** `startThreadTurn` dispatches `thread.turn.start`; the decider produces user-message and turn-request events. The engine checks command receipts, commits events + projections + accepted receipt in one SQL transaction, publishes committed events, and resolves with the last sequence. Its acknowledgement means durable orchestration acceptance, not provider completion. Retried accepted command IDs return the same sequence; cross-aggregate ID reuse is rejected. Sotto's outbox should preserve this distinction without requiring a new event store. [Client command](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/operations/commands.ts#L300-L312), [decider](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/decider.ts#L1309-L1348), [receipts](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/OrchestrationEngine.ts#L144-L174), [commit/ack](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/OrchestrationEngine.ts#L274-L341).
3. **Provider execution follows acceptance.** The provider reactor consumes turn-request events, prepares the request and forks `providerService.sendTurn`; provider runtime events subsequently become orchestration updates. A committed user message therefore need not prove the CLI has started executing. Sotto must keep native acknowledgement/echo reconciliation, rather than marking a persisted local outbox item sent. [Reactor](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/ProviderCommandReactor.ts#L1547-L1576), [runtime ingestion](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/ProviderRuntimeIngestion.ts#L1653-L1701).

The receipt retry test asserts equal acknowledgement sequences and exactly one user message after duplicate dispatch. This is a server-command invariant, not evidence of universal exactly-once CLI execution. [Test](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/OrchestrationEngine.test.ts#L1928-L1990).

## What to adopt, adapt, or avoid

| Area | Verified T3 mechanism | Sotto action |
|---|---|---|
| Targeted reads | Separate shell and per-thread detail queries; SQL bounds activity detail to 500 rows and turn-page candidates to 150 raw turns. [Queries](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/ProjectionSnapshotQuery.ts#L3530-L3584), [shell](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/ProjectionSnapshotQuery.ts#L2532-L2584) | **Adopt separation:** send validation and receipt reconciliation should await only the selected thread. Model discovery and other threads' history must not be prerequisites. Bounds alone do not justify truncating pending permissions or takeover history. |
| Serialization | Client mutations share a scheduler keyed by environment/thread. Server command persistence still has one queue; provider send is forked after preparation. [Client lanes](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/threadCommands.ts#L89-L109), [server worker](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/Layers/OrchestrationEngine.ts#L416-L450) | **Adapt carefully:** keyed lanes for independent thread operations; brief shared state commits remain serialized. Do not simply parallelize the coordinator's shared draft/assignment/outbox mutations. Keep cancellation able to reach the adapter during a slow send. |
| Warm navigation/cache | Cached thread content appears immediately and resumes from its stored sequence; only applied data/cursor pairs enter the cache. Cache serialization stays off active streaming. [Cache logic](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/threads.ts#L183-L255), [persistence](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/threads.ts#L359-L396) | **Adopt presentation cache:** preserve an open thread's history during refresh, with refresh/connection state separate. Cached content is not authoritative permission or takeover evidence. Do not defer durable outbox/origin writes as if they were disposable display cache. |
| Event recovery | Subscribe to live events before snapshot/replay; buffer intervening events. Thread replay budgets count that thread's rows and serialized bytes, rather than unrelated global traffic; oversized catch-up resets to snapshot. [Budgets](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/ws.ts#L347-L360), [subscription](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/ws.ts#L1624-L1671) | **Adapt ordering:** attach listeners before async reads and reject stale read completions using thread revision/provider generation. Sotto need not invent a full replay protocol where its native adapter already reconciles from native history. |
| Stream batching | Coalesces latest `tool.updated` by stable tool-call ID **and turn**, preserving anonymous calls and order; 50 ms window, immediate flush before unrelated events/sync markers. A separate budget limits retained live data to 1,000 items/8 MiB, including batches awaiting consumer acknowledgement. [Coalescer](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/ThreadLiveEventCoalescer.ts#L17-L97), [budget](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/LiveStreamBudget.ts#L9-L10), [delivery accounting](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/LiveStreamBudget.ts#L131-L184) | **Adapt small emitter batching:** coalesce display-only repeated snapshots/deltas; flush for permission, error, terminal state and delivery confirmation. Never discard text deltas as if they were replacement snapshots. Avoid unbounded queues and silent event loss; overflow must trigger a recoverable refresh/error. |
| Native resume | Provider service adopts an existing session or resumes the persisted provider binding with cwd/model/cursor; missing resume state is an error. [Recovery](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/provider/Layers/ProviderService.ts#L1238-L1300) | **Preserve Sotto's existing seam:** `ThreadRegistry` owns Sotto identity; adapters own native aliases and transcript reconciliation. Never silently create a replacement session or resend an uncertain prompt. Do not copy T3's fallback runtime-mode value into Sotto's authority model. |
| Model catalog | Codex discovery follows `nextCursor` until exhausted. Model metadata has a network-free current read and a separately guarded background refresh; failures retain existing data. [Pagination](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/provider/Layers/CodexProvider.ts#L325-L340), [catalog seam](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/provider/ModelManifest.ts#L310-L321), [refresh](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/provider/ModelManifest.ts#L372-L416) | **Adopt:** native authoritative discovery, pagination and cached metadata off the send path. Distinguish stale metadata from verified installed/authenticated readiness. **Avoid:** depending on T3's remote manifest or treating its static model names as native capability evidence. |

Tests inspected substantiate [shared-lane ordering](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/runtime.test.ts#L773-L805), [warm cache without HTTP](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/threads-sync.test.ts#L596-L625), [no active-stream cache writes](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/packages/client-runtime/src/state/threads-sync.test.ts#L650-L672), [coalescing boundaries](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/ThreadLiveEventCoalescer.test.ts#L93-L171), [in-flight budget accounting](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/orchestration/LiveStreamBudget.test.ts#L11-L45), and [persisted cwd/cursor/identity recovery](https://github.com/pingdotgg/t3code/blob/d1d15c67f4a5fb82fd8d5e01e5e3b288296789c3/apps/server/src/provider/Layers/ProviderService.test.ts#L2793-L2831).

## Smallest useful Sotto implementation

Baseline inspected: [AgentHost](../../src/main/agents/host.ts), [coordinator](../../src/main/agents/control.ts), [thread identity](../../src/main/agents/threads.ts), [Codex](../../src/main/agents/codex.ts), [Claude](../../src/main/agents/claude.ts), [Grok](../../src/main/agents/grok.ts), and [renderer command queue](../../src/renderer/src/agents/AgentContext.tsx). These local links track the implementation branch, unlike the pinned T3 references above.

1. Add a **targeted authoritative thread refresh** through host wrappers and native adapters, returning/emitting the full cached `AgentHostSnapshot` after refreshing only the requested thread. This keeps the coordinator's existing snapshot merge contract without awaiting unrelated history. Replace pre-send and post-send broad snapshots with it. Codex currently polls all logs and reads all unconfirmed sessions; Claude/Grok snapshot paths poll their history. Scope and deduplicate native history reads with a per-thread lock while preserving dispatch-time takeover/permission checks; unrelated threads must not share that lock.
2. Give each submission a durable `commandId`/`messageId` and renderer `draftId`. Present pending immediately; confirm from the exact native acknowledgement/echo or reconciled message. Preserve uncertain outbox intent and edited drafts across navigation/restart. Sotto already persists origins before native dispatch; keep that ordering.
3. Separate **short state commits** from target-thread async work. Start with removing broad reads; introduce keyed command lanes only with tests for shared coordinator state and cancellation. A delayed unrelated thread must not delay target acknowledgement or renderer feedback.
4. Batch **display emission**, not authority/delivery persistence. Add timing for queue admission, target read, durable origin/outbox writes, native acknowledgement, reconciliation, and first renderer feedback. Verify delayed snapshots, acknowledgement loss, stale reads after reconnect, same-thread double submit, cross-thread send, permission arrival, native takeover and restart recovery.

These are recommendations inferred from source structure, not claims that the ticket already implements them. The native migration alone does not remove Sotto's broad snapshot waits or its renderer/controller global command tails.
