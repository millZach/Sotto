# Add host lists this computer's tailnet, and Sotto can connect Tailscale

## Status

Accepted September 27, 2026, by the owner's pick of round 3 of `prototype/host-setup-checklist` (commit 14fd23a6, placement A2 with the device list), for #430. Extends [ADR-0033](0033-the-desktop-lets-paired-phones-reach-its-threads.md), which first had the desktop run this computer's `tailscale` command, to Settings > Hosts.

Amended September 30, 2026: an SSH entry that goes to this computer, and one for a Git service such as `github.com`, is greyed under **Can't use now** too, since neither is a machine to add. An entry is this computer only when it goes to one of this computer's addresses or its full tailnet name; a bare name or alias never decides it, and loopback never counts.

Amended October 1, 2026: a jump is not this computer just because its `HostName` matches an address here. `ProxyJump` connects to that address from the jump host, and any `ProxyCommand` other than `none` decides for itself where the connection goes, so the alias stays selectable; a direct alias to this computer is still greyed. The full tailnet name still means this computer, jump or not. A Git service is the host SSH connects to, the `HostName` or the name itself when there is none, so an alias named `github.com` whose `HostName` is an ordinary computer stays selectable.

## Context

Add host asked for an SSH host or alias as text, with suggestions from the SSH configuration and known hosts. On September 27, adding `forge` meant knowing its tailnet name and that SSH would reach it. This computer's own Tailscale already knows every device on the tailnet, whether it is online, its operating system and whether Tailscale SSH is on. Phone access already runs the `tailscale` CLI (ADR-0033) with fixed arguments through `execFile`, and the CLI talks only to the local Tailscale service.

## Decision

Add host's host field is a **Device** list over two sources, read in main when the dialog opens: `tailscale status --json` on this computer and the SSH setup Sotto already read (`src/main/hosts/tailscale.ts`, `src/main/hosts/sshSuggestions.ts`). The window gets only the merged list; the renderer runs nothing.

- **One machine, one entry.** A configuration alias whose `HostName`, or the alias itself when it has none, equals one of a tailnet device's names (its MagicDNS name, the name's first label, the name the device reports) or one of its tailnet addresses is the same machine. It shows once with both tags, and Sotto saves the first such alias as the target so the user's user, key and port settings apply; a later alias for the same device only adds a name it answers to. The issue named `DNSName` and `HostName`; the label and the addresses are added because a configuration that reaches a device by `100.x` or by its short MagicDNS name is as common, and listing it twice is the confusion the rule exists to prevent. A known host that is one of a device's names only adds its tag.
- **Targets.** A tailnet device with no alias is saved by its MagicDNS name, such as `pihole.tail5728ca.ts.net`, which resolves whether or not the operating system searches the tailnet's domain; its name in the list and on the new host's row is the device's own name, or its MagicDNS label when that differs (an iPhone calls itself `localhost`).
- **Groups.** Online computers, configuration aliases and known hosts are under **Can connect**. Offline devices, phones (iOS and Android), machines already saved as hosts, SSH entries that go to this computer and SSH entries for a Git service (`github.com`, `gitlab.com`, `bitbucket.org` and the like) are greyed under **Can't use now** with the reason, and stay reachable by the arrow keys so the reason is read out. A jump to an address on this computer stays selectable, because SSH connects to that address from the jump host. A Git service is the host SSH connects to, not the alias it is given. "Already added" is the window's decision, which knows the saved hosts. The dialog reads the list again whenever Tailscale on this computer changes while it is open (connected, stopped, or a different number of devices), so the list, its foot and the dialog's Tailscale prompt never disagree. Mullvad exit nodes are left out: they are on the tailnet but are nobody's machine.
- **Connect to Tailscale** runs `tailscale up` with no flags, so Tailscale keeps the user's own settings (a bare `up` reconnects a signed-in node as it was). When Tailscale prints its sign-in page on `login.tailscale.com`, Sotto opens it in the default browser because the press asked for it, answers the window at once, and leaves `up` running for up to ten minutes so the sign-in completes; the window looks at Tailscale every three seconds meanwhile. Only one `up` runs at a time, for as long as the program runs: while it waits for the sign-in, the button reads **Open sign-in page** and a press opens the same page again rather than starting a second `up`, which would open a second page and could replace the first sign-in. Sotto stops a waiting `up` when it quits, so none is left running on its own. In Add host, Connect to Tailscale is the primary action, as the prototype drew it; on the Hosts page it is a secondary button in the row. A sign-in page on another control server is not opened; the window says to sign in from the Tailscale app. The URL is never logged or sent to the window.
- **Get Tailscale** opens `https://tailscale.com/download` and nothing else; the URL is fixed in main.

## Consequences

- Sotto contacts no new host: the CLI talks to the local service, and the pages that open are opened by the user's press. The README's "Privacy and cost" section says that Sotto runs the local Tailscale program to list devices and connect.
- `tailscale up` changes the state of the user's Tailscale, which is the one thing here Sotto does to another program. It happens only on the press, never on a timer or at start.
- End-to-end runs never touch the machine's Tailscale: `e2e-tailscale-status.json` in the run's profile stands in for `tailscale status --json` (`src/main/e2e/hostsTailscale.ts`), beside phone access's own `e2e-tailscale.json`.
- The SSH setup's entries are now devices rather than suggestions; typing a host is **Another SSH host…**, the list's last entry, which swaps the list for the SSH host, Username and Port fields.
