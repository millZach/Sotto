Widget trade-offs

A · Today's widget, placed by a rule

Looks like Sotto rather than Omarchy: rounded, Manrope, Sotto's teal. Nothing to build but a rule. A Wayland window cannot place itself, so the rule places it once and the pill grows from that corner unless Sotto keeps one footprint, whose clear margin then catches clicks meant for the window below. Dragging it to another edge goes away.

B · A shell plugin, pill and bar

Looks like Omarchy: square corners, the shell's font, the theme's accent as its border, repainted on every theme switch. A layer-shell surface is never a window, never takes focus and sits above full-screen apps. Costs a QML plugin under apps/omarchy/, on a plugin API Omarchy can change, and a path each way between the plugin and Sotto. Sotto writes a state file the plugin follows. The pill's buttons answer back through the dictation command from #837 over Sotto's socket: Click to dictate runs sotto dictation start, and Stop and Cancel run sotto dictation stop and sotto dictation cancel.

C · Bar only, with the OSD

The quietest and the least to build: a bar widget, and the shell's own OSD for the moments that matter. Nothing covers your work at rest. But the OSD takes no clicks, so Stop, Cancel and Try again live only in the bar, at the top of the screen, away from where you are writing. A hidden bar shows nothing while the microphone is on.

Chrome trade-offs

1 · No window controls

Nothing on screen that does nothing. Super+W closes (Sotto goes to the tray, as × does today) and Super+F fills the screen. A mouse user has no close button; the tray is their way.

2 · Close only

The one window control that works under Hyprland. It matches GTK apps on Omarchy, such as Files, which show close only (button layout appmenu:close).

3 · As today

Hyprland has no minimise, and Omarchy turns away every window's maximise request (suppress_event = "maximize" in its windows.lua). Two of the three buttons would do nothing when pressed.

What the desktop shows

  • Omarchy's bar, two tiled windows with Hyprland's 10 px outer and 5 px inner gaps and 2 px borders, and a terminal with focus, since that is where dictated text usually goes.
  • Omarchy hides an idle bar indicator until you point at the bar's centre. Voxtype's Dictation indicator is drawn as it looks then, so you can see where Sotto's sits beside it.
  • The copied state says Super+V, not Ctrl+V. Ctrl+V does not paste in a terminal; Super+V is Omarchy's universal paste, Ctrl+V for apps and Shift+Insert for terminals.
  • Bottom centre, where Sotto places the widget today, is the seam of a two-window split. A's and B's pills sit over the bottom corners of both windows; here that is Sotto's own stop button. C's OSD covers it too but lets clicks through.
  • Hover the idle pill in A or B to see it open. The page follows your system's reduced motion setting too.

A's window rule

Modelled on Omarchy's own rules for Hermes Desktop's HUD and the webcam overlay.

-- apps/omarchy/hypr/sotto.lua
o.window({ class = "^(Sotto|sotto)$", title = "^Sotto Widget$" }, {
  tag = "-default-opacity",
  float = true,
  pin = true,
  no_initial_focus = true,
  border_size = 0,
  no_dim = true,
  opacity = "1 1",
  size = { 248, 88 },
  move = { "(monitor_w/2-124)", "(monitor_h-88-16)" },
})

Designer's recommendation

Widget B, resting in the bar. It belongs on Omarchy the way A cannot, and unlike C it keeps a place to click Stop, Cancel and Try again near the text. Tick “B rests in the bar only” to see it: at rest only the bar glyph shows, and the pill appears while you dictate.

Chrome 2, close only. It is the only control Hyprland honours, and it is what Omarchy's own GTK apps show.
