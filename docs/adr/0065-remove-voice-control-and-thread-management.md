# Remove voice control and thread management

Accepted October 8, 2026. Supersedes [ADR-0012](0012-voice-coordinator-hidden-for-the-beta.md). Zach chose to remove wake listening, every reply voice, the Agents room and per-thread Manage controls, while keeping dictation, manual threads and memory unchanged. A typed command center is separate work; saved instructions and earlier assignments give it no authority.

Upgrades end every legacy assignment before provider refresh or observation. They discard attention and spoken clarification state, retain drafts and images with their question bindings, and preserve user follow-up queues, outbox entries, delivery evidence and provider history. Failed migration writes leave management unavailable in memory, keep drafts readable and report the failure; an uncertain send is never replayed. Retired-provider recovery cannot restore a grant. A temporary removal mode closes admission while the six removal commits land and is deleted with the unused machinery.

The encrypted `grokSpeech` slot is deleted without unlocking the vault, with failures reported and retried on startup. The shared OpenRouter `formatting` key, native provider sign-ins and saved reasoning credentials stay. Cleanup reaches only Sotto's named Supertonic cache, partial and backup directories under its own models folder, after containment and ownership checks. Unknown entries, symlinks, reparse points and user-supplied wake directories stay; failed cleanup leaves inert files and reports that fact.

[ADR-0025](0025-headless-host-and-client-identity.md)'s protocol v1 stays frozen. Its retired voice and management fields carry inert placeholders, and readers remove them before domain validation. Management commands and voice configuration are refused; `create-thread managed:false` remains an inert compatibility spelling. A host reporting live legacy assignments must be updated through the existing Update action before ordinary work continues. Its history and drafts remain readable, and draft saves and Stop remain available. A host without assignments can continue ordinary v1 work. There is no legacy unassign exchange.

[ADR-0008](0008-independent-coordinator-and-thread-providers.md)'s native account discovery and new-thread default resolution stay unchanged. Unused API-reasoning and automatic-coordinator controls will be hidden while saved credentials remain for later work. [ADR-0035](0035-an-agent-can-set-up-a-host-from-add-host.md)'s setup jobs remain ordinary user-started threads, and [ADR-0061](0061-a-thread-can-babysit-its-pull-request.md)'s explicit babysitting remains. The supervision exception for Codex URL elicitations and app-tool confirmations ends; users continue answering native requests. [ADR-0013](0013-memory-hidden-for-the-beta.md) and the memory gate are unchanged.

The removal plan's prototype and UI clarification step was skipped: the removed surfaces already default off behind the beta flag, and Zach accepted hiding the unused reasoning controls. The foundation commit changes no renderer surface. Later commits remove the surfaces and engines; final verification records the actual desktop, host, dictation and phone checks.

October 9 connection feedback decision: first-run setup and Settings, Providers show connection status themselves and leave the Threads room quiet. Connections Sotto makes at startup remain quiet too. Connect providers and Reconnect pressed in Threads still announce success there; connection failures remain visible. A connect command may carry `notice: false` solely to leave success feedback unset. It grants nothing and changes no provider action or answer policy.
