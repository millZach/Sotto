# Sotto's browser does what T3 Code's does

Proposed on November 27, 2026, for Zach's review. Rez asked that Sotto's browser do everything T3 Code's browser does. T3 Code's agents read a page as an accessibility tree with refs, act on elements by ref, answer dialogs and file choosers, wait for things, run script, set a device size and colour scheme, and record a video; its users see local servers, answer dialogs and take a page over. Sotto's agents could inspect the element at a point, screenshot, navigate, click and type at a point, press a few keys, scroll and set a size. [The research note](../research/2026-11-27-t3-browser-parity.md) compares the two feature by feature. This decision builds the gaps, in Sotto's terms, as an Owl feature, `browser-parity` in `src/shared/owlFeatures.ts` (ADR-0072). Browser profiles, the other half of the gap, are [ADR-0221](0221-browser-profiles-keep-the-users-sign-ins.md).

No mock-up round was held. ADR-0011's rule asks for one when the direction is not settled; here Rez's request settled it (match T3 Code), and every new piece sits on a surface that already exists: the dialog card and the recording line are the **browsing strip**'s, the menus are More's, and the local servers sit with **Opened this session**. Each was checked in the built app in light, dark and reduced motion at 1600x1000, 1280x800 and 820x560 ([verification](../verification/2026-11-27-browser-parity.md)).

## Decisions

1. **One Owl feature, checked on both sides.** `browser-parity` is off unless turned on, and not sent to stable. Main reads it once at start: off, the tool server lists the stable catalog, the browser service refuses every new action in words, and the pane's new channels answer "not on". The renderer reads the same answer and shows none of the new pieces. Turning it on or off takes a restart, as every Owl answer does.
2. **The full catalog.** `browser_action` adds `snapshot` (the accessibility tree with a ref on each element, the page's visible words, its console messages and errors, and a picture on request), `hover`, `select`, `drag`, `upload`, `wait_for`, `evaluate`, `dialog`, `appearance`, `record_start` and `record_stop`. Click, type, scroll and key take a ref from the latest snapshot, a CSS selector or a point; click takes a button, a count and modifiers; type can replace; key takes named keys, F-keys, one character and modifiers, with macOS's editing commands under Command. `navigate` waits for `load`, `domContentLoaded` or nothing, `screenshot` can keep a PNG and take the whole page, and `viewport` takes T3 Code's 17 device presets in either orientation, or `fill`. `browser_open` takes a port, path and protocol for a server on this computer, and `background: true`. Two tools are new: `browser_close` and `browser_servers`. A ref lasts until the page changes, the agent takes another snapshot, or the user takes the page over; a stale one is refused in words.
3. **Two catalogs, and Antigravity keeps the stable one.** The stable catalog is unchanged, so a thread without the feature sees what it saw. `agy` drops a session's largest tool without saying so once its tool declarations pass about 58 KB (ADR-0219, decision 2), and the full catalog's words would cost Antigravity `delegate`. An Antigravity thread asks the tool server for its catalog compact and is listed the stable one; its calls to a full-catalog action are refused as they would be with the feature off.
4. **Servers started from Sotto, and only those.** The empty pane and `browser_servers` list web servers on this computer's loopback that a process started from Sotto is serving: Sotto reads its listening sockets (`netstat` on Windows, `lsof` on macOS, `ss` on Linux) and the process table, keeps the ones whose process descends from Sotto and is not Sotto, and asks each for its first page with one `GET /` on loopback, for its title. Nothing is kept, nothing leaves the computer, and a server the user started elsewhere is never listed, so a list never tells an agent what else runs here. A server may belong to another thread; the tool's words say so.
5. **Upload always asks.** Giving a page files sends them off this computer, so `upload` asks every time, naming the files, whatever grant the thread holds; nothing but the user answers it. Its files come from the thread's own folder, by a relative or absolute path, or from Sotto's browser files for the thread (decision 7). A path outside both, a link pointing outside, a missing file, a folder or more than ten files are refused before anything is asked. With no target it answers a file chooser the agent's click opened, and `paths: []` cancels it.
6. **Evaluate is an action, masked, and off where a secret was typed.** `evaluate` runs one expression in the page and returns its JSON value, cut at 64 KB. It changes the page as a click can, so the browser grant covers it and without the grant it asks. Everything it says back is masked against secrets typed in the page (ADR-0219, decision 7), and on a page where a secret the user saved was typed it is refused until the page loads another document, since a script could read the field.
7. **Browser files.** A screenshot an agent keeps and a recording are written to `browser-files/` in Sotto's data folder, in a folder per thread named by a hash of the thread's ID, so no path names it; folders are the user's alone (0700) and files 0600 where the system has modes, written so they never replace a file. A start of Sotto deletes what is older than a week. A recording draws the page's screencast into a hidden window and encodes WebM with Chromium's own recorder, stops itself at 50 MB, and stops and is kept when its page closes or the user presses **Stop**; `record_stop` then returns its path.
8. **The user has the page whenever they want it.** Pause and Resume read **Take over** and **Hand back**. The user's own click, key, wheel or touch on a page holds an agent's input for 750 ms after it, and the strip says "You are using the page. The agent waits until you stop"; reading the page still works, a pointer passing over does not count, and the agent's own input never counts as the user's. Taking over or handing back forgets the agent's refs.
9. **The page's dialog is answered where the page is.** While Sotto's tools hold a page, Chromium draws no dialog for it, so an alert, confirm, prompt or leave-page dialog shows as a card in the browsing strip's place: the page's words, without control or direction characters, OK and Cancel, or Leave and Stay, a field for a prompt, and OK focused. The user or the agent's `dialog` action answers it. An action that opens one says so, and acting on the page waits until it is answered. Electron cancels `prompt()` in a page on this computer before Sotto hears of it, so a prompt is answered only on a paired host's page.
10. **What the browser grant covers.** The grant (ADR-0029) answers, as the user would, the actions that change a page the way a click or typing does: navigate, click, type, tap, key, select, drag, evaluate and dialog. Hover, scroll, wait_for, appearance, recording and every read ask nothing on a shared page, as scroll never did. Upload always asks (decision 5).
11. **Scroll moves what it names.** A scroll by ref or selector moves the element's nearest scrolling container, or the page, directly, and says how far it went or that it could go no further. Chromium routes a synthetic wheel by where the page is drawn, so a wheel aimed outside the part the pane shows was lost; a scroll at a point is still a wheel.
12. **Background pages, and closing them.** A page opened with `background: true` is listed in Tools and never brought forward or played for the agent, and its player appears only while it waits for the user. `browser_close` closes a page the agent opened, stopping and keeping its recording; a page the user opened stays open.
13. **A paired host's thread gets the same catalog.** The host's Chromium (ADR-0198) runs the same page automation, so every action works there. Recording, the server list and developer tools are this computer's only and are refused in words on a host's page; profiles are ADR-0221's and this computer's only. The host starts Chromium as before.
14. **Developer tools are the user's.** **Open developer tools** in More opens Chromium's own tools for the page, in a window of their own. No agent tool opens them.
15. **Nothing new is contacted, kept or added.** The pages an agent or the user open are the only sites contacted; the server list asks loopback only. Sotto keeps the browser files of decision 7 and nothing else. No dependency is added: the snapshot, input and recording use Chromium's DevTools protocol and its own recorder, and the server list uses the system's own commands. Windows first, then Apple silicon macOS and Linux, with the same code; only the server list's commands differ by platform. The README's privacy section says what is kept and asked.

## Considered options

- **Playwright in Sotto's main process.** It drives pages this way already, but it is a large dependency that would hold a second debugging connection to pages Sotto already holds one to. The DevTools protocol through Electron's own debugger reaches the same features.
- **Every server on loopback.** T3 Code lists local servers; listing every one would tell an agent what else runs on the user's computer, including other people's tools. Sotto's own children are the ones a thread can have started.
- **Let the grant cover upload.** Files leaving the computer are not a click; the grant answers what the user would do on the page, not what leaves it.
- **Draw the page's own dialog.** Chromium draws none while the debugger holds the page, and a native dialog would block Sotto's window; the card keeps the page drawn and the answer in reach of both the user and the agent.

## Consequences

An agent can test a web app in Sotto's browser the way it would in T3 Code's, by ref, and a user can watch, answer the page and take it over. Antigravity threads keep the stable catalog until `agy` takes the larger set. The server list reads system commands on every platform; a Linux or macOS without `ss` or `lsof` lists no servers, and the pane says none is answering. Recording on a paired host and a prompt on this computer remain open, each with its reason in the research note. Zoom, downloads, the agent's cursor, drawing on the page and passkeys are [ADR-0222](0222-the-browser-zooms-downloads-shows-the-agents-cursor-and-takes-drawings.md).

## November 27 amendment: what a review tightened

A review of this branch by Gemini, spot-checked by the orchestrator against the code, found places where the decisions above were not held to. Each is now held as follows.

- **Decision 3.** An Antigravity thread's call to a full-catalog action is refused over the tool server's `tools/call` as well as when listed, so a name it learned elsewhere does not reach the full catalog. `browser_close` is refused with the rest of the pane's and agent's full-browser requests while the feature is off.
- **Decision 5.** An upload gives the page copies made when the agent asked, checked again at **Allow once** (ADR-0222, decision 11). **Allow this thread** is not offered for an upload, and a request to allow one for the thread is refused, since an upload asks every time. Holding a file chooser for `upload` lasts for the agent's own action alone; Chromium's interception is turned off after it, and when the page navigates, so the user's own file chooser opens as before.
- **Decision 6.** A secret typed into a page keeps `evaluate` off for the rest of the page's life, not only until a navigation starts or a new document commits, since the page's history keeps an address that held it and a site can write it back into a later document; a new page has `evaluate` again. The page's address, title and every result are masked against it in more of its forms, and `wait_for` compares words and addresses with it masked (ADR-0222, decision 12 and its November 27 amendment). The host's page follows the same rule.
- **Decision 8.** The agent's `navigate` waits for the user as every other action does, and each of the user's inputs moves the moment the strip says the page is free again, so it says so once the user has stopped, not 750 ms after they began.
- **Decision 9.** A dialog's words are masked against a typed secret before an agent is told them, and are not told at all while a secret is in the document.
- **Decision 12.** `browser_close` leaves the page open while the user has taken it over, has stopped sharing it or is using it, as every other action waits.
- **Decision 4.** Servers are found on `::1` too, and by the shape of `netstat`'s lines rather than its words, which are in the system's language; a page's content type is read without regard to case, and each probe has one deadline.
- **Decision 2.** A snapshot's text is cut at 180,000 characters in all, and an element's attributes are read as name and value pairs, so a value that reads like a name is not taken for one.
- **Decision 13.** A paired host's browser service is given the feature's answer and its browser files folder, and sweeps that folder when it starts.
