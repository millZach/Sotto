# An agent asks for a secret on a private card

Proposed on November 27, 2026, for Zach's review. Rez asked for a secret request card like T3 Code's: an agent that needs a password, an API key, a token or a pairing code asks for it on a card the user types into, and the value never reaches the chat. T3 Code's `request_secret` opens such a card and gives the agent a one-use reference or a file. This decision brings the same to Sotto, in Sotto's terms. It is an Owl feature, `secret-requests` in `src/shared/owlFeatures.ts` (ADR-0072).

No mock-up round was held. ADR-0011's rule asks for one when the direction is not settled; here Rez's request settled it (match T3 Code's card), and the card is an affordance on a surface that already exists, the request card above the composer, drawn with that card's own parts.

A **secret request** is the card; a **secret reference** and a **secret file** are the two ways its value reaches the agent's work (`CONTEXT.md`). Distinct from a **secret answer** (#2153), which is a provider's own question answered in a masked field and does go to the provider.

## Decisions

1. **One tool server for every provider that takes Sotto's tools.** `sotto_secrets` is a loopback thread tool server, as `sotto_plugins` is, with two tools. `request_secret` takes a title (`label`), a `reason`, one value or up to eight `fields` (each a name, a label, a placeholder, and `secret: false` to show what is typed, for a user name or an address), an optional sign-in or setup `url`, a `delivery` (`secretRef` by default, or `file`) and a `timeoutMs` (ten minutes by default, an hour at most). `release_secret` lets go of references and files the agent is done with. The server tells agents to call `request_secret` instead of asking in chat, `request_secret` is marked to load up front where a client defers tools, and both are listed for Devin (`DEVIN_SOTTO_SERVERS`).
2. **Antigravity threads are left out for now.** `agy` drops a session's largest tool, silently, once its tool declarations pass about 58 KB (`antigravityToolBudget.test.ts`), and an ordinary thread is within 500 characters of that already. Offering `sotto_secrets` there would cost Antigravity `delegate`. `admitsSecretRequests` admits every other provider that takes Sotto's tools; an `agy` check at the larger size is what would let Antigravity in.
3. **The card is one of Sotto's own thread requests.** Its ID starts with `sotto:secret:`, so it shows where a permission does: in its thread above the composer, in Needs you, in the popup and Watcher's lists, and on a paired phone. The request carries the card (fields by name and label, the button's address, the delivery and when it closes) and never a value. Its words say the agent asks for a value it will not see, and its only choice is Decline, so any client that knows nothing of the card, a phone among them, can decline it and nothing more.
4. **Values come only from the main window, on the card's own channel.** `sotto:secrets:answer` takes the values from the main window, for a thread on this computer, and answers with nothing but whether it worked. It never goes through the request's answer, a saved draft, the answer store, an event or the window's state: the values live in the card's inputs while it shows, and in no other renderer state. The popup and Watcher show the request's words and Decline, as a phone does. A refusal never repeats what was typed, and nothing on the path logs.
5. **A secret reference is one use, in memory, in its thread.** `secret-ref:` and 32 hex digits, saying nothing of what it stands for. Main keeps the value in memory alone. Sotto's own tools take it once, in the thread it was given to, and it goes when used, released, after an hour, when its thread closes and when Sotto quits. The first tool that takes one is `browser_action`'s `type`, which types it into the focused password field of Sotto's browser (decision 7); a later Sotto tool takes it the same way, through `takeSecret`.
6. **A secret file is the user's alone, and short-lived.** For a command (`sudo -S cmd < "$file"`, `adb pair host:port "$(cat "$file")"`), the value is written to `secret-files/<32 hex digits>` in Sotto's data folder: the folder mode 0700 and the file 0600, written so it never follows or replaces a path already there. Windows ignores those modes, so there the folder's inherited permissions are replaced by full control for the signed-in user (`icacls`). The file is deleted when released, after an hour, when its thread closes and when Sotto quits, and the folder is emptied at start, so nothing survives a restart. The agent is told never to print it.
7. **The browser types a secret only where the page masks it.** `type` with `secretRef` asks, and runs under the browser grant (ADR-0029), exactly as `type` with text does, but it types only into a focused `<input type="password">`, so no screenshot shows it. The value is taken from main as it is typed, not when it is asked for, so a declined or lapsed action spends nothing. The page's automation remembers what it typed while the page is open, and masks it in everything the page says back to the agent: its inspected words, errors and, with ADR-0220's tools, evaluated values and snapshots. The request and its step say "a secret you saved", never the value. A paired host's browser takes no reference (decision 9).
8. **The value never reaches** the tool's result, the transcript, the event store, the provider, a log, a notification or any renderer state beyond the card's own inputs. `secretRequestsCanary.test.ts` sends one known value through every delivery and asserts it appears in none of those, nor in any file in Sotto's folder but the secret file itself.
9. **A paired host's threads and a phone.** A paired host's threads are not offered `sotto_secrets` in this version: their agent runs on the other machine, so a reference or a file would have to be made there and the value carried over the host connection, which is a path this decision does not open. A phone shows the card's words and Decline and cannot type a value, since that would carry it through the relay; the value is always typed on the computer that runs the thread. Both are later decisions, each with its own path for the value.
10. **Asking is not a grant.** The card is the user's own action, typed by the user. Saving it approves nothing else: the browser grant, and every other request, still decide what the agent may do with the value.
11. **Nothing new is contacted or kept.** The sign-in button opens the user's own browser at the address the agent gave, an http or https address without credentials. No dependency is added. The README's privacy section names the file and the memory and how long each lasts.
12. **Off, it is dormant.** With `secret-requests` off, or the local host off, the server is not offered, the channel is not registered, the bridge is absent and no card shows. Windows first, Apple silicon macOS and Linux alike, with `icacls` on Windows and file modes elsewhere.

## Considered options

- **Values as the request's answer.** One path for every answer, but it runs through drafts, the answer store and the phone, each of which would have to learn to forget it. A channel of its own keeps the value off all of them.
- **Ask in a masked question.** That is a secret answer (#2153), and the provider sees it. Here the provider must not.
- **Keep values on disk across a restart.** A file that outlives Sotto is a file the user did not know about. A restart asks again.

## Consequences

An agent that needs a credential has a way to get one that is not the chat, and the instructions say so. Antigravity threads still ask in chat until `agy` takes the larger tool set. `takeSecret` is the seam for every later Sotto tool that types or sends a value: it must take the value once, as late as it can, and mask it in what it reads back.

## November 27 amendment: where a reference is typed, and what a file's card says

A second review of this branch found that a reference could be typed on any page the agent reached, and that the card promised more of a file than is true. Each is now held as follows.

- **Decision 7, the site.** A reference is bound to the site of its card's sign-in page, the origin of `url` as Sotto kept it. Sotto's browser types it only on a page at that origin. It checks when the agent asks, again when the action runs, and once more against the document's own `location.origin` just before the value is taken, so a page whose address changed without another document loading is caught. A page on another site is refused in words, under the browser grant too, and the reference is kept for its own site. A card that named no page binds no site, so every `type` with its reference asks the user, whatever grant the thread holds: the request names the page it would go to, and **Allow this thread** is refused for it. The tool's answer tells the agent which of the two it has. The limit is the site itself: Sotto cannot tell a sign-in page from any other page on the site the agent named, nor an agent's own server on `localhost` from the user's.
- **Decision 7, spending.** The value is taken only after every other check, the field's focus and the site among them, so an action refused for any reason spends nothing. Since the value then comes from the engine, which can be another process, the page is looked at once more before it is typed: a page that moved the focus or loaded another site meanwhile gets nothing, and the agent is told that reference is used.
- **Decision 7, the page's script and pictures.** A secret is not typed into a document the agent ran script in, or while the page records, and no picture of a page that holds one goes to the agent. Once one was typed into a page, `evaluate` stays off there until the page closes, and `wait_for` and selectors cannot test the value a character at a time (ADR-0222, November 27 amendment).
- **Decision 7, masking.** The value is masked however an address escapes it: in hex of either case, once or twice over, some characters and not others, a space as `+`; and as JSON escapes it, `\u` escapes included.
- **Decision 7, a spent reference.** Whatever stops the typing once the value is taken says the reference is used, a page that changed meanwhile included, and an action the user allowed that fails then answers the agent as an error that says so.
- **Decisions 3 and 6.** A file is read by the agent's own commands, so the card no longer says the agent and its provider never see it. It says the file stays out of the chat, but anything those commands print reaches the agent and its provider. The words a phone shows say the agent's commands read it from a file and the agent is told never to print it. A reference's card names the site it is typed on, by its host for an https page and with its scheme otherwise, as Sotto binds it, or says Sotto asks before typing it on any page.

## November 28 amendment: how the value is found, and what is masked before it is shortened

A third, independent review found where the second round's masking failed, or let part of a value through. Each is now held as follows.

- **Decision 7, finding the value.** The value is found without a regular expression. A pattern built from it overflowed V8's compiler once the value passed about 5,000 characters, which a private key does. That error carried the value, and every browser tool in the thread failed after it. The pattern also backtracked without end on a page of backslashes when the value held one. The text is now read a character or an escape at a time in four ways: as it is, as JSON writes it, escaped once, and with every escape at once. In each, the value's UTF-8 bytes are looked for with the Knuth-Morris-Pratt search, so the time grows with the text and the value added together. Should finding it ever fail, the whole text is the mask, and nothing of the failure goes on.
- **Decision 7, what is masked.** The page's own origin is left whole wherever it is written, since the agent knows the site it was given. So a PIN that is also the page's port, as 5173 on `localhost:5173`, no longer breaks the page's address, and whether the agent may see a page is decided from the page itself, not from an address that was masked. A value shorter than three characters is not masked, as one that short is as likely the page's own words; the page's rules hold all the same.
- **Decision 7, masked before it is shortened.** The page's words are masked before they are cut, have their spaces closed up or lose their marks, so none of that leaves part of the value. This covers a snapshot's text, tree and console, errors, dialogs, `inspect`, the page's title, a download's name, and the element the user points at or comments on, which goes into their message to the agent. Where the page itself cuts what it hands over, it is read further, by as much as the value can take written out, so a value that starts before the cut is there whole to be masked.
- **Decision 7, the copies a page or Chromium makes.** The value is also looked for with each run of its spaces closed up to one and none at either end, as a page shows its text, and with each character a file name cannot hold made `_` or `-`, as Chromium names a download before Sotto is told the name. What a field kept of it once typed, cut at its `maxlength` or without a line break, is masked as well, since a form sends what the field keeps. A page's own later change to the value is not followed.
- **Decision 7, an element's markup.** The markup of the element the user points at is masked whole before its tags go, so a value in an attribute goes with its tag, then each run of words between tags, then the words joined. An element whose words, with their tags or spaces closed up, would spell the value, as a PIN drawn a digit to a box does, says none of its words, as each piece is a part of it that no mask finds.
- **Decision 7, what else is masked.** The address a picture is taken at, which the user's feedback names to the agent. `inspect`'s answer is measured once masked, since a mask can be longer than the value it stands for, and an element's role there is cut as its name is.
- **Decision 7, a spent reference.** When typing fails after the value was taken, the agent is told only Sotto's own words, never the error's: one from the debugger or a paired host could quote the command, which held the value. The user sees plain words for an action they allowed that then failed. The agent still learns its reference is used when the page stopped being shared meanwhile.

## November 28 amendment, after the fourth review: what the window takes, and words tidied before they are masked

A fourth, independent review found where the third round's masking still failed. Each is now held as follows.

- **Decision 7, what the window takes.** A mask is eight characters, so masking a value shorter than that makes the words longer. A dialog's words, a page's title or its address that then ran past what the window takes made the window drop every news of the page, and its list of pages fail. What is masked is now cut again to what its place takes: a dialog's words at 2,000 characters, a title at 512, an element's name at 500, a task's output at 200,000. What it is cut from is masked already, so the cut takes off only the end of a mask. An address is cut until the window takes it, as escaped there, where each character of a mask is nine. One whose mask would reach into its origin, or that does not parse once masked, is said as its origin and a mask.
- **Decision 7, tidied before it is masked.** The value is looked for with its spaces closed up, but the page's words were masked as written and only then tidied: spaces closed up, line breaks and tabs made spaces, marks taken out. So a passphrase the page wrote across a line break, or with a mark inside it, was put together by the tidying and then cut through before it could be masked whole. Every place that tidies and cuts the page's words now does it in one order: tidy, then mask, then cut, with the value looked for both as the page wrote it and as tidied. That covers a snapshot's tree, a dialog, the element the user points at or picks, and the page's title. The words of a picked element whose markup was cut short are masked before the end the cut left is dropped.
- **Decision 7, a `+` is a `+`.** An address can write a space as `+`, so the value was looked for with every `+` read as a space, in the value and in the page's words alike, and a value with a `+` in it masked words with a space there. Now only a value that holds a space is also looked for with that space written `+`; a `+` in the value is only ever a `+`.
- **Decision 7, the page's own origin.** Whether a later document shows the value, and whether a field holds it, are now decided as everything else is masked, with the page's own origin left whole. A PIN that is also the page's port, or a password that is its host, no longer makes every document of a signed-in app count as showing it because its scripts name their own origin, nor every field that holds an address on it.
