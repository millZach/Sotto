# First-run setup covers the agents and ends in the Threads tour

## Status

Accepted October 8, 2026, by the owner's choices in `docs/prototypes/first-run-setup-prototype.html`. Setup should cover dictation, the coding agents, other computers and the iPhone beta. It includes checking the agents, adding a first project, choosing a look and a quick tour at the end. Of the three variants the owner picked A, "Guided steps", with variant B's tour over the real Threads page, and kept dictation first. The iPhone step opens a public TestFlight link, and only new users see setup.

Amended October 9, 2026, after the owner walked setup in a test build: the microphone, shortcut, coding agents and iPhone steps scrolled inside the card at Sotto's default 1080x720 window, a passed microphone test said only that access was confirmed, and only Codex connected on its own. From `docs/prototypes/first-run-setup-fit-prototype.html` the owner picked A, "Trimmed card", the microphone test that passes once it hears a voice, and connecting every installed agent wherever Connect providers runs. Decisions 1 and 3 now say so, with a new decision 7. Everything else here stands.

## Context

Setup had four steps, all about dictation: welcome, microphone, OpenRouter key, shortcut. It then opened Threads, where a new user met an empty page. A fresh install connects no agent client by itself (`connect` runs at start only once a provider is enabled, `src/main/agents/control.ts`), so nothing told the user that Threads need one, which clients Sotto found, or that projects, other computers and the iPhone exist. Each of those has a home already: Settings › Providers, the sidebar's Add project, Settings › Hosts and Settings › Phones.

## Decision

**1. Nine steps in four groups, dictation first.** Start: welcome, look. Dictation: microphone, OpenRouter key, shortcut. Agents: coding agents, first project. Elsewhere: other computers, iPhone. The bar at the top shows each group's steps. Every step after the welcome can be skipped. Its button says what a press does: **Continue** once the step's task is done, **Skip for now** until then. The microphone keeps its rule that moving on needs a test or an explicit skip, which is now that button. Its test is done once it hears a voice, the level Settings' own test counts as one (`MICROPHONE_HEARD_LEVEL`) for 300 ms in all. Then the box turns to the success colour, says **Sotto heard you. Your microphone works.**, closes the microphone and offers **Test again**. While it listens its button is **Stop test**, and after six seconds of silence it says it has heard nothing yet. Access alone is not a pass, but it still lets dictation run: a test that opened the microphone and was skipped before hearing anything does not mark the microphone as skipped.

**2. Each step reuses the surface that owns it.** Look writes `appearance` and sets both halves to one built-in theme through the appearance preview, as Settings › Appearance does. First project runs Add project on this computer, the one whose projects the step lists. Other computers opens Settings › Hosts' Add host dialog, with its device list, Tailscale prompt and host setup checklist. It offers Add it only: Have my agent set this up runs a host setup thread that asks its questions in Threads, which setup does not show yet, so that way stays in Settings › Hosts. The iPhone step's **Let phones connect** is the `phoneAccess` setting, with a pairing code once phone access is on (ADR-0033, ADR-0050); the paired phones and the name they show stay in Settings › Phones.

**3. The coding agents step connects what is installed and signs in to nothing.** Arriving sends `connect` with no provider: Connect providers, even when a client is already connected. On the desktop that now turns on and connects every client installed on this computer, Devin included, except one the user turned off, as a host does when it starts (ADR-0036). The default stays as it is while its client is installed, and that choice persists as it does from the Threads page. Main keeps what the press found (`installedProviders`), so a client it did not find says Not installed, with its install guide, and one the user turned off (**Turned off**, as on a host's tile) says so, with **Connect**, which is Settings › Providers' own connect for that client. A client Sotto has not looked for yet reads Not connected. Otherwise a row says Ready, Not signed in, Too old to use or Can't be started, with the client's own sentence. **Install guide** opens the maker's install page (`PROVIDER_INSTALL_GUIDES`). **Check again** retries the clients that reported a problem and runs Connect providers again, which picks up a client installed since. Provider commands go to the host selected for new work, so the step selects this computer first, sends nothing when it cannot (the local host is off, or the switch failed) and says why, and gives the previous selection back when it closes. A client's sign-in stays the client's own.

**4. Setup's links open the user's browser, on a press.** Install guide and **Get the iPhone beta** go through `openExternalLink`, as the update notes and Tailscale's guide do. Sotto itself contacts no new host, and the README's privacy section now says so. Get the iPhone beta opens `IPHONE_BETA_URL`, the iPhone app's public TestFlight link. The app is in internal testing (ADR-0032), so the constant is a placeholder until external testing has a public link, and the release procedure says to set it.

**5. The Threads tour replaces a closing card.** When setup saves, the Threads page opens with four notes on the real page: the sidebar, New thread, the thread area and Settings. The prototype's composer and widget stops are gone. A first run has no thread open, so it has no composer, and the widget is a window of its own. A spotlight is not possible across windows. The tour is a modal note: focus stays in it, `Escape` or **Skip tour** ends it, and a part that is not on the page is passed over. It is not remembered: it runs once in the session that finished setup, and a restart part-way through does not bring it back.

**6. Only new users see setup.** A profile with `onboardingComplete` never sees the new steps. Reset settings reopens setup as before.

**7. Every step fits the window it opens in.** At Sotto's default 1080x720 window and at the 820x560 minimum, each step's resting state fits its card with nothing to scroll. The bar above the card names the step, so a step has no icon tile or eyebrow of its own; only the welcome keeps its mark and eyebrow. The heading is 28 px, 23 px on a window under 640 px tall, and each lead is a sentence or two. The card still scrolls rather than clipping, for an error or a pairing code on a window at its smallest. `tests/e2e/first-run-setup-fit.spec.ts` walks the nine steps at both sizes, light and dark, and fails on any that scrolls.

## Consequences

The end-to-end specs walk setup through one helper that also ends the tour, and the design captures cover each new step and the tour's first stop. Setup has no voice-control step; voice control and thread management are removed (ADR-0065). Memory stays behind its gate (ADR-0013). Setting the TestFlight link, or changing an install page, is a one-line change in `src/shared`.
