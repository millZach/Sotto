# Short writing runs on the thread's own provider

Accepted September 22, 2026. Sotto writes four kinds of short text on the user's behalf: a thread's title from its first exchange, a new worktree's branch name from its first prompt, a commit message draft from the staged diff, and a pull request draft from a branch's commit subjects and capped diff. Until now all four went to a small OpenRouter model, the writing model, chosen in Settings under Cleanup and paid for with the OpenRouter key. The owner did not know that a thread's first exchange was being sent to OpenRouter to name it, and wants that stopped: "The title should be generated by the LLM being used in that thread."

**All four jobs ask the thread's own provider, in a side call.** A side call is one request to the same client, account and model the thread already uses, started in the thread's working folder, with the job's instruction and material as its whole prompt. It runs at the least thorough effort the thread's model reports, because a name needs no deliberation and the call comes out of the same subscription limits as the thread's work. The text that comes back goes through the same cleaning as before (first line, no quotes or trailing period, cut at a word) and the same caps: 2,000 characters of each half of the first exchange, 2,000 of the first prompt, 20,000 of a branch diff and 12,000 of a staged one. Only the transport changed. The first exchange stays with the provider it was written for, and no other service sees it.

**A side call never touches the thread.** It is never a prompt inside the thread's own session: the thread's transcript, history, activity and pane never see it, and it is never resumed, listed or counted as a Sotto thread. Each adapter keeps that promise with its client's own switches, each checked against the installed client on September 22:

- Claude Code 2.1.280: `claude --print --safe-mode --tools "" --permission-prompts none --no-session-persistence --output-format json --model <model> --effort <lowest> --system-prompt <instruction>`, with the material on stdin. No tools, no customisations, nobody to prompt, and no session file, so neither Claude Code's resume list nor Sotto's transcript reader can find it. `--bare` was the obvious flag and cannot be used: it reads only an API key and never the subscription sign-in the thread runs on.
- Codex 0.156.0: `codex exec --ephemeral --skip-git-repo-check --sandbox read-only --json --cd <folder> --model <model>` with the same switches Sotto's Codex reasoning uses (the shell and every other tool feature off, skills and MCP servers off directly and through the orchestrator, project instruction files and base instructions off), approvals set to never ask, and instruction and material on stdin. `--ephemeral` writes no rollout, so Codex's own thread list and the adapter's session-log watcher never see it. A tool item of any kind stops the call.
- Grok 1.0.41: its own `grok agent --no-leader stdio` process speaking ACP, the shape Sotto's Grok reasoning already uses, on a throwaway Grok home that is removed afterwards and that denies every tool inside Grok. The thread's leader session is never loaded for it and the adapter's alias store never learns it. Grok's headless `-p --output-format json` was tried first; it takes the prompt as an argument or a file rather than on stdin, returns the model's thinking alongside the answer, and in a live run set out to inspect the folder with its tools before answering, so the proven ACP shape won.

**Devin writes nothing.** A Devin thread keeps its placeholder title and its forms open with no draft. Devin's `-p` print mode exists, but it has no switch to keep the run out of Devin's own session list, no switch to turn tools off (its default mode approves read-only tools on its own), and it refuses an untrusted folder. Each of those breaks the rule above, so Devin's adapter offers no side call rather than a weaker one.

**A provider that writes nothing, or fails, leaves things as they were.** A disconnected client is not started for a side call, and no other provider is asked in its place. The title keeps its stand-in name, the branch its temporary `sotto/<token>` name, and the forms open the way they did before drafting existed. Main logs `short-writing-failed <job> <reason>`, where the reason is `unavailable`, `failed` or `empty`; no prompt text, reply or error body reaches a log.

**The writing model is gone.** `writingModel` leaves `AppSettings`, its schema, its default, the IPC patch allow-list and Settings; a settings file that still names one parses and drops it. The OpenRouter key no longer pays for any short writing. The Generated thread titles, Generated commit messages and Generated pull request text switches stay and gate exactly what they gated before, and titles and branch names still need Keep local history on. Transcript cleanup is not short writing and keeps OpenRouter under ADR-0006.

## Consequences

- Naming is slower. A side call starts its client cold, and a new thread's title arrived 9 to 22 seconds after the first prompt was sent in the live check (`docs/verification/short-writing-on-the-thread-provider.md`), where OpenRouter took one or two seconds. Titles and branch names run in the background; the commit and pull request forms wait for their draft as before, up to ninety seconds.
- Each side call is billed to the thread's own subscription, at the lowest effort the model offers.
- The Grok call copies Grok's own runtime into its throwaway home, as the Grok reasoning path does, and removes it when the call ends. That home holds the call's prompt in Grok's session store, so a home a crash, a kill or a failed removal left behind is removed the next time Sotto starts a Grok call or connects Grok, for side writing and reasoning alike.
- A remote host (ADR-0025, issue #209) needs no OpenRouter key for naming or drafting: the providers it runs already write for their own threads. `createAgentRuntime` builds the writer over its own `WorkspaceHost` and reads the switches through `writingSettings`, which carries no key. ADR-0025's sentence that titles and branch names on a host need the key is amended to point here.
- ADR-0014's sentence that the first prompt goes to the writing model to name a branch is amended to point here.
