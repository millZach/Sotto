Zach chose this shape on October 9 after [the first Windows live checks](../verification/2026-10-09-command-center-live-windows.md) and [the Codex benchmark](../perf/2026-10-09-command-center-codex-benchmark.md). It replaces this ADR's isolated read-only design. The A2 room, phone scope and provider-change continuity chosen on October 8 remain, following [ADR-0068](0068-remove-voice-control-and-thread-management.md) and [the plan](../plans/2026-10-08-command-center.md).

Sotto has one current **Watcher** on this computer, identified by main's durable local host and Sotto thread IDs, special thread kind, project and creation operation. Titles, tool arguments, prompts, phones and host commands cannot select it. The stat-signature cache and failure isolation keep ordinary threads independent of a missing or corrupt Watcher record. Retired conversations remain readable history and refuse resume. Creation retains ADR-0002's immutable bindings and flush-before-dispatch rule.

Before dispatch, main retains the original message's UTF-16 length and the complete wire message's SHA-256 digest on the owning Watcher request or delivered user follow-up. These optional fields contain no prompt words. Desktop details and deltas, and the phone's conversation, show the original prefix only for that host, thread and user-message identity when the complete text matches the saved digest. Native history, dispatch text, delivery evidence and permissions remain whole. A literal lookalike, another thread's message or changed native text stays whole.

Saved proof survives reopening and retirement. Older desktop records have no reliable original boundary and stay whole; guessing from a footer could remove text the user wrote. The phone retains its existing legacy matcher only when no proof exists. Presentation grants no authority and starts no provider work.

The display index keeps text-free proof independently of pane lifetime. Only held detail windows retain verified message text; closing or unobserving one releases that text, and an offscreen read verifies transiently. Unchanged messages in held windows share verification across assistant updates.

Watcher is a native thread launched as an ordinary thread of its provider, on the user's account, with native tools, settings, instructions, skills, plugins, hooks and user-configured tool servers. It uses no second key or OpenRouter reasoning account. Its neutral Sotto-owned folder is separate from registered projects; it can read and search anything the provider can normally read. There is no Sotto project-file broker or promise of project containment or secret filtering. Paired hosts get workers, not another Watcher.

Its native permission mode is pinned to asking before changes. Main and each adapter refuse changes that widen that mode, in plain words; model and effort changes remain allowed. Native one-time approvals remain available; remembered session/always grants are refused because they widen future permission. Working-copy changes remain refused. Watcher's own edit, writing-command and network permission requests are ordinary request cards. They do not stop or revoke its scoped server, and the user alone answers them.

`watcherPrompt.ts` says: you are Sotto's Watcher; coordinate the user's threads through `sotto_threads`; start or brief threads rather than editing or running things yourself; read and search as needed; never answer a thread's question or permission; say what you sent and to which thread. This is guidance, not enforcement. A model can ignore it or a user can ask for native work. Enforcement comes from the pinned native permission mode, durable tool scope, and the absence of any answering or permission-changing Sotto tool.

These are native permission modes, not isolation from inherited customization or servers. Existing native allow/deny rules and server permissions still participate. Codex's read-only sandbox constrains native execution, not an inherited MCP server running outside that sandbox; Claude and Grok's asking modes are not OS read-only sandboxes. Native authentication and provider-owned session/cache writes continue. Keep local history governs Sotto's stores, not the provider's persistence. We do not claim an asking mode can undo the user's existing provider permissions or prevent an administrator's startup hook from running.

## Windows Codex launch probe (October 9, 2026)

The lead diagnosed the first live failure: the user's elevated Windows sandbox requires one-time setup that fails on this computer. With command-line overrides selecting unelevated and read-only, the lead observed a successful PowerShell file read; project and Temp writes denied with UnauthorizedAccessException and no changed files; and curl exiting 7 while the same outside request returned 200. These are the lead's reported checks, not a claim that every network path is isolated. PowerShell runs in Constrained Language mode. OpenAI describes [unelevated as a fallback with weaker network isolation](https://learn.chatgpt.com/docs/windows/windows-sandbox#configure-a-legacy-fallback).

Before the first model turn on each Windows Watcher app-server, Sotto runs two zero-model-turn `command/exec` calls through that same server with an explicit read-only policy. It creates an owned synthetic probe folder in the thread's project, checks a `Get-Content` read against its marker, then attempts `Set-Content` to a separate probe file. Successful reads, an explicit permission-denied write result, and an absent output file are all required. Set-Content works in Constrained Language mode; a forbidden .NET method would not prove filesystem enforcement. Because app-server converts an uncaught sandbox denial into an RPC error, the PowerShell probe catches only UnauthorizedAccessException with the OS E_ACCESSDENIED HRESULT and emits a fixed denial marker. The cmdlet category varies between creating a file and opening an existing one, so it is not the enforcement check. Any other result refuses launch. Sotto removes only its known probe files and folder.

A failed, malformed, timed-out or inconclusive probe ends that app-server before it can receive a turn, with a plain refusal saying the read-only sandbox is not working and nothing was sent. The check runs again on early start, cold resume, settings/model replacement and a replacement client process; resident reuse needs no repeated probe. The override and probe never read or change the user's saved provider configuration or credentials. Fakes cover both working enforcement and refusal, including a successful write and an unrelated command failure. macOS uses its existing native policy and remains outside this Windows proof.

## Sotto's scoped servers

Only main's current identity gets the frozen `sotto_threads` server and its exact contract tool names. Codex uses per-tool `approval_mode=approve` with a prompt default; Claude uses exact `mcp__sotto_threads__<name>` allowances; Grok's scoped admission compares exact offered server/tool names. Preallowance admits a call to Sotto's boundary, never authority over a worker. Ticket 3 supplies the real local server with these frozen names. The earlier own-tools live suite retains its stand-in; the thread-tools live suite exercises the real service.

Attach `sotto_visual` and `sotto_pull_requests` as ordinary threads get them. Exclude Sotto's browser and host-setup servers from both offered servers and scoped admission. ADR-0029's automatic browser actions would exceed this shape. User-configured provider servers remain inherited.

## Proof and replacement of the old profile

Remove the admitted-combination list, version/platform gates, restricted flags and startup inventories, inherited-Codex-server discovery/disabling, Claude managed-policy and plugin/agent checks, Grok isolated home/ToolConfig, and permission-triggered shutdown. Remove the isolation live suite and benchmark harness; their dated notes and evidence remain historical records.

Fakes cover native tools/settings, exact scoped admission, all launch/resume/settings/replacement routes, ordinary request cards, permission-widening refusal and unchanged ordinary contracts. The opt-in `SOTTO_WATCHER_LIVE=1` suite selects one provider, never runs in CI, and uses at most four turns in a disposable project: scoped tool, native read/search, edit card interrupted without answering and unchanged sentinel, then scoped tool after cold resume. Windows additionally requires the same-app-server launch probe before any turn, and checks an unasked native write without a model turn. A successful unasked write stops the check; a sandbox setup failure leaves enforcement unproved. [The own-tools Windows note](../verification/2026-10-09-command-center-own-tools-windows.md) records actual results. macOS requires separate proof; a Windows result says nothing about it. No source admission list survives this decision.

This explicitly amends [ADR-0004](0004-authority-in-policy-records.md) and [ADR-0005](0005-codex-app-server-adapter.md) for bounded Watcher start/send authority. An actual top-level user Send to the current master creates a main-owned **Watcher request**, rooted in that user's message. Main admits start, send now, queue, steer, targeted stop and settle through the existing coordinator lanes, outbox and delivery receipts. Workers start at no wider than the user's effective new-thread default; an explicit narrower choice is allowed only when comparable. Existing workers whose permissions exceed or cannot be compared with that ceiling are refused. Main enforces a computer-wide limit of four distinct automated targets by default (setting 1–8), including reserved, queued, uncertain and waiting targets, and four total prompts per target per request. Retries, wake-ups, compaction, restart and model changes renew neither budget. Lowering capacity stops nothing and holds new admission until usage falls.

The human-only answer rules of those ADRs and ADR-0068 stay in force. No Watcher tool answers a question, approves a permission, changes policy or widens a worker's permissions. Native preallowance admits only a call to Sotto's scoped server; it grants no worker authority. Worker requests are answered on the worker's own request card. Watcher's own native question and permission requests use its normal request cards; only the user answers them. A request does not retire Watcher or revoke its tools. Main can enforce scope, identity, budgets and fences; it cannot prove that a generated brief faithfully interprets natural language. The original request reference and visible actions remain available to the user.

Direct user instructions or controls on a participating worker, including native and phone input, relinquish participation before dispatch. Main increments ownership generation and fences subsequent machine deliveries, retaining the user's drafts, queue and new turn. Opening, reading and answering an existing request card are not takeover. V1 offers the model no resume-ownership tool. User-only **Stop all** asks first, then stops only still-eligible threads Watcher started; it excludes the master, user-started and taken-over threads and unrelated provider subagents. A targeted stop records its action under the user's active request and may address an existing ordinary thread. Closed/stopped requests cannot be revived by a tool or restored history. An exact owning-host read that confirms an operation was never recorded retains a bounded text-free fence before the desktop refunds it; late packets and restart cannot turn that identity into a send. A bounded projection omission alone is not such proof.

Main wakes the master from observed participant and delivery changes, in bounded event batches, rather than model polling. [ADR-0061](0061-a-thread-can-babysit-its-pull-request.md)'s existing wake-up/queue path carries this distinct source of news without changing independent babysitting. Evidence carries source, observation time, identity, freshness and availability; a worker's claim is separate. Overview is a projection of all other threads, not a second attention store. Its precedence is Needs you, verified Landing, another open pull request, Quiet after twenty minutes of freshly observed active work without progress, Working, then Idle; display order is Needs you, Ready for review, Working, Landing, Quiet, Idle. Disconnection supplies stale/unavailable evidence, never an inferred failure or quiet turn. Landing is observed action/merge evidence and grants no permission.

`agents.json` names its record `watcher`; current and earlier thread kinds are `watcher` and `watcher-history`, and the capacity setting is `watcherInFlightLimit`. These names are set before the first preview persists this branch’s records, so there is no migration from the working names. Stores predating this branch still receive an empty Watcher record and ordinary `project` thread kinds.

`agents.json` keeps only versioned identities, requests, operation/retry/digest references, worker ownership generations, counters, reservations, takeover reasons/times, receipt links and read/wake positions. Tokens remain in memory. [ADR-0016](0016-sotto-owned-history-on-an-event-store.md)'s normal history-aware store holds messages and future cards; history off keeps Watcher words and file contents only in memory, including queues, drafts and evidence payloads. No prompt, file content, bearer token, tool argument, protocol body or error prose enters control metadata, logs or backups. After restart unavailable text is reported unavailable; uncertain delivery is reconciled, never replayed.

Paired-host automation requires the optional `watcher-control` and `watcher-reads` features with closed machine-origin operations and owning-host enforcement. Ordinary privileged desktop commands are no fallback, and generic socket/phone clients cannot forge that origin or acquire remote-answer authority. Host protocol remains v1; unsupported hosts retain readable existing summaries and refuse automation. Zach superseded the initial phone-hiding choice on October 11, 2026: Watcher will be visible and usable on the phone after ticket 8's prototype. Ticket 3 builds no phone surface; its state projection does not assume Watcher is invisible there. Ordinary workers keep their existing phone journeys on their owning host. The desktop's aggregate roster is not a phone host feature.

Changing provider waits for no in-flight master turn, worker slot, invocation or unresolved delivery, then creates a replacement native conversation with a new Sotto ID. The previous conversation becomes readable Watcher history according to history settings, its tools are revoked, and the current reference changes atomically. A bounded visible handover is offered through the replacement's send path only after the user chooses to continue. Worker ownership and receipts survive; the handover revives no stopped or taken-over request. This preserves ADR-0002 rather than rebinding one conversation across providers.

## October 11, 2026: local tool and room boundary

Ticket 5 adds the optional host-v1 `watcher-control` and `watcher-reads` paths. A headless host offers them independently of its release track, while stable desktops use neither. Both listeners require the paired desktop's SSH-written client record; phone and general socket pairings cannot claim machine origin, even with Can answer. The local tool bearer remains local. Request attribution binds the authenticated desktop to the master's creation identity, root user-message reference and ceiling; operations retain the exact master-minted target, retry, digest and receipt identities. The owning host imports these into the established Watcher service rather than duplicating adapter enforcement. Its own new-thread default and the master's default both apply. No policy is written and no request is answered.

The master persists and reserves capacity before sending. The host never creates master requests or extra global slots. A lost acknowledgement holds uncertainty until the owning receipt proves what happened; reconnection and host restart do not replay mutations. Host native or phone input fences ownership before the next machine writer. Scoped text-free projection pushes carry receipts, participation and sourced evidence, bounded at a thousand records of each kind, with separate exact operation reads. Thread reads use the owning store's positional cursor and epoch; no detail revision becomes a message position or event cursor. Older hosts keep ordinary summaries and refuse automation before the wire. No phone filter is introduced; Watcher's phone surface remains ticket 8 after its prototype.

The local service retains the model and effort in the creation intent, because recovering by a provider's first ready model could silently change the user's choice. Recovery resumes the saved intent under the same Sotto ID. A thread's immutable native binding remains unchanged.

Stop all uses a sixty-second, main-issued preview identity naming its exact eligible targets. An expired or changed preview refuses before stopping anything. Each target's ownership is rechecked at dispatch, so a later takeover can make a confirmed batch partial. The private room contract projects current identity/options, participation, takeover, capacity and text-free receipts without relying on desktop selection.

Forward reads use a position of -1 for a restart cursor before the first zero-based message. Card anchors and expected turn/last-user guards are separate identities. Local tools have no file broker and no remote-control fallback. With history off, machine queue items and Watcher drafts are omitted from disk while their control references remain.

Machine admission travels through the workspace, provider router and Sotto identity adapter as a private in-process guard, rechecked after native preparation and at the writer. It never becomes a field generic IPC or a socket client can supply. A machine interrupt cancels native work without sending a denial answer to a pending request. Targeted Stop increments participating generations and records `automationStopped`; it cancels only undispatched machine messages, retains uncertainty and prevents replenishment within those participations. A reserved creation whose target is unavailable returns its original receipt rather than dispatching again. Queued user continuations retain text-free draft/message references on their original request and share its budgets.


Ticket 3 also retains each participant's last observed native user-message ID as text-free metadata. When Owl returns after a stable session, a changed head that is not one of Watcher's recorded message IDs is takeover, including a normal Sotto user Send. Definitive pre-writer failures refund their prompt reservation; an unknown delivery retains capacity through takeover until reconciled. Explicit user Queue retains its original request even after Stop all, and refuses before the first actual Send. Machine Stop leaves user queues intact and waiting for the user's review.


Native creation uncertainty is retained separately from prompt delivery because the workspace can fail before the first prompt while creation is still unresolved. A stopped action uses the coordinator's outstanding command and fresh native reconciliation rather than requiring a prompt receipt. Owl's history-off queue cleanup also covers corrupt and abandoned write copies. Readable copies retain ordinary items; an unreadable copy identified as holding Watcher words is discarded without a plaintext backup. Stable leaves these dormant copies whole for Owl to own the cleanup.

## October 11, 2026: event news and evidence

Ticket 4 uses a two-second trailing batch deadline capped at five seconds from the first event. Quiet uses a single cancellable twenty-minute deadline per connected episode, reset by real message/activity/background-work progress and by fresh reconnect observation. There is no Watcher polling timer. Provider residency includes participating workers, independently of the user's reading marks.

Legacy babysitting news remains readable in the same follow-up queue. Watcher news is a separate discriminated source, checked before claim and again at the native writer after preparation. It carries only identities and references; a worker's pending card is opened on that worker and answered only by the user. A final takeover notice may outlive closure of its request as information, but a stopped request or retired master receives no news. Durable queued-event digests bound restart deduplication to the newest thousand events; uncertain delivery stays in the existing outbox.

The room's optional news, per-target evidence and observation fields add no channel or phone restriction. GitHub observers reuse babysitting and explicit Pull request reads. A changed head discards earlier-head checks, absent/refused checks stay unknown, and only the Pull request surface's current GitHub review decision supplies approval evidence. Git and GitHub observations older than five minutes are stale on projection, without another fetch. Checkpoints publish reliable file counts and stable unavailable reasons under their capture identity. They do not infer a native turn ID from the current thread, because a capture can precede the next turn. Turn line counts are omitted because this boundary has not proved text-diff attribution. Working-copy line totals retain their separate scope. Evidence projections stay in memory and history-off Watcher wake prose never enters queue files, metadata or logs.
