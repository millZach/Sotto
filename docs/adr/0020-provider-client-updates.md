# Provider client updates

Accepted September 21, 2026. Sotto drives four installed clients and until now said nothing when they fell behind. Two of them, Grok Build and Devin, refused every version but the one they were verified against, so the installed Grok client stayed on 1.0.5 while x.ai published 1.0.40. The pin was keeping the client old, and nothing in the app said so.

**Sotto asks the npm registry what is published.** Once an hour at most, per provider, `registry.npmjs.org` answers with the version its package's `latest` tag points at. The request carries a package name and nothing else: no key, no prompt, no transcript, no identifier beyond the ordinary web request any computer makes. This adds one host to the README's list, alongside the GitHub check the app already makes for itself, and it obeys the same shape: on by default, one line in Settings that turns it off, nothing installed behind the user's back. A provider that is not connected has no known installed version, so it is not compared.

**The channel that installed a client is the channel that updates it.** The resolved executable path and the npm global root say which, and the first live run of this feature is what taught Sotto to read them. A binary with `node_modules` above it is npm's, and so is a client whose package sits in the npm global root even when its real binary lives somewhere else entirely: Grok Build is 142 MB of `~/.grok/bin/grok.exe` that npm's install script put there, and `grok update --check --json` answers `"installer":"npm"` about itself. Only a client npm does not own, like Claude Code's installer in `~/.local/bin`, updates itself with `<client> update`. Devin ships inside the Devin desktop app, which updates itself; Sotto reports Devin's version and never offers to replace it. An install under any other manager is named, not driven: Sotto shows the command and lets the user run it. Guessing at another manager's layout is how a working install gets a broken second copy.

**npm runs as npm, not as a shell line.** `npm-cli.js` runs under this process's own Node, through `ELECTRON_RUN_AS_NODE`. The shell hop is where the live run broke: `cmd /s /c "C:\path
pm.cmd" install …` loses its quoting and answers "operable program or batch file", which is not a sentence anyone can act on. No shell, no quoting, same npm.

**A client is replaced while nothing is using it.** Sotto disconnects the provider, runs the update, then reconnects and reads the new version. Windows refuses to overwrite a running executable, so this is what makes the update work at all, and a turn in flight would be lost either way. A provider with a working thread is refused until the user presses Update anyway, which says in the notice what it will stop. Two updates never run at once. An installer that finishes without the version moving is reported as it is — the client that is open is the one still answering — because "updated" next to the old version is a lie the user can check.

**An exact version pin becomes a verified minimum.** Grok Build and Devin connected only to one exact version. They now connect to that version or newer and record that the installed client is past what Sotto verified; older is still refused, because the adapters read protocol shapes those versions were checked against. A newer client that changes its protocol fails visibly at `initialize`, which is a better failure than a client the user cannot update. The verified versions themselves stay where they are until someone checks a newer one against the adapter contract.

**The notice is one card in the corner.** Every behind client is a row in it, with one press to update them all, over the composer's corner in the region the toast already uses. Sotto considered a toast per provider and a pill that waits; four stacked toasts bury the composer, and a pill that announces nothing is a pill nobody presses. The card says what is installed, what is published, what a press will do, and after an update whether it worked and what to reconnect. See `design/provider-updates/provider-update-notice.html` for the three shapes and `docs/plans/2026-09-21-provider-client-updates.md` for the choice.
