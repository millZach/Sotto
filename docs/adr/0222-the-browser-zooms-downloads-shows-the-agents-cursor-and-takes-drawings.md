# The browser zooms, downloads, shows the agent's cursor and takes drawings

Proposed on November 27, 2026, for Zach's review. [ADR-0220](0220-sottos-browser-does-what-t3-codes-does.md) left five things T3 Code's browser does unbuilt: page zoom, downloads, an agent's cursor drawn where it acts, drawing on the page with speech, and passkeys. Rez asked for them too. Each had a reason to wait in [the research note](../research/2026-11-27-t3-browser-parity.md): zoom changes the scale every agent coordinate relies on, a download writes to the user's disk, and the cursor, the drawing and a passkey bridge each seemed to need something in the page. This decision builds the first four without putting anything in the page, and finds the fifth needs nothing. It also records two rules a review of ADR-0220's branch tightened: what an upload gives a page, and how long a typed secret keeps a page's script out. Part of the `browser-parity` Owl feature (ADR-0072); with it off, nothing here shows and downloads stay blocked.

No mock-up round was held. Rez's request settled the direction, and each piece sits on a surface that exists: zoom in More and as a chip beside the address, downloads in the browsing strip's place and in the empty pane under **Opened this session**, and the drawing in the mark-up editor Sotto already uses for pictures (ADR-0170). Each was checked in the built app in light, dark and reduced motion at 1600x1000, 1280x800 and 820x560 ([verification](../verification/2026-11-27-browser-zoom-downloads.md)).

## Decisions

1. **Zoom is the user's view, and the agent's pixels do not change.** Ctrl (Command on macOS) with =, - or 0 zooms the page as in Chrome, and the page does not get those keys; so do Ctrl with the wheel and **Zoom in**, **Zoom out** and **Actual size** in More, which name the keys. Zoom steps through Chrome's levels from 25% to 500%. Away from 100%, a chip beside the address says the level, and pressing it goes back to 100%. In a narrow row the chip is its magnifier alone, and in the narrowest, a docked panel's at the smallest window, it steps aside so More stays clear of the window's buttons; **Actual size** in More still says the level there. Zoom belongs to the site in its session, as in Chrome, so every page on that site in the same session changes with it. The test iPhone keeps its own fit, and a paired host's page offers no zoom yet. No agent tool zooms.
2. **Every coordinate stays in the page's CSS pixels.** Chromium already takes the DevTools protocol's input in CSS pixels at any zoom, and Sotto's screenshots were already scaled to CSS pixels, so a point from a screenshot is a point to click at 50% or 175% alike. What zoom does change is the size a page lays out at, so an agent's fixed size is sent to Chromium multiplied by the zoom, and `innerWidth` stays what the agent set; the device presets emulate a phone and are not scaled. A zoom change makes every ref on that site's pages stale, and the agent is told to take a snapshot again. In the built app at 50%, 100% and 175%, a click by ref and a click by point each pressed the element they named, the page stayed 1000 by 600, and so did the screenshot.
3. **A download waits for the user.** With the full catalog, a page's download is no longer refused. It starts paused, in `browser-downloads/` in Sotto's data folder, which nothing else reads, and the strip at the page's foot asks: "localhost:5173 wants to download a file. Where should it go?", with the file's name, **Save to Downloads**, **Save as…** (the system's Save dialog, starting in Downloads) and **Cancel**. Nothing reaches the user's folders until they answer; Save to Downloads never replaces a file; it adds a number, as `notes (1).txt`. A saved file offers **Open** and **Show in folder**, and a file that runs a program or script when opened (`.exe`, `.msi`, `.bat`, `.ps1`, `.js`, `.sh`, `.app`, `.dmg` and the like) only **Show in folder**. A page's suggested name loses folders, control and direction characters and names Windows reserves. The empty pane lists **Downloads this session**. A download nobody answered is deleted at the next start, and a run lists at most 100. A page in a browser profile asks the same way (ADR-0221, November 27 amendment).
4. **A download an agent's action started says so.** A download that starts during an agent's action on the page, or within three seconds of one, is the agent's: the strip says "The agent's action started a download from localhost:5173. Where should it go?", and the action's result tells the agent the file's name and that the user is asked. It asks exactly as the user's own does; no grant answers it.
5. **An agent does not read what it caused to be downloaded, unless the user saved it in the thread's folder.** `browser_pages` lists the thread's downloads with each file's name, state and whether the agent's action started it. It gives a path only for a file the user saved inside the thread's working folder, and then relative to it, as `downloads/report.pdf`. It never names a folder outside, so a file saved in Downloads or anywhere else is not the agent's to find through Sotto. A download is not a browser file (ADR-0220, decision 7), so `upload` does not reach it either.
6. **The agent's cursor is Chromium's overlay.** While an agent acts at a point, an arrow in the theme's accent with a white edge goes there, and a click or tap shows a ring for a moment. It is drawn with the DevTools protocol's `Overlay.highlightQuad` and `Overlay.highlightRect`, so no script goes into the page and no window sits over it. It glides there in six steps, or jumps with reduced motion, and goes 1.2 seconds after the last action. It is not drawn while the user points at something (the overlay is Point's then), on the test iPhone (a touch has no pointer), or on a paired host's page.
7. **No picture shows the cursor, and a recording does.** Every picture Sotto takes of a page (an agent's screenshot, a step's thumbnail, the evidence in Tools, **Screenshot to message**, a drawing's picture) takes the cursor off first and puts it back after, so the agent sees the page alone. A recording is the page as Chromium draws it, so it shows the cursor moving, which is what a person watching it wants.
8. **Draw on the page, on a picture of it.** **Draw on the page** in the pane's row captures the page as it looks now, hides the native page, and shows that picture in its place in the mark-up editor: pen, box, arrow, circle and note, with a **Comment** field. **Add to message** adds one draft item, as Point at something does: the marked picture named "Drawing on" and the page's name, carrying the comment, with the context telling the agent that the user drew on it. **Cancel** or Escape brings the live page back. Nothing goes into the page, and drawing is the user's own action, so it needs neither sharing nor the browser grant.
9. **Speech fills the comment through dictation.** Sotto's dictation types where the keyboard focus is, so the comment takes the focus when the editor opens, and while dictation is on it says "Dictation types here while this field has the focus". No new recording path is added to the browser.
10. **Passkeys need no bridge, and nothing in Sotto blocks them.** Chromium's own WebAuthn works in Sotto's pages, which have no preload. On Windows 11, in a `WebContentsView` set up as Sotto's pages are (sandboxed, no preload) on a session whose permission handlers refuse everything, as Sotto's do, `isUserVerifyingPlatformAuthenticatorAvailable` was true and `navigator.credentials.create` opened Windows Hello's own prompt (the system's `CredentialUIBroker`), which the probe then cancelled. In the built app a passkey was made and then used against Chromium's virtual authenticator. The permission handlers do not gate WebAuthn, so nothing needed changing. The system's prompt is the user's: an agent's click can open it, but only the person at the computer can answer it.
11. **An upload gives the page copies made when the agent asked.** Amending ADR-0220, decision 5: when the agent asks, Sotto copies each file into a folder of its own, checking that the file it opened is the one its path leads to without a link and inside the thread's folder or browser files. The user is asked about those copies, and at **Allow once** Sotto checks the copies still hold the same bytes and gives the page only them. A file changed, replaced or relinked after the request changes nothing. The copies go when the request lapses or the page that took them closes, and a start of Sotto deletes any left behind.
12. **A typed secret keeps the page's script out until the page is another document.** Amending ADR-0220, decision 6, and ADR-0219, decision 7: a secret is typed only into a password field, the one the agent named or the one already focused, and Sotto checks it still has the focus first. From then on, until a new document commits in the page's main frame, `evaluate` is refused and the agent is not told the words of a dialog the page opens. A change of the address's fragment, or a navigation that never commits, does not end it, and neither does **Stop sharing**. Everything the agent and the window are told about the page (its address and title, an action's result, a step's address) is masked against the value as typed, as JSON escapes it, and as a form or address encodes it. The limit is the page itself: one that reverses, hashes or re-encodes the value and writes that into its own words can show it in a snapshot, since masking matches only the forms above.
13. **Nothing new is contacted, kept or added.** No dependency is added: zoom is Electron's own, the cursor is the DevTools protocol's overlay, downloads are Electron's, and the drawing is Sotto's editor. Sotto keeps only the paused downloads until answered and the upload copies until used. Windows first, then Apple silicon macOS and Linux, with the same code.

## Considered options

- **Leave zoom out, as before.** The presets show a page at another size, but not at another scale, and a user who reads small text zooms. Keeping input and screenshots in CSS pixels makes it safe for agents.
- **Scale an agent's points by the zoom.** It would make every action's point depend on a value the agent cannot see, and the presets would need two answers. Chromium already gives CSS pixels; sending the fixed size times the zoom is the only change needed.
- **Save downloads straight to Downloads, as Chrome does by default.** Rez asked that Sotto never save silently, and an agent's click could otherwise write to the user's disk unasked.
- **Let an agent read any download it caused.** A page an agent visits could then hand it any file to read, and Downloads holds the user's other files beside it. A file the user saved into the thread's folder is already the thread's.
- **Draw the cursor with Sotto's script in the page, or in a transparent view over it.** Script in the page changes the page under test, which Point at something avoids. A view over the page would need its own input pass-through and z-order, and would not be in recordings. The overlay is Chromium's, already used by Point, and appears in the screencast.
- **Draw on the live page.** Same objection as the cursor's script; a frozen picture keeps the page as it was and gives the agent exactly what the user marked.
- **Bridge passkeys through a preload, as T3 Code does.** Untrusted pages in Sotto have no bridge to Sotto by design, and Chromium's own WebAuthn already reaches the system's authenticator, so the bridge would add a privileged path for nothing.

## Consequences

The user can zoom without breaking an agent's work, keep what a page downloads where they choose, watch where an agent acts, and show an agent what they mean by drawing on the page. An agent can start a download but never places or reads it unless the user saves it in the thread's folder. Passkeys work as in Chrome. Still open: zoom, downloads and the cursor on a paired host's page, and passkeys on macOS and Linux, which were not checked here.

## November 27 amendment: what the owner's review tightened

A review of this branch by its owner found places where the decisions above let a secret, a file or a name slip. Each is now held as follows.

- **Decision 12, before a secret is typed.** Once the agent has run `evaluate` in a document, a secret is not typed into it until another document commits in the main frame, since the agent's script could still be listening for keys or reading the field. `evaluate` is the one way an agent runs its own script in a page: `wait_for`, `select` and selectors pass the agent's words to the page as values, not as code, and `navigate` takes only http and https addresses. A secret is not typed while the page records, either.
- **Decision 12, an address that held it.** Once the page's address, a frame's address or an address within the document has held the value, as a form sent by GET leaves it, `evaluate` stays off for the rest of the page's life, since the page's history and `document.referrer` keep that address across documents.
- **Decision 12, pictures.** While a page's document holds a typed secret, no picture of it goes to the agent or into the task: `screenshot` is refused, `snapshot` with `includeImage` gives its words alone, the task keeps no thumbnail, and recording does not start, since a page can draw what a password field holds. An open dialog is still refused first, as before.
- **Decision 3, names.** Save to Downloads holds the free name it finds from the moment the user answers until the file is placed, so two downloads of one name, answered before either finishes, get a name each, as `notes.txt` and `notes (1).txt`. Names are compared as the disk compares them: without regard to case on Windows and macOS. The file is placed with a hard link, or a copy that refuses to replace one where the disk takes no hard links, so a file that appeared at that name after the user answered is never replaced: the download takes the next free name instead. **Save as** may still replace a file, the one the user chose in the system's Save dialog, but not a name another download holds. A file saved under a name that runs a program, by Save as, is only shown in its folder.
- **Decision 3, what runs.** Disk images (`.iso`, `.img`, `.vhd`, `.vhdx`), compiled help (`.chm`), Excel add-ins (`.xll`), ClickOnce references (`.appref-ms`), Windows Installer patches (`.msp`), and settings, library and saved-search files (`.settingcontent-ms`, `.library-ms`, `.search-ms`) join the files Sotto only shows in their folder.
- **Decision 3, a closed thread.** A download still asking in a thread that is archived, settled or deleted is cancelled and its waiting file deleted, since nobody is left to answer it. The engine tells the shell which threads are closed with each change to the thread list, beside their folders (ADR-0210). One the user already placed goes on to where they said.
- **Decision 5.** `browser_pages` lists only the downloads the agent's own action started, and those from a page that is shared with the agent now. A download from a page the user keeps private, never shared or made private with **Stop sharing**, is the user's alone, and so is one from a page that has closed.
