# The iPhone opens on Focus Threads

Amended October 4, 2026 by [ADR-0051](0051-the-iphone-takes-the-glow-look.md): the look is Glow, the thread page places the agent's steps between messages instead of on an Activity tab, Settings holds the theme, text size, density, local alerts and new-thread defaults, and a question with one-tap choices or a permission can be answered on its Threads card again. What follows about navigation and Settled still holds.

Accepted September 29, 2026. Zach chose variant A, **Focus**, from the thread redesign study, then asked for a permanent search pill and for Settings to replace Needs you. He approved the revised prototype at `0d3e5835` on `prototype/ios-threads-redesign` with “Looks good” and subsequently requested native implementation; the design approval is recorded at `54607463` on that branch.

The iPhone opens on Threads. Questions and permissions come first, working threads have room to show their activity, and recent threads use quieter rows. Search remains visible beneath the heading and computer selector. The three tabs are Threads, Computers and Settings; Threads carries the waiting-request badge, which since ADR-0046 also counts recent threads that finished unread. Requests are opened and answered in their thread, so removing the separate Needs you page removes no permission or question capability. This chooses one place to read and act on threads over a separate request inbox, project-first folders or a chronological preview list.

Reachable requests and ongoing work remain visible above Settled even when their thread or project is settled. The other settled threads start collapsed, and a search exposes matches without an extra expansion step. A finished turn and a settled thread remain different things. Working, background work, Waiting and Compacting context keep their existing meaning; an unreachable computer cannot establish current activity from its last snapshot.

Settings stores Dark or Light appearance and Larger text on this iPhone. Dark is the default. The controls do not change a computer's settings or synchronize themes from it. This amends the mobile-appearance exclusion in [ADR-0011](0011-main-window-themes-replace-the-accent.md), while keeping the native-client boundary in [ADR-0025](0025-headless-host-and-client-identity.md): SwiftUI and system frameworks, host protocol v1, host-qualified thread identity, and authority only from the host's policy and the user's explicit answer. Local display preferences need no host setting or new transport operation.

The HTML study records the selected hierarchy and spacing; it is not evidence of native accessibility, live thread status, connection recovery or delivery. Native compilation, simulator inspection and live device verification remain separate checks in [the implementation plan](../plans/ios-focus.md).

## September 30 amendment: create on a chosen computer

Zach asked to create threads from iPhone and chose variant B, the guided flow, over a compact options sheet and a list of projects grouped by computer. He then asked to choose a project folder that was not already active in Sotto. New thread therefore chooses a computer, a known project or an existing folder on it, then that computer's model, effort and permissions. The folder browser uses the existing `host-folders` extension, including drives on Windows, name filtering in the current directory, and a full path. It reads folder names, never file contents. The study is retained on `prototype/iphone-new-thread`; [the plan](../plans/iphone-new-threads.md) records the source and verification.

The iPhone creates a manual thread in the shared project folder, opens its conversation and leaves the first prompt to its existing reply path. Its model and effort start from the computer's saved new-thread choices when present. Its permission mode starts by asking, with an explicit mode on the command: a remote client without Can answer must not inherit a permissive desktop default. A more permissive mode is an explicit choice available only while that computer lets this iPhone grant permission. This follows ADR-0004 and ADR-0033; it adds no automatic permission answer or policy record.

Project registration and thread creation keep separate ID-only pending markers. An unconfirmed registration stops before creating the thread. A phone-minted Sotto thread ID lets a reconnect confirm the exact thread even after a receipt expires; an unknown registration receipt remains for the user to check and dismiss. Neither command is replayed. This adds no host, runtime dependency, listener or protocol version.

Existing-folder registration now refuses a folder that disappeared after browsing. It never turns that selection into a request to create an empty folder. The existing `useExisting` field carries this intent; no protocol field is added.
