# The command center is a read-only thread

Accepted October 9, 2026, following [ADR-0062](0062-remove-voice-control-and-thread-management.md) and [the command-center plan](../plans/2026-10-08-command-center.md). Zach chose the A2 room, phone scope and provider-change continuity on October 8. This record establishes the contract; no provider is verified or enabled to host it by this ticket.

Sotto has one current **Command center** on this computer, identified by its durable local host and Sotto thread IDs, special thread kind, project and creation operation. It is an ordinary native conversation on the user's Claude Code, Codex or Grok Build account and plan, never Devin, an OpenRouter reasoning account or a second API key. Its neutral Sotto-owned folder is separate from registered user projects. A paired headless host gets workers, not another command center. Creation and recovery preserve [ADR-0002](0002-sotto-owned-thread-identity.md)'s immutable bindings and flush-before-dispatch rule and extend [ADR-0035](0035-an-agent-can-set-up-a-host-from-add-host.md)'s special-thread admission pattern with a durable identity. Titles establish no identity.

The command center has an immutable read-only launch and turn profile. It has only the closed `sotto_threads` tools, with no native project writes, shell, extra MCP servers, browser, executable customization or native delegation around that boundary. Sotto brokers bounded, contained reads of registered project files; roots displayed to the model confer no filesystem capability. Profile preflight must prove the effective restrictions for the provider, model and platform, including startup and resume. An unverified combination is refused, with no asking-mode or prompt-only fallback. Native authentication and provider-owned session/cache persistence remain separate from Sotto's history promise.

This explicitly amends [ADR-0004](0004-authority-in-policy-records.md) and [ADR-0005](0005-codex-app-server-adapter.md) for bounded command-center start/send authority. An actual top-level user Send to the current master creates a main-owned **Command-center request**, rooted in that user's message. Main admits start, send now, queue, steer, targeted stop and settle through the existing coordinator lanes, outbox and delivery receipts. Workers start at no wider than the user's effective new-thread default; an explicit narrower choice is allowed only when comparable. Existing workers whose permissions exceed or cannot be compared with that ceiling are refused. Main enforces a computer-wide limit of four distinct automated targets by default (setting 1–8), including reserved, queued, uncertain and waiting targets, and four total prompts per target per request. Retries, wake-ups, compaction, restart and model changes renew neither budget. Lowering capacity stops nothing and holds new admission until usage falls.

The human-only answer rules of those ADRs and ADR-0062 stay in force. No command-center tool answers a question, approves a permission, changes policy or widens a worker's permissions. Native preallowance admits only a call to Sotto's scoped server; it grants no worker authority. Worker requests are answered on the worker's own request card. An unexpected permission outside the master's profile stops/revokes that profile, rather than inviting an approval. Main can enforce scope, identity, budgets and fences; it cannot prove that a generated brief faithfully interprets natural language. The original request reference and visible actions remain available to the user.

Direct user instructions or controls on a participating worker, including native and phone input, relinquish participation before dispatch. Main increments ownership generation and fences subsequent machine deliveries, retaining the user's drafts, queue and new turn. Opening, reading and answering an existing request card are not takeover. V1 offers the model no resume-ownership tool. User-only **Stop all** asks first, then stops only still-eligible threads the command center started; it excludes the master, user-started and taken-over threads and unrelated provider subagents. A targeted stop records its action under the user's active request and may address an existing ordinary thread. Closed/stopped requests cannot be revived by a tool or restored history.

Main wakes the master from observed participant and delivery changes, in bounded event batches, rather than model polling. [ADR-0061](0061-a-thread-can-babysit-its-pull-request.md)'s existing wake-up/queue path carries this distinct source of news without changing independent babysitting. Evidence carries source, observation time, identity, freshness and availability; a worker's claim is separate. Overview is a projection of all other threads, not a second attention store. Its precedence is Needs you, verified Landing, another open pull request, Quiet after twenty minutes of freshly observed active work without progress, Working, then Idle; display order is Needs you, Ready for review, Working, Landing, Quiet, Idle. Disconnection supplies stale/unavailable evidence, never an inferred failure or quiet turn. Landing is observed action/merge evidence and grants no permission.

`agents.json` keeps only versioned identities, requests, operation/retry/digest references, worker ownership generations, counters, reservations, takeover reasons/times, receipt links and read/wake positions. Tokens remain in memory. [ADR-0016](0016-sotto-owned-history-on-an-event-store.md)'s normal history-aware store holds messages and future cards; history off keeps command-center words and file contents only in memory, including queues, drafts and evidence payloads. No prompt, file content, bearer token, tool argument, protocol body or error prose enters control metadata, logs or backups. After restart unavailable text is reported unavailable; uncertain delivery is reconciled, never replayed.

Paired-host automation requires the optional `command-center-control` and `command-center-reads` features with closed machine-origin operations and owning-host enforcement. Ordinary privileged desktop commands are no fallback, and generic socket/phone clients cannot forge that origin or acquire remote-answer authority. Host protocol remains v1; unsupported hosts retain readable existing summaries and refuse automation. In v1 current and retired command-center conversations are hidden from phones, including old clients through host-side projection and targeted-command filtering; ordinary workers keep their existing phone journeys on their owning host. The desktop's aggregate roster is not a phone host feature.

Changing provider waits for no in-flight master turn, invocation or unresolved delivery, then creates a replacement native conversation with a new Sotto ID. The previous conversation becomes readable command-center history according to history settings, its tools are revoked, and the current reference changes atomically. A bounded visible handover is offered through the replacement's send path only after the user chooses to continue. Worker ownership and receipts survive; the handover revives no stopped or taken-over request. This preserves ADR-0002 rather than rebinding one conversation across providers.
