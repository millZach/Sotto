# Project-free personal chats have their own durable identity

Accepted September 13, 2026 for #68. A personal chat is a distinct conversation kind, not a project thread with an empty or invented project. It has its own Sotto-owned ID, provider binding, drafts, uncertain submission intents and cached native history. The existing project ThreadRegistry and public AgentThread project invariant remain unchanged. Using the project registry would either weaken project memory/authority boundaries or manufacture a project the user never selected.

The personal-chat service reuses CodexAppServerHost with a separate child process, alias directory and neutral app-data working directory. Its private conversation union permits a personal alias without projectId; public project snapshots filter it out. Only the dedicated personal snapshot and creation methods expose this kind. No native ID is transferred to the renderer. Normal native tools, skill discovery and provider-owned rollout persistence remain enabled; the constrained coordinator command parser is not involved.

New local chats capture the configured Codex model and effort. Unsupported coordinators report unavailable rather than silently choosing Codex. Creation/submission and answer intent are saved before their respective native writes. Draft revisions advance independently of network waits; accepting an older revision cannot erase newer text. Restart converts unfinished intents to uncertain and only reads the same owned native conversation. No uncertain operation is automatically replayed or rebound, including creation whose native ID was never received.

Relevant existing global preferences are retrieved through the existing explicit-memory query without project or thread scope, and are supplied as context, never grants. Initial context goes on thread/start because installed Codex 0.154 cannot resume an unmaterialized thread; subsequent turns refresh developer instructions through thread/resume. Native user text, client message IDs, command origins and assistant message IDs stay unchanged. Questions and approvals reuse the shared answer contract and require exact explicit user decisions; no personal-chat management or policy-writing path exists.

The history cache honors Keep local history: disabling it removes transcript, activity, generated title and submitted-answer/prompt copies from disk while preserving unsent drafts and recovery identities. Codex owns its separate native history and account configuration, as for project threads. Disconnect ends only the personal connection, declines pending requests and keeps recovery data; view navigation merely unsubscribes. Rendered presentation and the combined Phase 3 journey remain the integrator's responsibility.
