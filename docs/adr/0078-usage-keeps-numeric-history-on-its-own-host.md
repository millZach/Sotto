# Usage keeps numeric history on its own host

Superseded in part October 14, 2026 by [ADR-0083](0083-usage-counts-every-clients-work-on-each-computer.md): Usage now counts every client's work on each computer, read from the clients' own local records, including sub-agents and work outside Sotto; older Sotto prompts come from the thread store; prompts count under the model that served them; and Claude's limits are read on demand through Claude Code's `get_usage`. The scope, history, prompt, model and Claude-limit rules below are historical; the store, Clear, Owl gate and host rules stand.

Accepted by Zach on October 12, 2026. Usage is an Owl feature (ADR-0072): stable opens no Usage store, starts no new collection or limit readings and preserves the dormant records. Existing thread usage accounting remains available as before.

Zach chose both native account limits and activity Sotto has observed, covering every connected computer. They measure different things. Account limits can include other clients and side calls; they are displayed per provider and computer, never added together or inferred from token counts. Codex and Grok can read native account metadata without inference. Claude supplies passive native limit events; an idle refresh cannot manufacture an observation. Devin's unverified token and limit capabilities remain unavailable. No second key, private credential reader, paid refresh prompt or new network host is introduced. [The source study](../research/2026-10-12-provider-usage-dashboard.md) records verified wire capabilities.

Numeric history belongs to the computer that owns its threads, independently of Keep local history, thread deletion and rewind. Its separate local database retains only counts, instants, provider/model names, Sotto message/thread identities and hashes of native accounting identities. It contains no prompt, reply, transcript, title, folder, address, key or protocol body. The dashboard asks bounded aggregate queries through the existing host connection; history never grows the regular thread broadcasts. Calendar filters and daily/hourly views use the viewing computer's named time zone across every host.

An accepted prompt is one authored Sotto user message whose exact native echo confirms its message ID. Numeric metadata records the original selected model and origin after durable intent, before native execution. An uncertain result waits for evidence; a definitive refusal removes the pending record. Watcher messages and wake-ups are separate counts. Tokens describe observed native model requests, which can outnumber prompts and include native-client work on tracked threads. Input already includes cache read/write subsets, so total is input plus output. Missing fields stay unknown and partial counts remain lower bounds. Legacy accounting rows have no event dates and remain undated; automatic side-writing usage is not reconstructed.

Clear usage history is a separate user-confirmed action, guarded by each host's current revision and existing remote client authority. It removes numeric figures while retaining hashed exclusions, a clear generation and the import marker. Old native replay and further updates of cleared request groups cannot repopulate the figures. Only proved new work counts afterward. Persistence failures affect usage alone and never refuse or replay a provider send.

The new surface follows Zach's chosen **C: Focus** design: an index of useful headlines and one focused view, with Overview, Subscriptions and Models. The first prototype's visual feel was rejected; Opus 5.5 at xhigh made the independent pass Zach selected. Both passes and their verdict are archived under the [`prototype/usage-dashboard` tag](https://github.com/millZach/Sotto/tree/prototype/usage-dashboard/docs/prototypes).

All connected computers require an Owl host, rather than an Owl desktop activating collectors in a stable host. The same Owl prerelease can carry plain Node host archives built from its exact source commit and full Owl version; each host gates itself from its own packaged version and negotiates the optional Usage capability in protocol v1. Older hosts remain usable and report Usage unavailable until the user updates them. This extends ADR-0072's release scope to preview **host archives**, without introducing a macOS or Linux Owl desktop. Stable desktop and host release paths stay as before.

## Amended October 27, 2026: the selection is written right after the send

This record said Usage records a prompt's original selection and origin "after durable intent, before native execution". Usage's store now runs on the usage store worker, off main (ADR-0083, October 27 amendment), and a send that waited for the worker to write the selection waited 250–300 ms at the median during a history import on a copy of Zach's store. Zach chose on October 27, 2026 that sends never wait for Usage.

The selection is now written right after the send, never before. The coordinator hands it to Usage once the send is cleared to go, without waiting, and Usage writes it with its next flush. Flushes commit in the order handed over, so the selection is always written before the echo that accepts the prompt, and an accepted prompt still counts under the selection made when it was sent. The cost: if Sotto crashes between the send and that write, one prompt can be counted under the model the provider reports rather than the one selected, or missed from Usage. Nothing else is lost, and the message itself is unaffected. Everything else in this record stands.

## Amended October 30, 2026: before anything is recorded

From the desktop UI review (#1834), approved as proposed in `look-fixes-prototype.html` on the tag `prototype/ui-hillclimb-desktop`. While no computer has recorded any usage (the range shows nothing, a read without dates finds nothing either, and none was cleared), Usage shows one card in place of the views, the filters and a page of dashes: **No usage yet**, saying that prompts sent from Sotto and from the providers' own apps show here with their tokens and limits, and that filters appear once there is something to filter. The room-left gauges of the providers whose limits have been read stay above it, since limits come before any prompt, and a press on one opens Subscriptions with the views as before. The read without dates is asked only when the range shows nothing, and again when a computer's record moves; until it answers, the page says it is reading. With one computer chosen, or once anything is recorded, even outside the range, the page is as before; a cleared computer keeps its own **Nothing recorded yet**.
