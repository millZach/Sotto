# Sotto's interface speaks the computer's language

## Status

Accepted October 23, 2026. Zach asked for Sotto's interface to support the major European languages, Mexican Spanish, Arabic, Chinese, Japanese and the main languages of India, on the desktop app, the iPhone app and saysotto.com. Only the interface is in scope: dictation keeps Parakeet v3 and its 25 European languages (ADR-0071), and no speech model is added. Before building, he reviewed an HTML prototype (tag `prototype/interface-language`) with three language pickers, an Arabic screen laid out two ways, and Chinese and Japanese screens. He chose the picker as one row in Appearance, the window following the computer's language with that row overriding it, the thirty languages below, machine drafts with native review over time, and, after seeing both layouts, an Arabic and Urdu window that keeps the English layout. It is an Owl feature (`interface-language`, ADR-0072).

## Decision

**What is translated.** Everything Sotto itself writes for the person using it: every page, the floating widget, the tray, the application menu, Sotto's own dialogs, and the words main and the host send to be shown. What other people and programs write is shown as written: messages, replies, thread and project titles, file and branch names, terminal output, and text a provider or a remote host sends. What Sotto writes for a model stays English: Watcher's prompt, tool instructions and tool descriptions. So do the product and provider names (Sotto, Sotto Owl, Owl, Watcher, Muse, Claude Code, Codex, Grok Build, Devin, OpenRouter, Parakeet), strings that code compares by value (error codes, the stored provider labels, the sentences used as keys), and the English that Sotto reads from git, gh and the provider CLIs, which keep their `LC_ALL=C` pins.

**The interface language.** It is the language Sotto's interface is written in, and one setting holds it: `interfaceLanguage`, either `system` (the default) or a language code. Under `system`, Sotto uses the computer's language when it is one of the thirty below, matched by language and region (`es-AR` reaches `es-MX`, `pt` reaches `pt-BR`, `zh-TW` and `zh-HK` reach `zh-Hant`, `no` reaches `nb`), and English otherwise. Spanish with no region or from outside Europe reaches `es-MX` and Spanish from Spain or elsewhere in Europe `es-ES`; Portuguese from any region but Brazil reaches `pt-PT`; Chinese goes by its script, which a region implies. The first of the computer's preferred languages that reaches one of the thirty wins. A choice in Settings wins over the computer. The choice is one **Language** row at the top of Settings > Appearance, a list that starts with "Same as this computer (…)" and names each language in its own script, with its name in the current language beside it. The word "Language" stays beside the translated label, so someone who chose a language they cannot read can find the way back. A change applies at once in every window, the tray and the menu, with no restart.

**The languages.** English; Spanish for Mexico (`es-MX`) and for Spain (`es-ES`); French, German, Italian; Portuguese for Brazil (`pt-BR`) and for Portugal (`pt-PT`); Dutch, Polish, Swedish, Danish, Norwegian Bokmål, Finnish, Czech, Romanian, Hungarian, Greek, Ukrainian, Turkish; Arabic; Chinese in Simplified (`zh-Hans`) and Traditional (`zh-Hant`) script; Japanese; and Hindi, Bengali, Marathi, Telugu, Tamil and Urdu. Thirty in all. Russian, Korean and the other EU languages are not in this set.

**Right-to-left text in a left-to-right window.** In Arabic and Urdu the window keeps its English layout: the sidebar stays on the left, icons and arrow keys keep their direction, and the window controls stay where they are. Only text runs right to left, inside its own box. Paragraphs and descriptions start from the right edge of their box, short labels keep the English label's place, and code, diffs, paths, branch names and the terminal stay left to right, isolated from the text around them. Zach chose this over mirroring the window, which is the convention of Windows, macOS and iOS for their own apps.

**Type.** Figtree stays for Latin text. Other scripts fall through to the computer's fonts, keyed off `:lang()`, so Chinese and Japanese get their own glyph shapes. That only works if the window's `lang` follows the interface language, so it does. Sotto bundles a font only where a computer may have none: Noto Nastaliq Urdu (Windows has no Nastaliq face unless an optional feature is installed), and Noto faces for Arabic, Bengali and Telugu. Figtree's negative heading tracking is switched off for scripts it would break.

**How it is built.** The desktop uses Lingui as a devDependency, bundled into each process at build time, so no production dependency is added (ADR-0018). English stays in the source as the message itself. Translations are PO catalogs committed in the repository, one per area of the app, compiled into the build. Main resolves the interface language, from the setting and the computer's languages, and gives each window the answer as the window is made and again whenever it changes; a window draws its first frame in it. End-to-end runs and design captures read English as the computer's language, and the unit tests read English, so every test reads English on any machine. Sotto fetches none at run time and contacts no new host. The iPhone app uses String Catalogs and follows the iPhone's language for Sotto, which iOS already lets the user change in Settings. saysotto.com is built as one page per language from one template, each listing the others with `hreflang`, with a language menu of plain links and no redirect.

**Where translations come from.** A model drafts each language against a glossary drawn from `CONTEXT.md` and a list of names it must not translate. CI checks every catalog: messages parse, placeholders match English, and nothing is missing. A pseudo-language with longer, accented text (`en-XA`) and a right-to-left pseudo-language (`ar-XB`) catch clipping and direction mistakes in development, chosen with `SOTTO_INTERFACE_LANGUAGE` on an unpackaged run. The drafts ship on Owl under a "Preview" mark, and native speakers review a language when one is available. A message with no translation shows in English.

**Owl.** `interface-language` is an Owl feature. On stable the row does not exist and Sotto stays in English. A saved choice is kept whole, so it returns when the feature does. The iPhone app has no Owl track: it ships only through TestFlight, which is already a preview, so its translations ship in its next build with no gate (Zach's call, October 23, 2026). The website has no track either; its pages in other languages say nothing about the app's interface being translated outside Sotto Owl.

## Considered Options

- **Mirroring the window for Arabic and Urdu.** It is what the operating systems do, and the prototype showed it. Zach chose the kept layout: the window stays the one he designed, and the roughly 420 left and right style rules in the stylesheets do not have to be rewritten and kept mirrored.
- **A Language page with search, or following the computer with the picker tucked behind a link.** Both were prototyped. One row in Appearance is enough for thirty languages, and it is where someone looks for how Sotto looks.
- **i18next, FormatJS or a small in-house `t()`.** i18next and FormatJS are five to seven times Lingui's size in the window and check less at build time. An in-house parser is where silent wrong plurals come from: Arabic has six plural forms, and Polish, Czech and Ukrainian three or four.
- **A hosted translation service (Crowdin, Weblate) or a paid vendor.** The free plans are for public source, and the source is private. A vendor costs money and sends the strings out of the repository. Catalogs in pull requests need neither.
- **One Spanish (`es-419`).** Fewer catalogs to review, but Zach asked for Mexican Spanish by name, and the Spanish of Spain differs from it in vocabulary and in how it addresses the reader.

## Consequences

- Tests run in English. The suite asserts English text in thousands of places, and those assertions stay true because the test environments pin English.
- Every new string a pull request adds is a message. The catalog check fails on a translation that drifts from English, and a new English message shows in English until its translations are drafted.
- Text a remote host sends to the iPhone (a refusal, a failure) stays in the host's English until host protocol version 1 carries a code the client can translate.
- Durations and relative times that Sotto writes by hand ("4 min", "2 h", "just now") move to `Intl`, and so do dates now pinned to `en-US`.
