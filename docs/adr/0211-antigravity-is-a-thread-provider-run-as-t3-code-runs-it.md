# Antigravity is a thread provider, run as T3 Code runs it

## Status

Accepted November 20, 2026. Zach asked for Google Antigravity as a provider, "reference how T3 code does it and match that as close as possible", and answered the question cards the same day. Where T3 Code's way and Sotto's conventions part, he chose T3's every time: stable rather than Owl, all four of `agy`'s sign-ins, Sotto downloading `agy` itself, token counts and the account's limits, and T3's four permission modes with Sotto answering `agy`'s requests by the mode. He chose Watcher and short text on Antigravity, paired hosts and phones in the same change, and design B of the [design drafts](https://github.com/millZach/Sotto/blob/prototype/antigravity-provider/docs/prototypes/antigravity-provider-prototype.html) (tag `prototype/antigravity-provider`): signing in on the row, the model menu grouped by maker. How T3 runs `agy` is in [the research note](../research/2026-11-20-antigravity-in-t3code.md), read at t3code `236e90e`, with what `agy` 1.5.12 answered live on forge; the plan is [docs/plans/2026-11-20-antigravity-provider.md](../plans/2026-11-20-antigravity-provider.md).

This amends [ADR-0004](0004-authority-in-policy-records.md) (Sotto answers requests on Allow edits and Full access), the "One key" rule in AGENTS.md (a second key, the user's own Google one), and the README's list of hosts (Google's download, Google's limits).

## Decision

**The provider.** Antigravity joins as a thread provider, id `antigravity`, shown as **Antigravity**, on stable with no Owl gate. Its adapter speaks ACP over `agy acp` on stdio, one process per thread (ADR-0038): `initialize` with protocol 1, then `authenticate` with the sign-in method on every start, as T3 sends it eagerly; `session/new` or `session/resume`; `session/prompt`; `session/cancel`; `session/update`; and `session/request_permission`. The floor is 1.5.0, T3's, read from `initialize.agentInfo.version`; 1.5.13 is the version built against.

**Sotto's own Antigravity folder.** Every `agy` Sotto starts runs with `--gemini-dir <directory>/antigravity/gemini --app-data-dir antigravity-acp` and `GEMINI_HOME` set to the same folder, as T3 gives each instance a profile of its own, so a thread never reads or writes the user's own `~/.gemini`, and the user's own `agy` never lists Sotto's conversations. The environment is Sotto's allow-list, so no Google key or project variable of the user's reaches it, plus T3's: `AGY_ACP_FORCE_FILE_STORAGE=1`, `AGY_CLI_DISABLE_AUTO_UPDATE=1`, temporary files under Sotto's folder, and for a Google account `SSH_CONNECTION`, which makes 1.5 keep the sign-in in that folder rather than the system keyring. `BROWSER` is never set for a thread. On a headless host the folder is under the host's data directory.

**Getting `agy`.** Sotto downloads it, as T3 does: Google's platform manifest from `antigravity-cli-auto-updater-974169037036.us-central1.run.app`, the build itself only from `storage.googleapis.com/antigravity-public/antigravity-cli/`, refused unless its SHA-512 matches the manifest's, into `antigravity/runtime/<platform>-<arch>/versions/<version>/`. On Windows the build is `agy.exe` itself; elsewhere a `.tar.gz` holding one file, read out with the system's own `tar`. A version a running thread uses is leased and never removed under it. Antigravity's row offers Install, with its progress in plain words, Cancel and **Remove downloaded Antigravity**; the update line updates a copy Sotto downloaded and names any other. The program is looked for in T3's order: the binary path in Settings, then Sotto's download, then `agy` or `antigravity` by Sotto's CLI lookup (ADR-0036). Only a program named `agy` or `antigravity` is started, and only this machine's own Settings set the binary path; a paired client is refused.

**Signing in, design B.** The row offers `agy`'s four methods as one choice, each with its steps in the opened row:

- **Google account**, the default: T3's argv plus `--login`, through Sotto's paste-code sign-in (ADR-0200, ADR-0037). Main opens the `accounts.google.com` page only on a press, and the user pastes back the code, or the whole address, of the `antigravity.google` page Google lands on. On a host the page opens in this computer's browser and the code goes to the host's `agy`.
- **Gemini Enterprise**: ACP `authenticate` with `oauth-business`, the Google Cloud project and location written to `agy`'s own settings, finished in a browser on this computer, only on a press of Sign in, with fifteen minutes to finish. A host cannot finish it, since the page returns to `agy`'s own callback on the machine it runs on; T3 forwards that callback, which this version does not.
- **Gemini API key** and **Agent Platform** (Vertex AI, with a key or a project and location): the key is the credential store's `antigravity` slot on this computer, handed to `agy` in its environment only (`GEMINI_API_KEY` or `GOOGLE_API_KEY`), never in a file, an argument or a log, and the window learns only whether one is saved. A key is not copied to a paired host.

**Sign out** stops Antigravity's processes, sends `agy`'s ACP `logout` in Sotto's own folder and forgets the account's last limits; threads and their history are kept.

**Models.** The account's own, read from a session's `model` option on connect in a scratch session, each model chosen in turn to read its thinking levels, then that session's files removed; never a list shipped with Sotto. A `thought_level` option's values are the model's effort levels in Sotto's order (ADR-0044), set with `session/set_config_option` before the prompt that needs them, as the model is. The menu groups the models by **model maker** (Google, Anthropic, OpenAI), as Cursor's does (ADR-0128), and the model `agy` starts on leads.

**Permissions.** T3's four modes. **Auto** runs `agy`'s own Auto mode, offered only where the account's sessions offer it, and leaves every request `agy` still raises to the user. `agy` refuses an edit-only or run-everything session mode, so **Ask for approval**, **Allow edits** and **Full access** run `agy`'s `default` mode and Sotto answers by the thread's mode, as T3 does: on Allow edits, a request whose tool is an edit, delete or move is allowed once; on Full access, every permission request is allowed once. Ask for approval leaves all of them to the user. A mode change reaches `agy` at once, mid-turn included, so leaving Auto takes `agy`'s own approvals away at once; if `agy` will not take it, the turn is stopped. A request already waiting is answered when the new mode would answer it. Sotto answers allow once or reject only, never allow always, which would save a rule in Sotto's folder for every later thread. A request whose tool call ID starts `interaction_` is `agy`'s own question and is a question card answered with the chosen option, never an approval, on every mode. Watcher's thread never has a request answered for it.

**Threads.** Replies, reasoning, commands, file changes, reads, tools, plans and `agy`'s subagent calls as activity; images; skills and commands as `/name` from `available_commands_update`; stopping. A thread resumes after a restart with `session/resume`, which replays nothing, so no earlier tool call shows or runs again, and its history is Sotto's event store's (ADR-0016). A message sent while a turn works is steered in as a new `session/prompt` into the running session, as T3 does on 1.5, and the turn ends with the answer to its newest prompt. Not offered: compaction, and rewinding; Fork from here starts a new thread from a handover, as for Cursor.

**Watcher and short text.** Watcher runs on Antigravity, its instructions in the session's `_meta.antigravity.systemPrompt.append`, which `agy` advertises, never in the user's words; a client that does not advertise it is refused for Watcher in words. Short text (ADR-0026) is one prompt in a session of its own in the thread's folder, with no tool servers, on the thread's model at its least effort; a request is cancelled and a tool call stops the call, which then writes nothing, and the side session's files are removed.

**Usage.** Token counts are read the way T3 reads them, from `agy`'s conversation files in Sotto's folder and in the user's own `~/.gemini/antigravity*` and `~/.config/antigravity` folders, keeping only counts, dates, model names and app names, as Usage keeps Claude Code's and Codex's. The account's limits are read from `daily-cloudcode-pa.googleapis.com` and `cloudcode-pa.googleapis.com` with `agy`'s own sign-in token from Sotto's folder; an older `acp_token.json` is renewed at `oauth2.googleapis.com` as T3 renews it. The token stays in main and is never logged. Limits show as Gemini 5-hour and weekly windows and a shared Claude and GPT window. A Gemini Enterprise sign-in kept only in the system keyring is not read.

**Hosts and phones.** A paired host offers Antigravity (`provider-antigravity`), runs the `agy` installed there in a folder of its own, and signs a Google account in from this computer. Sotto's own download runs on this computer only in this version. The iPhone and Android clients name Antigravity, show its models and open threads on it.

## Consequences

- Sotto answers some of `agy`'s permission requests on the user's behalf: a thread's mode, chosen by the user for that thread, is the authority, recorded with the thread, as T3 treats it. ADR-0004's amendment says so.
- Sotto holds a second key the user chose, the user's own Google one, on this computer only.
- Sotto contacts Google's download and limits hosts for things the user asked for: Install, Update and the hourly update check, and Usage. Usage reads limits only for a Google sign-in, as T3 does.
- Not yet matched from T3: Sotto's own download on a paired host, per-turn token counts from each prompt's answer (Usage reads them from `agy`'s conversation files instead), Gemini Enterprise on a host, reading child work from `agy`'s `brain` folder, placing edit snippets on lines, and reading a failed turn from the conversation file's last step. Each is a follow-up.
- Verified with a fake `agy` through the adapter contract; the live check on the laptop is in [the verification note](../verification/2026-11-20-antigravity-provider.md).
