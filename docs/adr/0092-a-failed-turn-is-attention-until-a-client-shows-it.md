# A failed turn is attention until a client shows it

Accepted October 19, 2026. A thread whose last turn failed said **Needs attention** in amber in the sidebar, and nothing cleared it but a later turn that finished. Zach reported that nothing let him acknowledge or clear it, and that the pane often did not say why the turn had failed: the banner showed the provider's latest error, which may belong to another thread, and older failed threads had none. He decided the behaviour on October 19, 2026, from the prototype `docs/prototypes/needs-attention-clear-prototype.html`, variant A. This records that decision. It extends ADR-0046, which made the host's coordinator the owner of what clients have seen, and changes no part of it.

## Decision

**Opening a thread counts as seeing its failure.** A thread whose status is `error` and which asks nothing, a failed thread, says **Needs attention** until a client shows it. After that its row reads **Done**: no amber, no dot. What a client shows is what it observes, exactly as for **Finished unread** (ADR-0046): the desktop window's panes and pinned Tools thread while the window has the focus, and the thread a paired iPhone has open. A thread that fails while a client shows it is seen at once.

**The host's coordinator owns the record.** `FailuresSeen` (`src/main/agents/failuresSeen.ts`) sits beside `FinishedUnread` and hears every `showThreads` call. It names each failure itself, with a new ID, when it first sees a thread in error, or in error on a different failed turn than before, and keeps the provider's failed turn with it once one is known. A failure first seen without a turn, as a resume that fails, keeps its name when history later names the turn, unless that turn's record says it started after the failure was named: then a later turn failed, and that is a new failure. The failure ends once the thread runs or rests again with its provider connected, so the next failure is news. A provider or host that disconnects says nothing new about the thread, so its failure stands. Two failures that leave no trace between them, neither a snapshot out of error nor a turn ID, read as one, since nothing the host is told can tell them apart. The record saves the seen marks in `agents.json` as `failuresSeen`: the thread ID, the failure's name, its turn ID and when it was named, nothing the thread said. A thread still listed keeps its mark however many there are; the limit of 200, oldest first, bounds only marks of threads gone from the list. Every thread in error is published with `failureId`, the failure's name, and `failureReason`, its failed turn's recorded reason when there is one; a seen one also carries `failureSeen: true`. The fields are add-only on protocol v1.

**A desktop shows a remote host's threads only while its window has the focus.** ADR-0046 kept that rule on this computer alone: a remote host counted every thread a desktop observed as shown, so a failure in a pane of a desktop behind another app was seen there, and a finish read. The desktop's router now hears the window's focus with this computer's host service, and tells each remote host that lists `failure-seen` with the threads the window observes there: an `observe` carrying `shown: false` while the window is behind another app, minimised or in the tray, and one without it once the window is back. The host's socket server keeps the answer per client and tells its host service which observed threads are shown (`shownThreadIds` on `observe-threads`, which a paired client cannot send). The threads stay observed, so their history keeps streaming. A phone, which never sends the field, shows what it has open as before. A host from before this would refuse the field, so it is never sent one and counts a desktop's panes as shown, as it always did; a desktop from before this sends none, with the same result.

**Dismiss all marks every failed thread seen at once.** Under the sidebar's search, a line reads **N need attention** with **Dismiss all** beside it while at least one failed thread is unseen. Its accessible name is "Dismiss Needs attention on N threads". One press sends `dismiss-failures` naming each thread it counted with the `failureId` its row showed. Each thread's own host marks it seen, as if a client had shown it, only while it still stands in that failure: a turn that fails between the press and the command reaching the host stays news. The desktop's router splits the entries by host. A remote host takes the command when it lists the `failure-seen` host feature, and it is on the remote allow-list. The command answers no request and grants nothing, so pairing is enough. The line has no live region: it announces nothing, as the rows do not. Once the hosts accept the command and the line goes, the search field just above takes the focus; when a host keeps its threads as they were, the focus stays on Dismiss all.

**Requests are never dismissed or counted.** A thread waiting on a permission or a question says **Needs your approval** or **Needs your answer**, whatever its status. Neither showing it nor Dismiss all marks it seen, and the count leaves it out. The user answers every permission (ADR-0004).

**The open pane says why the turn failed, once, for as long as the thread is failed.** The reason is the failed turn's own, the `error` on its turn record (`markTurn`, `markTurnActivity`), never the provider's latest error. When the transcript's failed turn line carries it, that line is the explanation. When it does not, a quiet notice above the composer says **The last turn failed.** or **{Provider} reported an error on this thread.**, then the reason the host published with the failure if there is one, and "Nothing in the transcript was lost. Send a message to try again." otherwise. A thread that could not be resumed records no turn: when the provider's error is its wording for that, which each adapter reads from `src/shared/threadFailures.ts`, the notice gives those words as the reason. While the open thread's failure is explained either way, the pane's error banner stands down when it is about a thread failing: any thread's published failure reason, or a provider's wording for a thread it could not resume. A banner about the provider itself, such as a disconnect, a sign-in or a missing client, always shows. A provider that words a resume failure in its own reason, as Devin can, is not recognised, and its banner shows beside the notice. A thread whose provider sent a request Sotto could not show already says why in its own alert, so it gets no notice. Seen or not, the explanation stays while the thread's last turn is failed.

**Other readers.** The folder and Settled dots count rows that need you, so a seen failure leaves them. A delegated thread's seen failure no longer rolls up to the row it is reached from (ADR-0081), and its Agents roster entry follows the same rule. Watcher's overview (ADR-0073) is unchanged: it groups threads by their last turn's outcome, says **Last turn failed** rather than Needs attention, and Watcher's own tools read the same grouping. The composer's send gate is unchanged.

## Consequences

- Seen is per host, not per device, as for Finished unread: opening a failed thread on the iPhone makes it Done on the desktop. The iPhone and Android clients still say **Turn failed** for any failed thread. They ignore `failureSeen` and never send `dismiss-failures`.
- A desktop that predates this ignores the field and the feature, and its rows say Needs attention as before. An updated desktop connected to a host that predates it sends that host nothing for Dismiss all. Its message says the host runs an older Sotto, that its threads still say Needs attention, and to update it in Settings > Hosts. A host that is out of reach is told the same way, with "Connect to it again".
- Most failures from before this change have no reason on their turn record, and some have no turn record at all. They get the notice's plain words rather than a reason. Recording a reason for every failure path in every adapter is left for later.
- A mark for a thread that is later forgotten stays in `agents.json` until newer marks push it past the limit. It names nothing but the thread and its turn.
