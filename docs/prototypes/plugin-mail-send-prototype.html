Sending mail from a thread · prototype for slice 9 (#2494) · nothing here sends anything

Already decided in ADR-0205: sending an email always asks, with no switch that turns the asking off, a mail grant never covers a send, and Watcher cannot send (it changes nothing through a plugin). The adapter that sends is built and tested against a made-up server. What is left is yours: what the card shows and says, what a thread may send, and how many people one message may go to.

1 · The card that asks before each send

It appears in the thread, where a GitHub comment's card does, and nothing is sent before its first button. It lapses after five minutes like every card, and a lapse sends nothing. Use the bar below to switch between A and B.

Gmail
ann@example.com, ben@example.org and 2 more

      

    

    
The whole text is shown, in a box that scrolls when it is long. A Bcc is shown to you and is in no line of the message.

2 · What a thread may send



  
A · A new plain-text message
  • To, Cc and Bcc, a subject and text.
  • No HTML and no files.
  • A reply is a new message with “Re:” in its subject. Gmail usually groups it with the conversation by subject.

  
B · A, and replies that stay in the conversation
  • The thread names a message it has read, and the reply carries that message’s own name, so every mail program groups it.
  • Sotto reads two header lines of that message to do it, so the thread needs to be allowed to read the account.
  • A later part, after A.

  
C · B, and files from the project
  • The card lists each file by name and size.
  • A file leaves the computer for everyone on the message, and cannot be taken back.
  • A later part, after B.





3 · How many people one message may go to


To, Cc and Bcc together. Gmail itself takes up to 100 for mail sent this way, and 500 messages a day. Every message still asks you, so this is a cap on one card, not on a day.



4 · What the read card and Gmail’s row say once sending exists


Both say today that a thread “cannot send, move or delete mail”. Once a thread can ask to send, that is no longer the whole truth. Proposed, with the changed words marked:



  

    
The card a first read waits on (third line)

    
Today: It cannot send, move or delete mail. Every other thread asks for itself.

    
Proposed: This does not let it send: each email it wants to send asks you first. It cannot move or delete mail. Every other thread asks for itself.

  

  

    
Gmail’s row in Settings › Plugins

    
Today: A thread cannot send, move or delete mail, and a message it reads stays unread for you.

    
Proposed: A thread asks you before each email it sends, and shows you the whole email first. It cannot move or delete mail, and a message it reads stays unread for you.
