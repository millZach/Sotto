Why does the composer lose its draft when I switch threads?

The draft lives in ThreadDraftStore, keyed by thread ID, so switching threads should keep it. The loss comes from the editor: it mounts with key={threadId}, and its first effect writes its empty initial text back to the store before the saved draft has been read.

There are two ways to fix it:

  • Read the saved draft synchronously when the editor mounts, so the first render already has it.
  • Skip the write-back until the editor has seen one user edit.

The first is smaller and keeps one source of truth. The second leaves a window where a dictation landing during mount could still be dropped, because the dictation path writes through the same effect.
