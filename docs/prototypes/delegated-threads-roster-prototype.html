Delegated threads · mock-up

Variants

A · Own section. A “Delegated threads” group above “Muse’s agents”, each delegated thread a roomy roster row with its provider’s mark and an Open as thread button.

B · Mixed by time. One list, newest start first; a delegated thread is told apart by its provider’s mark and a “Thread” marker, and keeps the same button.

C · Split and cards. A Threads | Agents switch at the top of the tab. Delegated threads are cards, the second level listed inside its first-level card.

When a delegated thread is opened

The parent’s row stays highlighted. The pane is showing one of its threads, so the sidebar keeps your place; no row is added.

Tools stays on the parent’s roster, pinned. The header reads the parent’s name with the pin pressed, and the opened row says “In the pane”, so the next delegated thread is one press away. Unpin and Tools follows the pane as it does today. Delegated by, or the parent’s row, returns the pane.

When one waits on you

The parent’s sidebar row reads Needs your approval (or Needs your answer). The roster row is edged in the attention colour, says the same, and its button reads Open to answer: a press opens the thread where the request is answered. Nothing is answered from the roster.

Keys

← → change variant (not while a field, tab or switch has focus). Esc closes an open row’s details, then this panel. Links: ?variant=A|B|C&scenario=needs&theme=light.
