# Sotto memory-first spec review

The product thesis is credible, but v0.1 is not ready to serve as an engineering commitment. It combines a useful memory experiment with a provider-host rebuild and an oversized research program. The cited projects and paper exist, but local capability, benchmark portability, privacy, and voice responsiveness need tighter definitions. Keep the existing T3 thread layer, prove explicit memory and a small reviewed import first, and defer autonomous learning and competing backends until measured failures justify them.

## Founder decisions after review (2026-09-10)

- The product name is Sotto and the wake phrase is "Hey Sotto". The spec's "Soto" spelling is a typo, corrected in the extracted copy.
- Threads are a core Sotto function and must not depend on T3 Code. Proposal 2 below (keep T3 as the thread layer) is rejected. Sotto builds its own thread layer on the provider protocols the repo already speaks for reasoning: Codex App Server (`subscriptionCodex.ts`), Claude stream-json (`subscriptionClaude.ts`), and Grok ACP stdio (`subscriptionGrok.ts`). Sequence: define Sotto's own thread interface and IDs first, keep T3 as the first implementation behind that interface while explicit memory (M1) is proven, then replace it with native Codex, Claude and Grok adapters. Memory binds to Sotto thread IDs, never T3 IDs, so T3 can be removed without touching memory. The thread persistence, permission and question routing, recovery, and takeover behaviour T3 provided are rebuilt in Sotto as part of the native adapters.
- Memory stays on the user's machine. The only "consent" moment is choosing which model reads imported history during extraction, because a cloud extractor sends one provider's transcripts to another provider. A local extractor needs no consent step.

### Local retrieval and packaging

Transformers.js can run local ONNX embedding and cross-encoder models. Candidate assets: [BGE-small-en-v1.5](https://huggingface.co/Xenova/bge-small-en-v1.5), 384 dimensions, approximately [34 MB quantized weights](https://huggingface.co/Xenova/bge-small-en-v1.5/tree/main/onnx); [MS-MARCO MiniLM-L6 reranker](https://huggingface.co/Xenova/ms-marco-MiniLM-L-6-v2), approximately [23 MB](https://huggingface.co/Xenova/ms-marco-MiniLM-L-6-v2/tree/main/onnx), plus tokenizers/runtime. Configure [local model/WASM paths and remote loading off](https://huggingface.co/docs/transformers.js/main/custom_usage). Benchmark with pinned 4.2.0 before promising latency. Sherpa's [documented embeddings](https://k2-fsa.github.io/sherpa/onnx/c-api/html/index.html) are speaker embeddings, not a text-memory retriever.

[SQLite FTS5](https://www.sqlite.org/fts5.html) plus [sqlite-vec](https://alexgarcia.xyz/sqlite-vec/js.html) works with better-sqlite3 or node:sqlite. Prefer an M0 probe of built-in [node:sqlite](https://nodejs.org/api/sqlite.html) plus FTS, initially scoring small vector sets in a worker. Actual Electron-build availability remains unverified.

[notes.md](../../notes.md) requires production dependencies exactly `['zod']`. Bundling JavaScript cannot absorb native binaries. better-sqlite3 needs an [Electron-compatible ABI build](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules); sqlite-vec needs platform libraries. Explicitly include/unpack these through [electron-builder resources](https://www.electron.build/v26/docs/contents/), bundle loaders, and verify installed Windows x64/macOS arm64 paths and notices. Adding ordinary production dependencies violates this repo's constraint.

## C. Proposed changes, ranked by impact

1. **Must change — Reduce v0 to a memory experiment.** Three execution integrations, seven memory classes, autonomous consolidation and eight baselines exceed a credible solo-founder first release. Replace M0–M2 with the cut below; defer automatic inferred preferences, graph services, Git reflection and broad adapters.

   | Milestone | Deliverable and exit check |
   |---|---|
   | M0 | Reuse current voice/T3 flow; instrument a no-memory run; prove packaged persistence; label 20–30 cases for scope, correction, exceptions and authority. |
   | M1 | Explicit project/global preferences, minimal goal state, SQLite/FTS, provenance, edit/delete inspector. Demonstrate a saved preference changing behavior after restart without changing permissions. |
   | M2 | One opt-in Claude importer with reviewed candidates; demonstrate imported context in a Codex execution thread through T3, subject to host capability verification. Run a focused daily-use trial; defer Grok import and autonomous learning. |

2. **Must change — Keep T3 as the thread layer.** Sotto owns goals/memory; T3 owns thread lifecycle and provider execution integration. This is compatible with the thesis. Extend `AgentHost` behind a stable internal boundary; replacing it discards recovery, permissions and manual takeover. Add a direct adapter only for a demonstrated host gap. Distinguish host thread IDs from native provider session IDs and preserve one controlling writer.

3. **Must change — Make authority a separate enforced model.** Section 6.1's “temporary exceptions stay scoped unless repeated” lets repetition expand scope; repetition must never grant authority. Imported explicit instructions and agent-confirmed claims are evidence, not current grants. Separate source origin from speaker/evidence class; require policy records with action, resource, scope, expiry and revocation. Retrieved workflows cannot approve spending, publishing, destructive actions or relaxed verification boundaries. Treat transcript/tool text as untrusted and check policy at dispatch.

4. **Must change — Specify cloud consent and deletion.** Permission to inspect local history is not consent to upload it. Before extraction, show provider, selected projects/date range, data categories, redaction, cost estimate and cancellation. Apply that choice to later retrieval, reasoning, speech and telemetry too. Reconcile permanent import with existing “Keep local history” behavior. Deletion must purge archive copies, indexes, projections, Git history and logs, and prevent re-import resurrection; local deletion cannot retract prior provider transmissions.

5. **Must change — Establish one memory source of truth.** SQLite owns accepted memory; Markdown is a generated projection with revision IDs, atomic replacement and regeneration. Use transactional revision/outbox processing for indexes/files. Human edits enter a validated change path. Preserve original bytes/hash and versioned normalization separately: section 5's normalized “raw” archive is lossy. Source records prove what was recorded, not that an agent's claimed success happened.

6. **Must change — Define voice budgets and interruption semantics.** [July 28 measurements](../perf/2026-07-28-asr-model-benchmark.md) give 185/465/1781 ms Moonshine inference for 2/4.4/16.6-second clips; [July 20](../perf/2026-07-20-dictation-latency.md) is faster and explicitly machine-sensitive. Current `voiceCapture.ts` adds 650 ms endpoint silence; `voiceSession.ts` suppresses capture during TTS plus 450 ms afterward. Proposed warm short-utterance gates: useful transcript/status feedback p50 ≤1.2 s/p95 ≤2 s from acoustic end; retrieval p95 ≤100 ms; button/hotkey stop ≤150 ms. Measure intent, delegation and first audio separately, including cold/loaded cases. These are targets, not achieved results. Spoken barge-in needs new work. [notes.md](../../notes.md)'s remote 48/232 ms results do not describe local agent voice.

7. **Should change — Trim eight baselines to four controlled comparisons.** Start with recent-only, bounded summary, raw-history RAG, and one structured explicit-memory candidate. Hold reader, model, budget and questions fixed; add one challenger only when it targets observed failures. Separate extraction/retrieval/action scores. Reserve held-out cases, manually adjudicate ambiguous labels, record labeling hours, and require zero observed authority/project-leakage failures without claiming statistical safety from 30 cases.

8. **Should change — Budget imports and distribution before bulk processing.** Estimate extraction, retries, embeddings and consolidation separately; cache by content hash/model/prompt version, cap concurrency/spend, checkpoint and pause during voice. Specify downloads, checksums, disk/RAM limits, cancellation and model licenses; current local Supertonic alone is a 263 MB download. Include native packaging in M0, not release cleanup.

9. **Should change — Specify importer and session recovery contracts.** Handle partial JSONL lines, rotation/compaction, duplicate forks/subagents, unknown event types, unavailable source files and version migrations. Preserve Windows drive/UNC/case distinctions, spaces, Unicode, junctions and encoded-path collisions; map worktrees to explicit repository identities. Test restart, lost acknowledgements, cancellation and concurrent external sessions without replaying actions.

10. **Consider — Borrow formats before adopting runtimes.** Trial Trajectory normalization and Letta-style progressive views; defer full Letta, Mem0 or Graphiti integration until controlled results justify their operational cost. Keep Sotto's existing name/branding consistent in the revised spec.
