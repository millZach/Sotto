## Local challengers

**Kokoro v1.0 is the most straightforward first challenger.** Its publisher lists 82M parameters, Apache-2.0 weights, eight languages and 54 voices; examples output 24 kHz audio. [Model card](https://huggingface.co/hexgrad/Kokoro-82M) The author's JavaScript package documents WASM/WebGPU and Node CPU, quantization choices, and a text-splitter stream yielding individual audio results. This establishes a JavaScript integration route, not measured Electron TTFA or verified within-sentence incremental PCM. [Kokoro.js](https://github.com/hexgrad/kokoro/tree/main/kokoro.js)

**Supertonic 3 remains testable, with an explicit maintenance limitation.** The official archive confirms 99M parameters, 31 languages, 44.1 kHz output, and examples for Node/browser/native runtimes. The repo was archived September 9, 2026; its notice says development and support ended. It now directs downloads to the `supertone-oss-archive` Hugging Face namespace. Pin archive revisions before building an adapter; do not silently repoint the incumbent. The archive is evidence of continued downloadable code/models, not continuing hosted demo support. [Official archive](https://github.com/supertone-oss-archive/supertonic)

**Piper is a reasonable reserve.** The maintained project advertises a C/C++ API, embeds espeak-ng for phonemization, and identifies GPL-3.0 licensing. [Piper repository](https://github.com/OHF-Voice/piper1-gpl) The detailed C/C++ page failed to load during this check, so chunk granularity and cancellation guarantees were not verified here. Do not carry over a promise of sub-300 ms Electron performance or turnkey native packaging. Check the chosen voice's own model card before redistribution.

Pocket TTS, Kitten and Chatterbox details were not revalidated in this bounded check; yesterday's proposal is not new evidence for their runtime performance.

Deepgram explicitly requires stopping local playback immediately before sending server `Interrupt`; its optional playback offset is session-relative. Server spoken-text feedback depends on that offset. This distinction should govern every provider's interruption experiment: canceling synthesis and silencing the speaker are separate events. ## Suggested order

1. Establish the three current app controls with frozen 24 replies, exact voices/settings, raw audio and timings. Record first byte, first PCM, playback start and complete synthesis separately; unavailable events remain unavailable.
2. Screen Kokoro locally and one hosted voice from each documented hosted challenger. Add Supertonic 3 as an incumbent-family comparison if maintaining an archived runtime is acceptable. Defer Piper's native packaging until a clear need emerges.
3. Compare current whole-WAV playback and streaming as separate configurations. Use identical text submission boundaries and explicit buffering. A streaming provider's published inference figure is not comparable to full-response app latency.
4. Run blind listening and calibrated output capture before any selection. No source reviewed proves better technical pronunciation, warm audible p95 at or below 300 ms on both target machines, or interrupt-to-silence p95 at or below 100 ms in Sotto. The prior proposal's publisher timings and leaderboard scores remain screening evidence, not acceptance results.

Unverified: account-specific access and credits, actual download integrity/size for new adapters, Electron compatibility, local hardware latency, audible device drain, listener preference, and full license/dependency redistribution review. No replacement recommendation is justified before those measurements.
