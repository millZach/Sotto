# MAI-Transcribe-2: research brief and Sotto benchmark plan

Checked 2026-09-10. All external links below are primary sources checked on that date. Research only; no transcription API calls, benchmark runs, or application changes were made.

MAI-Transcribe-2 is Microsoft AI's speech-to-text model, released September 3, 2026, succeeding MAI-Transcribe-1.5. It is worth a small benchmark, particularly for dictionary-assisted proper nouns, but does not yet justify replacing Parakeet. Microsoft distributes it through Foundry/Azure Speech, MAI Playground, and OpenRouter; no public weights or supported self-hosted package were located. Azure marks it public preview without an SLA. [Launch](https://microsoft.ai/news/mai-transcribe-2-is-the-fastest-most-accurate-and-cheapest-speech-recognition-model-in-the-world/), [model card](https://microsoft.ai/pdf/MAI-Transcribe-2-Model-Card.pdf), [service documentation](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe).

Sotto's [July benchmark](../perf/2026-07-28-asr-model-benchmark.md), [latency investigation](../perf/2026-07-20-dictation-latency.md), and [August 27 notes](../../notes.md) establish the bar: 2–4-second push-to-talk utterances. Moonshine completed 2.0/4.4-second clips in 185/465 ms, with 6.0% mean normalized WER. Remote Parakeet **v3** recorded 48 ms for 2 seconds and 232 ms for 16.6 seconds, **including** the LAN/Tailscale round trip, with 8.2% WER. These are historical ASR timings, not current stop-to-paste measurements. Planned production is on-device Parakeet v2, v3 for multilingual, and optional LAN ASR; the inspected local harness/runtime still cover Moonshine/Whisper, so on-device Parakeet needs a fresh baseline.

The [fixtures](../../scripts/asr-bench/fixtures/ground-truth.json) contain seven Windows TTS recordings: tiny 2.0s, short 4.4s, long 16.6s, technical 16.8s, numbers 14.6s, propernoun 11.9s, homophone 10.3s; total 76.6s. WAVs are 16-kHz mono PCM16; hosted tests prefer checked-in 32-kbps MP3s. [wer.mjs](../../scripts/asr-bench/wer.mjs) computes word-level Levenshtein errors/reference words after lowercasing, punctuation/number/time/currency normalization and compound reconciliation. Mean WER weights fixtures equally. Caveats: normalization removes every “and”; alphanumeric identifiers still produce formatting penalties; `missedWords` is a set diagnostic, not aligned proper-noun WER. Freeze this scorer for historical comparability and separately audit identifiers.

Microsoft claims FLEURS WER **5.2% across 60 languages**, or **3.4% across its top 25**. Its model-card chart reports 5.2% versus Whisper large v3's 23.5% with inferred language; Parakeet is absent. These are vendor evaluations, not Sotto results. [FLEURS chart, page 2](https://microsoft.ai/pdf/MAI-Transcribe-2-Model-Card.pdf). No MAI-specific CommonVoice, LibriSpeech, or AMI scores were located. [Microsoft performance](https://microsoft.ai/models/mai-transcribe-2/), [launch](https://microsoft.ai/news/mai-transcribe-2-is-the-fastest-most-accurate-and-cheapest-speech-recognition-model-in-the-world/).

MAI supports 60 languages, including English, Spanish, German, French, Mandarin, Cantonese, Arabic, Hindi, Japanese and Korean; the [complete language matrix](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe#language-support) also documents automatic identification and code switching. Diarization and word/segment timestamps are available. `phraseList.phrases` supplies vocabulary hints, not guaranteed substitutions; arbitrary custom prompts are unsupported. Use `enhancedMode.modelOptions.transcribeStyle:"verbatim"` for false starts/self-corrections, with timestamps and diarization off for baseline timing. [Feature matrix](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/llm-speech).

Microsoft's [one audio hour in ten seconds](https://microsoft.ai/models/mai-transcribe-2/) is long-form inference throughput. AA reports 307.3× median speed on ten-minute files, including network time. [AA methodology](https://artificialanalysis.ai/methodology/speech-to-text). Neither predicts a two-second request. [OpenRouter](https://openrouter.ai/microsoft/mai-transcribe-2) currently shows roughly 0.5s aggregate provider p50, without clip-length breakdown. No Microsoft short-clip TTFT, full-clip p50/p95, or MAI-specific p95 was found. REST returns a completed transcript, with no documented partials or separate MAI asynchronous Batch-job interface. The MAI guide mentions Voice Live input integration; [Voice Live uses WebSockets](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live), but MAI-specific partial-event behavior and latency remain unverified. Do not promise streaming dictation.

Azure's [Speech privacy policy](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/speech-service/speech-to-text/data-privacy-security) says fast transcription retains neither customer input nor output; regional processing is documented above. No MAI-specific retention exception was found. OpenRouter adds another processor: its [audio policy](https://openrouter.ai/privacy/) permits retention exceptions for security, abuse, billing and legal obligations. Audio and dictionary terms leave the machine: this can only be an explicit opt-in cloud tier, like earlier OpenRouter candidates, with local fallback.

The current [remote path](../../src/main/asr/remoteAsrService.ts) sends PCM16 WAV through renderer IPC to Electron main, then unauthenticated multipart `file`/`model=whisper-1` to `/v1/audio/transcriptions`, parsing `text`. It probes `/health`; the renderer applies a 4s timeout and 30s failure cooldown. Azure needs a small main-process adapter and credential/probe handling.

A future `bench-mai.mjs` should reuse fixture loading/scoring and serial requests, replacing [bench-asr.mjs](../../scripts/asr-bench/bench-asr.mjs)'s base64 `/chat/completions`, `choices[0].message.content`, and `/generation` telemetry:

| Route | Benchmark request and parsing |
|---|---|
| Direct Azure, preferred for latency/privacy | Environment-provided endpoint/key; `definition={"enhancedMode":{"enabled":true,"model":"MAI-Transcribe-2","modelOptions":{"transcribeStyle":"verbatim"}}}`; optionally add top-level `phraseList:{"phrases":[...]}`. Read mono `combinedPhrases[0].text`; duration metadata is audio length, not inference time. |
| OpenRouter, easiest compatibility check | Bearer `OPENROUTER_API_KEY`; POST `https://openrouter.ai/api/v1/audio/transcriptions`, multipart `file` and `model=microsoft/mai-transcribe-2`, parse `text`. JSON `input_audio:{data,format}` supports dictionary options under `provider.options.azure.phraseList.phrases`; read `usage.seconds/cost`. |

OpenRouter explicitly supports [OpenAI-compatible multipart](https://openrouter.ai/docs/guides/overview/multimodal/stt); Sotto still needs configurable auth/model and a replacement health probe. It is not a URL-only switch. No MAI-specific OpenRouter RPM is published; paid requests remain subject to upstream capacity and [429/backoff rules](https://openrouter.ai/docs/api/reference/limits). Let Node FormData generate the multipart boundary. Keep keys out of results.

Reuse [bench-local](../../scripts/asr-bench/bench-local.mjs) for Moonshine, [bench-forge](../../scripts/asr-bench/bench-forge.mjs) for LAN, and [bench-hybrid](../../scripts/asr-bench/bench-hybrid.mjs) for a separately reported, identical polish/dictionary pass. Record actual model identity from server configuration/`/health`, weights, precision, runtime, hardware and region: Forge report titles alone do not identify weights. Both hosted harnesses currently stop timing before JSON parsing; the new measurement must end after complete transcript parsing.

| Benchmark step | Protocol |
|---|---|
| Comparison set | Parakeet v2 on-device; v2 and v3 on the same LAN GPU; MAI direct Azure; existing Moonshine-base q8 WASM/4-thread baseline. Screen OpenRouter separately, never pool its latency with Azure. |
| Audio | Preserve seven fixtures. Add 30 human recordings: 24 at 2–4s, including fixed 3s clips, and six around 16s; cover coding vocabulary (`remoteAsrService`, TypeScript), model names (Parakeet TDT 0.6B v2, MAI-Transcribe-2, ONNX), repo names (Sotto, millZach/Sotto), 100+ annotated proper-noun tokens, and “v2—no, v3” corrections. Include ordinary speech and noisy microphones, plus silence controls; add ten Spanish/German/code-switching clips for v3/MAI only. Freeze verbatim references before testing; use separate corrected references for polish. |
| Runs | Two excluded warmups, then 30 serial runs/fixture/model/configuration, split across three sessions with randomized model order. Separately record five cold-start trials. Extend the 3s test to 100 runs if near the adoption boundary; 30-run p95 is exploratory. Baseline without vocabulary; repeat MAI with one frozen dictionary including distractors. Repetitions measure variability, not new accuracy samples. |
| Metrics | Every-run/per-fixture normalized WER and macro mean; proper-noun WER = aligned edits within annotated name spans/reference name tokens, plus exact-name accuracy. Report silence false positives separately from speech WER. Report p50/p95 full-result latency for 2s, 3s and 16s separately, cold starts, failures/retries, and stop-to-paste including encoding, IPC, upload, polish and delivery. Bootstrap accuracy differences by unique recording. Save every transcript, configuration and timing for rescoring. |
| Transport/cost | Matched WAV first; separate MP3 ablation including encoding cost. Keep connections warm, log network conditions and retry time. Cost/1,000 = 1,000 × mean billable seconds × $0.10/3,600: 2s dictations ≈ $0.056; 3s ≈ $0.083; 16s ≈ $0.444, excluding polish/fees. Local/LAN have no API charge; report power/hardware separately. Cap initial cloud ASR spend at $2. |
| Adoption gate | Require ≥25% relative and ≥3 percentage-point proper-noun WER reduction versus the strongest Parakeet result, with no mean-WER regression and a paired 95% confidence interval excluding zero. For 3s clips, p50 and p95 stop-to-paste must not exceed the Parakeet route being replaced, with identical polish settings. Require ≥99% successful requests and no hallucinated speech on silence controls. Confirm in an Electron push-to-talk trial; timeouts/fallback failures cannot be hidden. |

First screen tiny, short and propernoun five times each on direct Azure and OpenRouter; then continue the full matrix only if short-clip latency is competitive. Keep Parakeet as the planned standard; even a winning MAI result warrants only an experimental opt-in tier until preview reliability and privacy requirements are satisfied.
