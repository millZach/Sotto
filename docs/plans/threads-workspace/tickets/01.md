## What to build

Typing in any thread gives immediate, truthful delivery feedback and each thread keeps its own unsent draft.

## Acceptance criteria

- [ ] Enter sends; Shift+Enter inserts a newline; IME composition and skill-menu selection do not accidentally send.
- [ ] Each thread independently restores its text and attachments after navigation and restart, including legacy draft migration without changing ownership.
- [ ] Show queued/submitting/accepted/failed or uncertain delivery distinctly; a lost acknowledgement is reconciled without automatic duplicate submission.
- [ ] Measure local send feedback separately from provider latency; target visible acknowledgement within 100 ms on the agreed Windows fixture and document actual measurements. Preserve disconnected-provider and managed-thread behavior.

## Blocked by

None — can start immediately on the agreed integration baseline.

## Shared constraints

Build on the existing native-provider foundation and the approved Threads workspace specification. Preserve Sotto thread IDs, native provider bindings, scoped memory, explicit management authority and uncertain-delivery reconciliation. A completed slice must include its own focused tests and rendered verification when it changes UI.
