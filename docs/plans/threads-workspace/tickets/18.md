## What to build

Push a branch, create/open its pull request and follow review/check status inside Sotto.

## Acceptance criteria

- [ ] Use the configured repository identity and existing authentication; show target remote/base branch and editable PR title/body before the user's action.
- [ ] Create or open the existing PR without duplicates; display actual review and check status with refresh and useful authentication/network errors.
- [ ] Open relevant PR links according to browser preference and associate the surface with the correct branch/worktree.
- [ ] Verify against a controlled repository or faithful API fixtures plus an authorized end-to-end smoke action; do not silently merge or publish merely from viewing a thread.
