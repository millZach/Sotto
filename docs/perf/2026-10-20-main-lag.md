# Main lagging with a few hundred threads - October 20, 2026

## Answer-draft saves

Issue #1230. The owner's profile of Owl 0.1.38-owl.20261020.1 put half of main's time in one minute under `RequestDraftService.commit`, reached from `save`. Each save of a question answer looked up the thread of every retired answer in the ledger, and for a thread on a remote host the router built every host's state afresh to find it (`DesktopHostRouter.shell()`: `visibleState`, `clientAgentState` and a copy of each remote host's shell). The owner's store held 256 retirements, 40 of them remote, so every save built the whole state about 40 times, and the count grew with every question answered.

What changed:

- The router answers for one remote thread from that host's view, read in place (`windowThread`). Only the thread's requests are copied for the caller, as they already were for this computer's own threads. A thread with no provider of its own takes the selected host's catalog and default from that host's view, as `shell()` would give them, without building anything.
- The receipt pass (`issueRequestDraftChecks`) reads each held answer's thread the same way rather than building every host's state.
- `preservesDormantThread` reads the host's view instead of copying its shell.
- Once the ledger has been classified, `commit` looks up a retired answer's owner only when looking it up could change what is saved: its thread is Watcher or held to Owl now, or the owner is still unclassified. `requestDraftWatcherOwnerIds` names those threads, on this computer and each remote host, by reading each thread's kind in place, and the store finds them in an index of the ledger. Owners with a draft are looked up on every commit as before, and a legacy file with no Watcher list is classified in full once.
- The ledger index is rebuilt from the saved ledger when it changes, so it holds nothing the ledger no longer names. `retirement()` reads it rather than scanning the ledger.
- A commit that keeps the ledger as it was checks only the rest of the record, rather than parsing and comparing every retirement again.

Counted by `tests/unit/main/requestDraftSaveCost.test.ts`, a real `DesktopHostRouter` with one remote host behind `requestDraftOwnerState`, saving an answer on a remote thread. Owner keys count every `requestDraftOwnerKey` the store and router work out.
