# OpenCode on hosts and phones: what was checked

October 17, 2026. Issue #1107, [ADR-0087](../adr/0087-opencode-is-a-thread-provider.md) and [ADR-0037](../adr/0037-a-hosts-providers-are-connected-and-signed-in-from-this-computer.md), both amended the same day. The sign-in is variant A of the [sign-in prototype](https://github.com/millZach/Sotto/blob/prototype/opencode-sign-in/docs/prototypes/opencode-sign-in-prototype.html), Zach's pick for #1104, driven against a host's own OpenCode.

## OpenCode 2.0.31 itself

Both checks used a scratch OpenCode 2.0.31 (`@opencode/cli`) with scratch HOME, USERPROFILE, APPDATA, LOCALAPPDATA and XDG folders. Zach's own OpenCode, its folders and its desktop app were not touched, no real credential was used, and no process was left running.

- **A headless host's folder.** `tests/integration/opencodeHostLive.test.ts` (live only: `SOTTO_OPENCODE_LIVE=1 SOTTO_OPENCODE_EXECUTABLE=...`) starts a headless host on an Owl version with that OpenCode in the scratch home's `~/.opencode/bin`, where the host looks first. OpenCode connected on the host, with its version and OpenCode Zen's models. Its database was at `<dataDirectory>/opencode/data/opencode/opencode.db`, the four folders `data`, `config`, `state` and `cache` were under `<dataDirectory>/opencode`, and neither `~/.local/share/opencode` nor `~/.config/opencode` was made in the home. Passed.
- **Browser sign-ins from another computer.** A scratch `opencode serve` listed its sign-ins and started each browser method once, then cancelled it. Every `auto` one without a code sent the browser back to OpenCode's own machine: DigitalOcean to `localhost:1456`, OpenAI's "Sign in with ChatGPT" to `127.0.0.1`, its legacy Codex browser sign-in to `localhost:1455`, and Poe to `127.0.0.1`. The device ones, xAI's SuperGrok and OpenAI's legacy Codex device code, gave a code and no address to come back to. So a browser on this computer can finish a device code or a pasted code for a host, and not the others; GitHub Copilot, GitLab, OpenCode Console and Snowflake ask a form first and were not started. On this machine with a scratch home, "Sign in with ChatGPT" started (200); #1104's 500 for it came with Zach's real profile folder passed through.

## The tests

Each failed before the change that makes it pass. Logs and the mutation script are in the run's notes (`.zstack/opencode-provider/t7-logs`, `t7-scripts`).

- `tests/integration/hostOpenCode.test.ts`. A stable host still holds OpenCode; an Owl host runs it. A client whose hello does not accept `provider-opencode` is sent no frame naming OpenCode, through its hello, its event pages and the shells pushed after OpenCode and Codex threads change. That client has an OpenCode thread's `detail`, `events` and select refused, while a client that accepts the feature reads all of it. Through `DesktopHosts`, forge's OpenCode is signed in from this computer: a key reaches the host's OpenCode once and is in no log on either side, no console line and no file either Sotto keeps. A device code's page opens in this computer's browser, its address comes back when the browser does not open, and the sign-in finishes. A pasted-code sign-in is cancelled on the host, and sign-out works. A ChatGPT-style sign-in that would return to the host is cancelled there and refused in words. Only the client that started a sign-in may read or cancel it. A stable host offers no OpenCode sign-in and the words say to update it. Against the code before this change: 5 of 6 red. Seven guards were then broken one at a time and each turned its test red: every peer taken to know OpenCode, the shell sent whole, the desktop logging the call, the host logging the call, the auto sign-in let through, another client's sign-in readable, and the window allowed to ask for a page.
- `tests/unit/host/providerPeers.test.ts`. A host's shell with OpenCode in its rows, models, projects, threads, drafts, settings, client updates and update line reads with no `opencode` in it, and still parses. Handovers and Watcher rows from OpenCode are dropped.
- `tests/integration/headlessHost.test.ts` and `socketHostContract.test.ts`. The host service contract runs with OpenCode, in process and in a child over the socket: 10 cases each, with the fixture's two skips. Its lost-acknowledgement case was red against the previous `opencode.ts`: the reaper stopped an unwatched thread's server while OpenCode might still take the prompt. A thread with an unconfirmed prompt is now busy for up to a minute.
- `tests/unit/renderer/hostOpenCode.test.tsx` (6), `tests/unit/main/hostsOpenCodeIpc.test.ts` (2) and `tests/unit/preload/hostOpenCodeBridge.test.ts` (3). The OpenCode tile, the block and the dialog naming forge. A key going through the host bridge, the external method being forge's, and an older host's words. Nothing of OpenCode on stable. A method that came back refused is not offered again. The IPC refuses an unreadable request and a `page` call without echoing a key. The preload bridge exists apart from the local host, and reads each answer strictly.
- `tests/unit/main/hostProviderJob.test.ts`: the provider job brief installs OpenCode 2 by its own channels, `~/.opencode/bin` first, never OpenCode 1.
- iPhone (`apps/ios`): `NewThreadsTests` and `ThreadAlertsTests` cover OpenCode's name, `createProject` taking `opencode`, a model's source, and a shell with an unknown provider still decoding. Android (`apps/android`): the same in `NewThreadsTests`, and the hello's `provider-opencode` in `StreamingTests`. Android draws OpenCode's mark from `core/ProviderMarks.kt`, the desktop's frame with its inner square at 35%, in the thread header and each thread row's place line, where the iPhone draws it; `ProviderMarksTests` checks the shapes, and `tests/unit/shared/phoneProviderMarks.test.ts`, which CI runs, checks Android's source against the desktop's path and that both screens draw it. Neither phone's own tests could run here: there is no Mac, JDK or Gradle on this laptop. CI's macOS job compiles the iPhone app and runs SottoCore's tests; no CI job builds Android yet.

## Running desktop

Built with `npm run build`, then `npx playwright test tests/e2e/host-opencode.spec.ts` on Windows. An Owl desktop (`SOTTO_OWL_FEATURES=opencode=1`) adds forge over the scripted ssh, which runs the real launch script and a real headless host on an Owl version, whose OpenCode is the fixture server. It is the real renderer, preload, IPC, host connection and host. The model sources are the fixture's, and its sign-in pages are `sign-in.fixture.invalid` addresses that main writes down instead of opening.

- forge's OpenCode tile: Connected, what it is signed in to and its version, and Disconnect. The fixture's client is Node, so the tile also shows a published 2.0.32 that Sotto will not install itself.
