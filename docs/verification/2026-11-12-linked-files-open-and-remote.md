# A file link opens the file, and a paired host's file shows in Files with Download

November 12, 2026. Zach asked for a file a reply names to be a link that opens the file or its place: on this computer in its own app, and on a paired host in Tools > Files with an optional download. ADR-0120, November 12 amendment. Owl only (`reveal-linked-files`). His picks from `docs/prototypes/linked-files-open-and-remote-prototype.html`: a press opens it, a program is never run, Download is an icon, it saves to Downloads, and a file outside the thread's folder is shown alone.

## Checked

- **On forge, the built app against a real host over its socket.** `tests/e2e/linked-files-paired-host.spec.ts` pairs the app with a headless host on the Owl track, in dark and in light. A press on a link to `out/q3-report.pdf` opens Tools > Files with `out` open and the file chosen (`host-file-in-tree-dark-1280.png`). Download saves it, and the saved file's bytes equal the host's (`host-file-saved-dark-1280.png`, `host-file-saved-light-1280.png`). Open and Show in file manager act on the saved file. A second download is saved as `q3-report (1).pdf` with no `.part` file left. A link to a file outside the thread's folder shows it alone with its whole path and its text (`host-file-alone-dark-1280.png`), and it downloads too. A link to a folder opens it in the tree, and a link to a file that is gone says so beside the reply. The link's menu, opened with Shift+F10, offers Show in Files, Download and Copy path (`host-link-menu-dark-1280.png`), and Download from it shows the file and saves it. At 820x560 and 1600x1000 the file's head and the download line stay inside the panel (`host-file-saved-dark-820.png`, `host-file-saved-dark-1600.png`).
- **On forge, the built app on its own computer.** The same spec's last test presses a link to a PDF and to its folder, and main is asked to open each by the path it really is. A press on `build-report.bat` shows it in its folder, opens nothing, and the reply says "build-report.bat is a program or script, so it was shown in its folder. Nothing was run." (`local-program-shown-dark-1280.png`). The menu offers Open for the PDF (`local-link-menu-dark-1280.png`) and none for the program. A journey opens nothing on its machine: main records what it would have opened and shown, and the spec reads that record.
- **On the laptop, main's own code against real Windows files.** This branch's `FilesService` and `FileDownloads`, bundled with esbuild and run under the laptop's Node 24 with opening and showing recorded rather than done. Opened: a PDF by a relative path with a space, the same with backslashes and a line, a CSV outside the folder written `C:\...` and `/C:/...`, a folder, `win.ini`, and `hosts`, which has no ending. Shown and not opened: `notepad.exe`, a `.bat`, a `.ps1`, a `.js`, a Start Menu shortcut (`Access.lnk`), and `notepad.exe` copied to `invoice.pdf`, which only its first bytes give away. Refused: a network share, a drive-relative path, a relative path out of the folder, and a missing file. As a host, a Windows path inside the thread's folder was placed as `out/q3 report.pdf`, with forward slashes as Files lists it. A two-part download wrote the same bytes, a second took `q3 report (1).pdf`, and Open on the downloaded `invoice.pdf` showed it without opening it.
- **Over a real socket in the suite.** `tests/integration/socketLinkedFiles.test.ts` reads a place, a preview and a file larger than one part from a headless host, saves it through `FileDownloads`, and checks that a host whose Owl answer is off offers none of it.

## Not checked here

- The file's own app starting on Windows and on a Mac. Main calls Electron's `shell.openPath` there, which a journey records instead of doing. Pressing a PDF link on an installed Owl and seeing it open is a hand step.
- The laptop paired with forge, both on this build. It needs the next Owl on both machines, since the host offers the feature only where its own Owl answer is on.
- Windows and macOS runs of the journey. CI loads the spec (`npm run e2e:list`) and does not run it; it ran on forge, where Linux desktop journeys are checked (ADR-0062). `tests/e2e/markdown-side-panel.spec.ts` ran with it and passes; its Watcher's room test looked for "Show in the file manager" where Linux's button reads "Show in file manager", and now looks for the words the button has.
