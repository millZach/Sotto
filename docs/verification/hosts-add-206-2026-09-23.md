# Adding a host the way T3 Code does (#206)

September 23, 2026. Variant A of the #206 prototype in the running app, built from branch `feat/add-host-like-t3` and driven by `tests/e2e/hosts.spec.ts` (1 passed). The profile holds one saved host, Forge (`builder@forge`), switched off so the run connects nowhere, and a stand-in SSH folder inside the profile: an end-to-end run reads its suggestions from there and never from the machine's `~/.ssh`. Reduced motion is on in that profile.

## What was proved

1. **The Hosts page.** The saved host is a row reading "SSH builder@forge · Switched off", with an Off switch named "Keep Forge connected, now and when Sotto starts" and a More menu. Save host, Connect, Disconnect, Use this host and Use this computer are gone. Neither the page nor the settings column scrolls sideways at 1600x1000, 1280x800 or 820x560, in dark or light.
2. **Add host.** The dialog opens with focus in "SSH host or alias" and its list open. It offers `pihole` from the SSH configuration and `buildbox.example.net` (port 2200) from known hosts. It leaves out `forge`, which is already saved, the `Host *` pattern and the hashed known-hosts line. The dialog stays inside the window at all three sizes in both themes. The first Escape closes the list and leaves the dialog open.
3. **A host nothing answers on.** Adding `127.0.0.1` on port 1 ran a real connect through Windows' `ssh.exe`. The dialog showed the failure with "Nothing was saved." after what happened, and the saved-hosts file still held only Forge. Escape closed the dialog, and no row appeared for the failed host. In this harness `ssh.exe` exits 255 without output (see `forge-real-host-2026-09-23.md`), so the sentence was the one for SSH failing to connect at all; the path is the same for an unreachable host.
4. **The row menu from the keyboard.** Enter on More opened the menu and ArrowDown moved to Edit connection. Enter opened "Edit connection to Forge" with the saved target split into host `forge` and username `builder`. Escape closed it and gave focus back to the More button.

The states the running app cannot reach without a second host are covered by unit tests instead. They are the connecting notice and in-dialog SSH questions, "Connected", "Reconnecting…" and "Needs attention" rows, Connect again, the project badge, the New thread Host row and the composer's "Runs on" chip: `tests/unit/renderer/hostsSettings.test.tsx` and `tests/unit/renderer/hostVisibility.test.tsx`. Reconnect at launch, the switch, and add-saves-only-on-success run against a real headless host in `tests/integration/desktopHosts.test.ts`.
