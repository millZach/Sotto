## Integration findings and repairs

- **Draft ordering and persistence:** the parent first reproduced draft saves waiting behind a provider reply and separated draft persistence from renderer command latency. Independent review then found an older send waiting in that renderer queue could overwrite a newer saved revision, and that leaving/reopening Threads could lose failed-save/recovery knowledge. Connection-owned draft state and immediate ordered send admission fix these cases. A further fresh-renderer regression required exact persistence evidence from main: pending/failed writes, empty clears, later full-state success and older acknowledgements now remain truthful through renderer reload. Commits `c2668f9` and `a4351f2` include the fixes and real controller/disk regressions.
- **Uncertain delivery:** recovery actions must survive navigation/reload and remain independent of the current draft. Missing IPC evidence cannot mean "Not sent". Both reproductions now pass, and actual Electron navigation/reload followed by Check again yields exactly one user message while retaining the newer draft.
- **Clipboard:** the real app denies browser clipboard permission. Copy code now uses existing `deliverOutput` with `autoPaste:false`, and reports success only on `copied`. Tests use controlled output state and never inspect the user's clipboard.
- **Reading position:** the initial last 80 slice removed a row above a reader on every arrival. The parent measured a 120.29 px movement, then retained the first rendered message while away. The final journey checks message identity and a viewport-offset difference below 3 px, plus explicit jump-to-latest.
- **Light navigation:** project counts now count projects, and provider foreground marks meet 3:1 against sidebar/selected backgrounds.
- **Privacy recovery:** all independent persistence stores attempt history cleanup even when one fails, retaining a maintenance retry obligation. Corrupt workspace recovery creates no unmanaged transcript backup. Preview-only and workspace-only failure regressions verify immediate independent redaction and later retry.
- **Timing:** provider latency excludes preview persistence. The regression injects 500 ms persistence and 7 ms provider execution and reports 7 ms.
