# The machines line and Where new workers start, October 23, 2026

Issue #1032's interface, built to Zach's picks of October 23, 2026 in the placement prototype (round two, variant D "Names", with the narrow-room shortening he asked for). It sits on the placement work of `feat/worker-machine-choice` and the live load of `feat/machine-live-load` (#1311). All of it is part of the Owl feature Work across machines (`cross-machine-work`); Stable shows none of it.

## What changed

- **The machines line.** Under Watcher's header, under the needs-you line when one shows, always there: "This computer 2 working · forge 3 working". Working threads are counted from the window's own thread list (`workingThreadsByMachine`), and "1 starting" is the host's **work placed but not started**. A problem adds words after that machine's count, in the needs-you line's warning ink: "may slow down" above ten, "busy", "short on memory", "load unknown", or "not connected". Names and counts never change colour, and nothing is a pill, chip or meter (ADR-0110). The line reads Watcher's own `list_machines` through a new private read, `sotto:watcher:read-machines`, which main registers and the preload offers only while Work across machines is on: only when Watcher places work (once for each placement the room has not been read for) and when the user opens a machine's numbers, a panel or Settings; never on a timer (Zach, October 23, 2026). Whether a machine is connected comes from the saved hosts, which main keeps current, so the line says so between reads.
- **A machine's panel.** Each name is a text button that opens it: system and processors, CPU busy over the reading's window, memory available of the total, when it was read, why its load is unknown when it is (an older host, a reading over a minute old, or memory a Mac does not report), the working threads there and who started each (Watcher, the user, or the thread that delegated), work placed there that has not started, and **Change where new workers start**, which opens Settings at the group. It opens with focus in it, keeps Tab inside, and Escape or a press outside closes it, Escape returning focus to the name.
- **A narrow room.** Below 600 pixels of pane, the line drops the "starting" counts and keeps only the machines with a problem, then "1 more", which shows every machine and moves focus to the first one it had left out. With nothing wrong anywhere it names no machine and says how many there are and how much works on them, "3 machines, 5 working", as the press that shows every machine (review fix, October 23).
- **Receipt cards.** A start Watcher placed away from where new workers start says so under its card: Sotto's own sentence when it placed the start itself ("Forge, where new workers start, is not connected, so this one started on This computer."), otherwise "Not your default, forge. Watcher says why in its reply.", naming the machine new workers start on from the receipt's new `defaultName` (Zach, October 23, 2026) The room state carries this run's placements as `receiptPlacements`, from the same memory as the receipt's `placement`.
- **Settings, under Watcher: Where new workers start.** Between Watched threads and Worker roles: a card each for Let Watcher choose (once another machine is paired), This computer, and every paired machine by the name the user saved, each with what it is and how busy it is now. The chosen card says "New workers start here". A chosen machine that is not connected says that until it is, new workers start on this computer and Watcher says so. With no machine paired, the group says new workers start here and links to Hosts & phones. Find a setting reaches it.

From the keyboard, Enter on forge's name opens its panel with focus in it, Tab moves between Close and Change where new workers start and stays inside, and Escape closes it and returns focus to the name. studio's panel says it runs an older host. ## Review fixes, October 23

- A machine's panel is no taller than the room under its name, measured again when the room or the window resizes; its heading and Change where new workers start stay put and the rest scrolls inside it. The journey checks at every size that Change where new workers start is in view and the panel ends inside the room.
- A long saved name is cut short with an ellipsis, short enough to leave its count room on the line, and stays whole in the button's name and title; a problem's words may wrap. The journey seeds a 61-character name with "busy, short on memory" at 820x560 and checks it stays inside the line, its name is cut and its words sit clear of its count ([capture](../../artifacts/watcher-machines/machines-long-name-dark-820x560.png)).
- Where new workers start's cards are filled with no outline (ADR-0110); the chosen card wears the selected card surface, and a machine not connected keeps its fill and says so ([light 820x560](../../artifacts/watcher-machines/machines-settings-light-820x560.png)).
- The short line with nothing wrong names no machine and says "3 machines, 5 working" (Zach approved these words on October 23).
- The iPhone's Watcher page shows the line in its short form and each machine's panel as a sheet (`watcher-phone-machines`); its Swift is first compiled and tested by the macOS CI job.

## Found while checking

- A panel opened from the keyboard was refused focus in the built app on the render that placed it, though the same call worked a moment later; the panel now offers focus again once the press has ended. jsdom did not show this.
- The night scene lays its owls out again a moment after the window resizes, so the journey reads the window's bounds once that has happened.
- Once the panel re-measured on resize, the one retry of focus after the press sometimes came too early in the built app; the panel now offers focus on each placing render and the next frames until it has taken it once.
- An inline flex box per machine wrapped its words a word at a time in the built app, though the line had room; each machine is plain inline text again, with only the name an inline flex box whose inner text takes the ellipsis.
