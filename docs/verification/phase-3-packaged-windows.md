# Phase 3 Windows package verification

Verified the complete isolated Windows app directory at local commit `7a166299f2b855b83e1b6079b29a2e21b7f5f6a6` with `node scripts/verify-packaged-resources.mjs release/phase-three-verification-7a16629/win-unpacked`. The JSON evidence is [phase-3-packaged-windows.json](phase-3-packaged-windows.json). This is a packaging integration checkpoint; the later personal-chat, layout and theme UI still require final validation. No installer or release was published, and existing release artifacts were preserved.

The verifier checked matching source/build/ASAR provenance, exact runtime dependency inventory, runtime resources and notices, the real packaged SQLite store (migration 3, full-text search), an actual native PTY command (exit 0; Electron modules ABI 148, NAPI 10), and normal packaged startup. Packaged startup rejected the development E2E flags and resolved the audio worklet from its installed ASAR location.

`node-pty` 1.1.0's Windows source rebuild failed in this checkout's spaced path when gyp could not run `GetCommitHash.bat`. The pinned package ships Windows Node-API prebuilds, which passed the actual packaged terminal probe. Windows packaging therefore keeps `npmRebuild: false`. Both supported macOS package scripts explicitly enable native rebuilds with `--config.npmRebuild=true`; macOS packaging and native behavior must still be verified on the Mac.

A `beforeBuild` hook returning false was tested and removed: in installed electron-builder 26.15.3 it marks node modules as externally handled and prevents normal production dependency collection. `npmRebuild: false` skips only rebuilding and preserves collection. This distinction was confirmed in the installed `app-builder-lib/out/packager.js` and by the failing then passing complete package verifier. The configuration is consistent with the [electron-builder build options](https://www.electron.build/v26/docs/configuration/) and the [native Electron module guidance](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules).

The packaged PTY probe resolves `node-pty` from the installed app with `createRequire`, accessed through `process.getBuiltinModule` because Playwright's Electron evaluation realm has no dynamic-import callback. It cannot accidentally load the checkout's native module. Notice generation now retains node-pty, node-addon-api and the shipped winpty license, alongside the xterm notices; 171 inventoried components passed verification at this checkpoint.
