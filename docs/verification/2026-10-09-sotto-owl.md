# Sotto Owl release track, October 9, 2026

Scope: Windows x64, local packaging only. No installation over Zach's Sotto, publishing, push, release creation or upload. Renderer branding belongs to a later UI change. The accessor is `useReleaseTrack()` in `src/renderer/src/state/useReleaseTrack.ts`; main includes `releaseTrack` in existing update information even on unsupported platforms.

## Update selection

`tests/unit/main/owlUpdates.test.ts` runs the installed electron-updater 6.8.9 `NsisUpdater`, provider factory, GitHub Atom selector, manifest parser and semantic-version availability gate. Only HTTP responses and the app adapter are scripted. Cases cover stable ignoring Owl, Owl skipping newer stable and superseded stable tags, numeric daily build ordering, next-patch Owl updates, same/older builds, no Owl tags, mismatched manifests and the GitHub provider's `latest.yml` fallback within an Owl tag. Invalid metadata cannot become a downloadable offer. Stable retains `allowPrerelease = false`; Owl sets channel `owl`, enables prereleases and resets `allowDowngrade = false` after the upstream channel setter. Automatic download and installation on quit remain off.

Shared helper, main status and renderer accessor tests cover version-derived track reporting. No renderer view, stylesheet or control was changed, so no visual prototype or design baseline was needed.

## Returning to stable

GitHub main and local `origin/main` both resolved to `09ea3f4231dd6ee81ac545f0f15363283eeabe47` during verification. A detached checkout under the repository's `.worktrees/` received its own `npm ci` (no junction or dependency sharing) and was removed afterwards.

`node tools/verify-owl-profile.mjs <stable-checkout>` built separate probes against each checkout's actual modules. The Owl probe created real threads through `WorkspaceHost`, seeded synthetic current/history roles and a schema-valid command-center fixture, then reopened and saved through the branch's `AgentControl.start()` / `privacyChanged()`, workspace fixture, `ThreadRegistry`, `ThreadStore`, `SettingsRepository` and `AgentCredentials`. The stable probe used the clean checkout's same load/save paths over that profile. Providers were test fixtures; no native session, paid turn or real key was used.

Observed output is retained in `artifacts/sotto-owl-release/stable-profile.json` and can be regenerated with the retained tool. All ten thread identities/titles survived, including current and retired Watcher conversations. Four messages (ordinary, current, retired and worker) survived in `threads.sqlite`. The ordinary selected thread, draft, French language, `Control+Alt+O` shortcut and XOR-encrypted synthetic formatting key survived. There were no corrupt backups or ordinary-data resets.

Stable stripped every `kind` and dropped the complete `commandCenter` record on save: identity, active request/participant, uncertain operation/receipt references, reservation and read position. It dropped the Watcher capacity setting (seeded at 6), and also dropped `llmQuality` (seeded high), which main intentionally retired in its own ADR-0069. Reopening on this Owl branch would default the missing record empty, missing kinds to project, capacity to 4 and cleanup quality to low. Watcher conversations can consequently be treated as ordinary threads by stable; this is a material limitation, not a lossless rollback.

Main needs an inert preservation path for the command-center record and setting, safe retention/handling of special thread kinds, and an Owl-to-stable-to-Owl regression before that rollback can preserve Watcher. No main code was changed. The fixture proves these specific records and stores, not every possible production profile, OS credential decryption or native provider recovery. Unrecognized profile files were not deleted by the test; provider launch-profile side files were not part of this fixture.
