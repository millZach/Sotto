# The iPhone app in thirty languages

October 23, 2026, with `origin/main` merged in on October 25 at `033a255a`. Branch `feat/ios-interface-language`, from `origin/main` at `452fa272`. Decision record: [ADR-0123](../adr/0123-sottos-interface-speaks-the-computers-language.md).

The iPhone app follows the iPhone's language, or the one chosen for Sotto in the iPhone's Settings, in the thirty interface languages the ADR names, and English otherwise. It ships in the next TestFlight build with no switch: the iPhone has no Owl track. The translations are machine drafts; no native speaker has reviewed them yet.

## What changed

- Copy Sotto builds as a `String` (feedback, errors, states, accessibility labels, the words around a count) is `String(localized:)`, with `bundle: .module` in SottoCore. Literals in SwiftUI initializers were already keys. Ternaries of literals in `Text(…)` and similar initializers, which Swift makes a `String` and never localizes, were split into one `Text` per branch. Sentences built from pieces were rewritten as whole sentences. Counted strings take one key for exactly one and one that varies by plural, so English reads right in the package tests, where no catalog is built.
- Host text stays as written: titles, names, messages, request text, step titles, commands, paths, branch names and a computer's own refusals. Most of it now goes through `Text(verbatim:)` so the intent is in the code. What the iPhone sends a computer stays English, such as a new thread's title and a photo's file name. Theme names stay as names, like Sotto's own; `ThemePalettes.swift` is generated by `iosPalettes.test.ts` and was not edited.
- Durations ("4m 07s", "1 minute 32 seconds", "6m 10s so far") come from SottoCore's `StepRun.clock`, `duration` and `spokenDuration`, in catalog strings. The two-digit minutes and seconds are padded by the locale's number format, so they come in the same digits as the catalog's `%lld`. English is unchanged, except that a finished step's own time now pads its seconds the way the run's line always has ("1m 07s", was "1m 7s"). Relative times already used `RelativeDateTimeFormatter`.
- A word that means two things in Sotto has a key for each meaning: Open and Closed on an agent's row (`agent-row.open`, `agent-row.closed`) are a folded or unfolded row, and on a pull request its state; Running and Working on the working line (`step-verb.running`, `step-verb.working`) are verbs, and elsewhere a check's or a thread's state. Those keys carry their English as `defaultValue:`, which the checker reads. Code compares raw values, never translated words: a pull request chip shows `stateWord`, and Watched's light reads the thread's status rather than the word Working.
- What main brought in while the branch was open is translated too: sending files from a thread's reply box and opening sent ones in Quick Look (ADR-0131), and photos in Watcher's box. The file sentences the iPhone shares with the desktop (`FileWords`), file sizes in each language's units ("180 KB", "180 Ko") and the locale's digits, and a file's progress as the locale writes a percentage ("40%", "40 %"). A notice about a box's photos is one whole sentence for a thread's reply and one for a message to Watcher, where main built it from pieces. The Spaceballs working words on the folded working line stay English, as on the desktop.
- A folder chosen in New thread is registered under its English name, "C drive" or "Root", as before, since the computer keeps and shows it; the sheet shows the name in the interface language (`FolderListing.shownName`).
- Catalogs: `apps/ios/Sotto/Resources/Localizable.xcstrings` (703 keys), `apps/ios/Sources/SottoCore/Resources/Localizable.xcstrings` (239) and `apps/ios/Sotto/Resources/InfoPlist.xcstrings` (the camera prompt). 51 keys vary by plural, with each language's CLDR categories: six in Arabic, four in Polish, Czech and Ukrainian, three in Romanian, `many` in French, Spanish, Italian and Portuguese, and `other` alone in Chinese and Japanese. The project lists the thirty regions; `es` is Spain's Spanish, `es-MX` Mexico's, and `es-419` repeats `es-MX` so `es-AR`, `es-US` and the rest of Latin America reach it rather than Spain's.
- Arabic and Urdu keep the English layout: the root sets `layoutDirection` to left to right, and paragraph text Sotto writes takes `paragraphDirection()`, which runs it right to left inside its own box. A path, branch name or command inside such a sentence goes through `Interface.isolated`, which wraps it in left-to-right isolates only in a right-to-left interface.
- Type: the root sets `typesettingLanguage` to the interface language, so the glyph fallback from Figtree picks Chinese or Japanese shapes as the language asks. Urdu is set in the iPhone's Noto Nastaliq Urdu. Headings drop Figtree's negative tracking in Arabic, Urdu, the Indic scripts, Chinese and Japanese.
- The Focus journeys launch with `-AppleLanguages (en) -AppleLocale en_US`.

## Checks run here

- `node apps/ios/Scripts/check-strings.mjs`: every one of the 942 keys the Swift sources localize is in its catalog, none is stale, and all 30 catalog languages besides English have every key with English's placeholders and their plural forms.
- `tests/unit/scripts/iosStringCatalogs.test.mjs`: 11 tests passed, run with the main checkout's Vitest. ESLint passed on the checker and the test.
- `--interpolations` was read by hand: every `%lld` is an `Int` and every `%@` a `String` in the code, after the checker learned to read a name's own declaration.
- `--prose` lists what still reads like copy but isn't localized: UI-test fixtures standing in for host data, values sent to a computer, and product names.

There is no Swift compiler on this Windows machine. Nothing here has been compiled, run in the simulator or seen on a device.

## Needs a Mac, the simulator or a device

- **Compile.** `sh apps/ios/Scripts/verify.sh` in the Native iOS client (macOS) job: the package tests, including the AppModel and Watcher tests that assert English, and the simulator build with the three catalogs compiled.
- **The catalogs as Xcode reads them.** Open the project on a Mac and confirm Xcode's catalog editor shows every language as translated and changes nothing on a build.
- **A language at a time.** Run the app with the iPhone set to Spanish (Mexico), Spanish (Spain), Spanish (Latin America), German, Arabic, Urdu, Japanese, Simplified Chinese and Hindi at least, and set Sotto's own language in the iPhone's Settings. Check Threads, a thread with steps, a question sheet, New thread, Computers, Settings and Watcher, a reply with files and Watcher's box with photos, at the small and large phone sizes and the largest text size, for clipping and truncation: German and Finnish run long, and Urdu's Nastaliq is much taller than Figtree.
- **Right to left.** In Arabic and Urdu, confirm the tab bar, the navigation bar and its Back button, sheets and the swipe-back gesture keep the English layout. They are UIKit's, and the SwiftUI environment may not reach them; if they mirror, `UIView.appearance().semanticContentAttribute = .forceLeftToRight` at launch is the next step. Confirm paragraphs start from the right of their box, short labels keep their place, and paths and branch names inside a sentence read left to right. System alerts and confirmation dialogs are drawn by iOS in the iPhone's own direction.
- **Type.** Confirm the font names `NotoNastaliqUrdu` and `NotoNastaliqUrdu-Bold` resolve on iOS 17 and later (an unknown name falls back to the system font without an error), and that Japanese text shows Japanese glyph shapes on an iPhone whose own language is Chinese.
- **Plurals.** Read a counted string at 0, 1, 2, 5, 11 and 21 in Arabic, Polish and Ukrainian.
- **Review.** A native speaker for each language. The drafters flagged the words they were least sure of, kept in the pull request.
