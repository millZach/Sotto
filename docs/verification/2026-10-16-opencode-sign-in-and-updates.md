# OpenCode sign-in and updates: what was checked

October 16, 2026. Issue #1104, [ADR-0087](../adr/0087-opencode-is-a-thread-provider.md) (amended the same day) and [ADR-0042](../adr/0042-provider-client-updates.md). Variant A of the [sign-in prototype](https://github.com/millZach/Sotto/blob/prototype/opencode-sign-in/docs/prototypes/opencode-sign-in-prototype.html), Zach's pick.

## OpenCode 2.0.31 itself, on scratch data

A scratch `opencode serve` 2.0.31, in a scratch folder with its own XDG folders, a fake model source defined through `OPENCODE_CONFIG_CONTENT` that answers every key with 401, and made-up keys only. Zach's own OpenCode, its folders and its desktop app were not touched, and no process was left running.

- `POST /api/integration/fakesrc/connect/key` with a made-up key answered 204, and the fake model source received no request at all, then or when the model list was read. An empty key also answered 204. So OpenCode keeps a key without trying it: a wrong key shows only when a thread first uses one of that source's models.
- `GET /api/integration` lists each source's sign-ins as `connections` (credential ID, label and method, no secret); `GET /api/credential` answers with the key itself. Sotto reads the first and never calls the second.
- `DELETE /api/credential/{id}` signed out, and both lists were empty again.
- Browser sign-ins: xAI's SuperGrok device sign-in started as `mode: auto` with the code in its instructions ("enter code: XXXX-XXXX") and its address, expiring after 30 minutes; GitLab's started as `auto` with a `https://gitlab.com/oauth/authorize` page, expiring after 10 minutes; both were cancelled with `DELETE`, after which their status was 404. A GitHub Copilot attempt without its form's `deploymentType` answered 400 "Missing required form field"; with it, and OpenAI's ChatGPT sign-in, answered 500 without a body on this machine.
- The methods' forms: GitHub Copilot asks GitHub.com or Enterprise and, for Enterprise, an address; GitLab its instance address with a default; OpenCode Console a hidden server address; Azure, Cloudflare and Snowflake keys a resource or account; Bedrock and Vertex use sign-ins already on the computer.

## The tests

Each test below failed before the code that makes it pass (logs kept with the run's notes): the client update tests against the previous `providerClients.ts` (8 of 9 red), the OpenCode tile tests against the previous `ProvidersSettings.tsx` (3 of 4 red), the adapter's client update contract case and the OpenCode 1 refusal against the previous `opencode.ts` (both red). The privacy tests were shown red by breaking the code on purpose: logging the key turned the key and bridge tests red, returning the key in an answer turned the bridge test red, and drawing the key field as text turned the dialog test red.

- `tests/unit/main/opencodeClientUpdates.test.ts`: npm's copy is checked against `@opencode/cli` and updated by npm; the install script's copy in `~/.opencode/bin` runs `opencode upgrade` on Sotto's own OpenCode folders with no other provider's key; Homebrew (`opencode`, the tap's `opencode-v2`), scoop (an app folder or a shim) and pacman copies are named and never run; OpenCode 1 and 2.0.30 are refused in words.
- `tests/unit/main/opencodeSources.test.ts`: legacy methods and environment variables left out, Sotto's names for each method, forms drawn (choices, a field shown for one answer, hidden values sent as they are) or the method left out, sign-ins read without a secret, device codes read from the instructions, and only `https:` pages opened.
- `tests/integration/opencodeSignIn.test.ts`, over the scripted server: the list with no credential read; a key handed over once and nowhere in what Sotto keeps, shows or logs, with the model list read again and Sign out; a refused and an empty key; a device-code sign-in, a pasted-code sign-in, a form answered first, an expired page, a cancel, an `http:` page never opened; nothing while OpenCode is disconnected, and the server stopping when idle; the bridge carrying a key in and never a key or a credential ID out; a signed-in source's refused turn naming it.
- `tests/integration/opencodeAdapter.test.ts`: the adapter contract's client update case now runs for OpenCode (a working turn finishes across the update, idle threads move to the new client), and OpenCode 1 connects as too old.
- `tests/unit/renderer/opencodeModelSources.test.tsx` and `opencodeProviderSettings.test.tsx`: the block, the dialog's search, Common first then A to Z, signed-in sources marked, arrows from the search into the list, Escape and focus, the key field, each waiting state, each error, the form, Sign out, and the tile's versions and package manager commands.

## Where this differs from the prototype

- Before a browser sign-in starts, the dialog says it opens "the Anthropic sign-in page" rather than naming the site and whether a code will be shown: OpenCode says both only once the sign-in starts.
- A device code's page address is the one OpenCode gives, shown without its query, and the expiry is OpenCode's.
- The tile has no account line under Local connection: Model sources says the same thing.
- After a key sign-in the notice adds that OpenCode tries the key when a thread first uses it, because it does not try it before.
- Sign-ins reach OpenCode through Sotto's own short-lived server, and each thread moves to the new sign-ins as it next goes idle.
