# Sotto launch video: storyboard

Approved on 2026-09-27, with Codex's Computer Use dropped and beat 7 kept to worktrees (see Decisions). Updated after capture: where this differs from the approved plan, the change and its reason are under **What changed in capture**.

## The film in one line

Someone speaks a sentence and it becomes a Claude Code thread working on a small web app. The camera pulls back to one window holding four agents, walks through what sits beside each thread, commits and merges from one press, and ends on the README's line: **"Your coding agents in one desktop window, with dictation built in."**

## Format

- 1080x1920, 9:16, H.264, 60 fps, 37.2 s.
- The edit is cut to a placeholder bed at **100 BPM** (one beat is 0.6 s, one bar is 2.4 s). Every cut lands on a beat or a half-beat, except the theme stills, which are cut in triplets (0.2 s). `cue-sheet.md` lists every cut and caption against that grid.
- Music: `audio/PLACEHOLDER-music.mp3`, silence. No voiceover.
- Captions: Figtree 600, 68 px, near-white on Ink or on a 72% Ink scrim over busy UI, one at a time. Each stays up for at least 1.2 s or 0.35 s per word. Captions sit at y = 1320. The safe area is 140 px clear at the top, 380 px at the bottom and 120 px on the right.
- Key caps: rounded rectangles in Figtree 600, 44 px, Ink fill with a 2 px border in the Sotto teal. Each appears on the frame the key is pressed in the footage and stays up 0.35 to 0.6 s, less when the next press follows sooner.
- Look: the Sotto theme in Dark (Ink), Figtree, reduced motion off, device scale factor 2.

## The demo project

**`pantry`** is a small Vite and TypeScript web app for keeping track of what's in the kitchen: a list page, a Settings page, a store module, a date helper, a CSV import, a few tests and a README. It is a Git repository with a local bare remote named `origin`, which the fake `gh` reports as `github.com/pantry-demo/pantry`. It is generated by `capture/demo/project.mjs`, and every take starts from the same saved seed (`capture/lib/snapshot.mjs`).

Threads in the sidebar, all in `pantry`:

| Provider | Thread title | What it's doing |
|---|---|---|
| Claude Code | Dark mode toggle in settings | The hook's thread, on its own worktree. Edits `settings.ts`, `theme.css`, `SettingsPage.ts` and `main.ts`. It is called New thread until its first exchange names it. |
| Codex | Fix expiry dates in the import | Widens the date patterns, then adds an `expiresSoon` check, asks how to mark those items, runs tests. |
| Grok Build | Tests for the pantry store | Writes store tests, then a test for a CSV row with no expiry date. |
| Devin | Tidy the README | Rewrites the setup section. |

The Windows user and home path never appear: the demo project lives at `C:\demo\pantry`, Sotto runs on a throwaway user-data folder at `C:\demo\profile`, and `USERPROFILE`, `APPDATA` and `LOCALAPPDATA` point under `C:\demo\home`. Thread worktrees therefore show as `C:\demo\profile\thread-worktrees\…`.

## Capture

`npm run capture` in `marketing/launch-video/` records every take, after `npm run build` at the root; `npm run capture -- <step>` runs one (`prepare`, `hook`, `split`, `requests`, `tools`, `git`, `worktrees`, `anywhere`, `themes`, `sync`). `npm run render` makes the film.

There is one rig (`capture/deskMain.cjs`): the built app in its normal mode, launched by Playwright's Electron launcher on the throwaway profile with `--force-device-scale-factor=2`, so the global shortcut, the widget, the recording and paste are the real ones. The providers are the repository's fake CLIs (`tests/integration/fixtures/`), reached through small stand-in executables at the paths each adapter looks for its client first, with a `PATH` that reaches no real client. The provider adapters are unchanged. Replies, requests and side-call answers are written to each fake's control file on cue (`capture/lib/rig.mjs`); the pointer and keyboard are real input (`capture/shim/Input.cs`).

The screen is recorded with `ffmpeg`'s `ddagrab` at 60 fps. Each take starts with the pointer jumping to a dark corner at a logged moment; `capture/sync.mjs` finds that frame and puts every logged event on the footage's clock (`src/takes.json`). The cut in `src/edit.ts` is written against those events, so a retake keeps its place.

Before each take the rig restores the seed, so every take starts from the same state, and checks that nothing else holds `Ctrl+Shift+Space`.

## Honesty notes

- Every frame is the built app running. The only additions are captions, key caps, crops, pushes and pans, cuts, and the end card.
- The agents' words, edits and requests are scripted through the repository's fake providers, as the brief allows. Sotto's handling of them is the real code: the UI, permissions, the side calls that write the thread title, branch, commit message and pull request, Git, worktrees, the browser tools and the terminal. The builds, tests and Git operations really run on the demo project.
- **Transcription is simulated.** The hotkey, the widget, the recording and the paste are real, but the call to OpenRouter's transcription endpoint is answered inside the capture process with the line that was spoken, after 650 ms, and no request leaves the machine. The stand-in key is never shown. See Decisions.
- The model names are the fakes' stand-ins: **Opus 5.5**, **Sonnet 5**, **GPT-6 Astra**, **Grok 4.7** and **SWE-1.5**. The pixel creature's status lines ("Raising the air shield", "Combing the desert") are Sotto's own.
- The voice coordinator and Memory stay off (`voiceCoordinatorEnabled` and `memoryEnabled` false in the profile), and neither appears.
- Captions were checked against the README and guide:
  - "Your coding agents. One window." echoes the README's first line. I changed the brief's "Every coding agent" because Sotto runs four agents, not every one.
  - "You answer every request." is the README's own heading.
  - "Dictation anywhere." is also the README's own heading. I used it instead of "Dictation works in any app", because the guide says automatic paste is blocked in elevated apps and password fields. The text is still copied there, but not pasted.
  - "Leave the message. The agent writes it." follows the README's "Leave the message empty and the agent writes it."
  - "Remove the folder when you’re done." is the README's own words on worktrees. The film shows the control under the pointer; it is not pressed.

## What changed in capture

- **Transcript.** "Add a dark mode toggle to the settings page." instead of "…to settings and open a pull request.": the pull request is opened by the Git action in beat 6, not by the agent, so the spoken line shouldn't promise it.
- **Browser.** The agent's browser work is shown in Tools rather than the floating player. In the player, the browser tools' clicks miss: `DOM.getNodeForLocation` reports no node at the page coordinates while the page is shown there. Moved into Tools, the same calls work. This is a Sotto bug to file, not a capture problem.
- **Hook framing.** The widget sits on the window's edge, not above the composer, so the hook cuts between the two.
- **Git captions.** Swapped, so each sits over the step it names.
- **Worktrees.** The Claude Code thread is on its own worktree from the start, so beats 5 and 6 run in its worktree.
- **Rigs.** One rig instead of two. The app's development test mode wasn't needed once the fakes ran behind stand-in executables.

## Decisions

Answered on 2026-09-27:

1. **Four providers in one sidebar.** Try the `PATH` shims first. They worked; no app change was needed for this.
2. **Remote hosts.** Dropped. They are a development feature, and the fake SSH host can't be reached from the built app. Beat 7 is worktrees only.
3. **Codex's Computer Use.** Dropped. It can't be faked honestly, and a live capture would run on a real Codex account.
4. **OpenRouter key.** None was available. The user chose to simulate transcription rather than capture it live.
5. **The "claude" label.** The Claude Code adapter named its models' provider `claude`, so the model picker said so. Fixed on its own branch (`fix/claude-provider-label`, PR #415) and captured on a build that includes it; this branch is stacked on it.
