Watcher's header beside the macOS traffic lights, in a narrow pane

Pull request #1214. On macOS the header starts 88 pixels in, past the traffic lights, and at a 400-pixel pane one row is about 46 pixels short. Pick A or B. These are captures of the real built app (Sotto Owl, on Windows with the room's macOS class on and the traffic lights drawn where macOS puts them), in a 1280x800 window with Visual gate flake open beside Watcher and Stop all showing.

Worth knowing before you pick

  • A keeps everything, including Watcher's name, and moves the tabs and actions to a second row from the pane's edge. Watcher's header is then 90 pixels tall while the thread beside it keeps 44, so the two panes' first lines no longer line up.
  • B keeps one 44-pixel row, but it takes more than the Owl tile. Below 520 pixels Watcher's name goes first (screen readers still hear it). Below 470 the tile goes, so nothing in the room's corner says it is Watcher's except the lit owl in the floating switch. Below 430, All threads loses its chevron and the gap before the tabs tightens.
  • B is tight at 400 pixels: about 11 pixels to spare between the tabs and Stop all. Two-digit counts (10 or more threads, 10 or more watched) take about 16, so B would also have to drop All threads' count there, or more. A has more than 100 pixels to spare on each row.
  • At 520 to 664 pixels both options are the same: one row, All threads and Stop all keep their icons and counts, and the tabs tighten. The 600 captures show it.
