Restart at reset — mock-up

Prototype, throwaway. When a provider's usage limit stops threads, Sotto restarts every thread that was working once the limit resets, Watcher first if its own provider was cut off. The same restart replaces the note sent after Sotto itself restarts. Babysitting wake-ups go; Watcher still gets its pull request news. "Restart at reset" is a working name: "Continue" already means a continued thread on another provider (ADR-0089). Flip the three placements of the "restart scheduled" note with the bar at the bottom, or the ← → keys.

1. A limit stops four threads

Claude Code's limit is hit at 11:42 AM. Four Claude Code threads were working (two watched, two not). Sotto read the reset time, 3:00 PM, and schedules the restart. The variants disagree on where you learn that.

A — In each stopped thread: one quiet line under the stop, and the sidebar row says when.

B — Once, for the whole provider: a band at the top of the sidebar lists the threads; each thread pane only shows the stop.

C — Over the composer: a strip where you type, saying a restart is coming and that sending now goes first.

B + C — your pick: the band at the top of the sidebar, the strip over the composer, and rows saying "Restarts at 3:00 PM".

2. At 3:00 PM

Sotto checks the limit really reset, then sends each thread one note, the same words on every provider, tagged "Restarted". A thread already carrying on gets nothing. The note never answers a request or approves anything.

3. What goes

No more "Wake-up from Sotto" in a thread's queue, no Babysit pull request button, no hourglass row. Watcher still hears when checks pass or fail, a review comes, a branch conflicts or a pull request merges: Sotto reads GitHub for the pull requests of watched threads instead of babysat ones.
